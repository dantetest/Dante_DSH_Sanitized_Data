## 一、产品边界

### 做什么

| 场景 | 输入 | 产物 |
|---|---|---|
| 律师把卷宗喂给 Kimi | PDF / 扫描件 / 合同 | 换名版，人名案号全假，逻辑完整 |
| 医生让豆包整理病史 | 病历 PDF / 照片 | 涂黑版，患者信息不可还原 |
| 财务让 WorkBuddy 看报表 | XLSX / 对账单 | 账号金额替换，可做分析 |
| 测绘把正射影像给外部 | TIF / OSGB | 去地理坐标、降精度、去元数据 |

### 不做什么

- **不做匿名化承诺**。国标语境下"去标识化"仍属个人信息，产品只说"已隐去"，不说"已合规"。
- **不做云端**。没有账号、没有上传、没有遥测。默认无网络权限。
- **不做解密**。涉密数据的降密由持密单位决定，本产品只做技术处理。
- **不做通用 DLP**。只管"文件进 AI 之前"这一段。

## 二、总体架构

```
┌───────────────────────────────────────────────────────────────┐
│  ① 界面进程  Tauri WebView                                    │
│     投放台 · 对照台 · 补漏层 · 交付台                          │
│     只拿缩略图/瓦片，手上不持有原文件                          │
└───────────────────────────┬───────────────────────────────────┘
                            │ 本地命名管道 + 一次性令牌
┌───────────────────────────▼───────────────────────────────────┐
│  ② 引擎进程  Python（无出站网络权限）                          │
│                                                               │
│   任务编排  Job Orchestrator   队列 / 重试 / 断点续跑          │
│   ┌─────────────────────────────────────────────────────────┐ │
│   │ 处理管线  Parse → Detect → Plan → Apply → Verify        │ │
│   └─────────────────────────────────────────────────────────┘ │
│   插件注册表   Parser / Detector / Replacer / Exporter        │
│   规则引擎     YAML 规则包 · 热加载 · 任务级版本锁定           │
│   映射库       SQLCipher · 会话密钥 · TTL · 单次使用           │
│   审计链       HMAC 签名 · 链式哈希 · 可 verify               │
└───────────────────────────┬───────────────────────────────────┘
                            │ 仅文件系统
┌───────────────────────────▼───────────────────────────────────┐
│  ③ 加密工作区   临时文件加密 / 崩溃可恢复 / 退出即擦除          │
└───────────────────────────────────────────────────────────────┘

  ✗ 引擎进程无出站 socket —— 由操作系统强制，不是配置项
```

### 为什么这样切

| 决策 | 理由 |
|---|---|
| 界面/引擎双进程 | 引擎崩溃不带走界面；引擎可独立升级（新增格式只换引擎包） |
| Python 做引擎 | OCR（PaddleOCR）、PDF（PyMuPDF）、GIS（GDAL/rasterio）、三维（trimesh）生态全在这边 |
| 界面只拿瓦片 | 1GB 的 TIF 不能进浏览器内存；界面永远只渲染可视区 |
| 进程级断网 | "数据不出域"如果只是配置项，早晚被用户的网络代理绕过 |

## 三、后端设计（架构师视角）

### 3.1 统一文档模型 UDM

**所有格式先归一化，管线只认 UDM。** 这是"新增格式不改管线"的前提。

```python
@dataclass(frozen=True)
class UDM:
    doc_id: str
    format: str                  # pdf | docx | xlsx | image | geotiff | mesh
    pages: list[Page]
    meta: dict                   # 作者/设备/坐标系等"隐藏字段"，默认全丢弃

@dataclass
class Page:
    index: int
    size: tuple[float, float]    # pt 或 px
    blocks: list[Block]

@dataclass
class Block:
    id: str
    bbox: Rect                   # ← 所有格式统一的寻址基础
    kind: Literal["text", "table", "image", "vector", "raster_tile"]
    text: str | None
    cells: list[Cell] | None

@dataclass
class Entity:
    id: str
    type: str                    # PERSON / ID_CARD / GEO_COORD / ...
    value: str
    spans: list[Span]            # (block_id, start, end) 或 (page, rect)
    level: Literal["L0", "L1", "L2", "L3"]
    confidence: float
    origin: Literal["regex", "dict", "model", "ocr", "manual"]
```

关键点：`Span` 同时能表达**文字区间**和**像素矩形**。于是同一套 `RedactionPlan` 既能涂黑 PDF 里的一段字，也能涂黑正射影像里的一块军事设施，还能标掉三维模型贴图上的一块招牌。**不需要为每种媒体写一套脱敏逻辑。**

### 3.2 五段式管线

| 阶段 | 输入 | 输出 | 失败处理 |
|---|---|---|---|
| **Parse** | 文件 | UDM | 未知格式 → 栅格化兜底，至少能涂黑 |
| **Detect** | UDM + 规则包 | `Entity[]` | 超时 → 标记"未识别区"，转人工 |
| **Plan** | `Entity[]` + 策略 | `RedactionPlan` | 冲突 → 按密级取严 |
| **Apply** | UDM + Plan | UDM' | 原子写，失败整体回滚 |
| **Verify** | UDM' | 残留报告 | **有残留 → 阻断导出** |

**Verify 是整个架构最容易被省掉、也最不能省的一段。** 做法：对**成品**再跑一遍全部检测器 + 元数据扫描 + 文本抽取。如果从导出文件里还能抽出"张伟"，就不许导出。

> 零信任自己的输出。

### 3.3 插件契约（怎么加东西）

#### 加一个新文件格式 = 1 个 Python 文件

```python
# plugins/parsers/heic_parser.py
from engine.sdk import Parser, UDM, ParseCtx, ExportResult

class HeicParser(Parser):
    format_id  = "heic"
    extensions = [".heic", ".heif"]

    def sniff(self, head: bytes) -> float:
        return 1.0 if head[4:8] == b"ftyp" else 0.0

    def parse(self, path: Path, ctx: ParseCtx) -> UDM: ...

    def export(self, udm: UDM, plan: RedactionPlan,
               out: Path, mode: ExportMode) -> ExportResult: ...
```

放进 `plugins/parsers/` 目录即生效（引擎启动时扫描注册表），或在 `隐站.toml` 里显式列一行。**不需要改管线、不需要改界面、不需要发版。**

#### 加一条脱敏规则 = 1 个 YAML 文件

```yaml
id: cn.idcard
version: 3
entity: ID_CARD
level: L3                       # L3 = 绝不允许原文进入上下文
detect:
  - type: regex
    pattern: '(?<!\d)[1-9]\d{5}(19|20)\d{2}(0[1-9]|1[0-2])(0[1-9]|[12]\d|3[01])\d{3}[\dXx](?!\d)'
    validate: cn_id_checksum    # 校验位，把误报压到千分级
  - type: context
    near: ["身份证", "公民身份号码", "证件号"]
replace:
  strategy: partial_mask
  keep: [first6, last4]         # 律师可能想保留籍贯和尾号做核对
scope: [pdf, docx, xlsx, image, scanned]
```

规则包支持导入导出 —— 一个律所可以把"本所案号格式"做成规则包发给同行，这是生态的种子。

#### 加一个检测器 = 1 个类

```python
class Detector(Protocol):
    entity_types: list[str]
    def detect(self, udm: UDM, rule: Rule, ctx: DetectCtx) -> list[Entity]: ...
```

内置 6 类检测器，按需组合：

| 检测器 | 技术 | 主要用途 |
|---|---|---|
| `RegexDetector` | 正则 + 校验位 | 身份证、银行卡、统一社会信用代码 |
| `DictDetector` | AC 自动机 + 词表 | 客户名单、项目代号、医院名 |
| `ModelDetector` | 本地 NER（小模型，CPU 可跑） | 人名、地址、机构 |
| `OcrDetector` | PaddleOCR + PP-Structure | 扫描件、照片、印章 |
| `GeoDetector` | GDAL 元数据解析 | 坐标系、图幅号、控制点 |
| `MeshDetector` | 顶点分析 + 纹理 OCR | 三维模型的地理原点、贴图文字 |

#### 格式 → 管线对照

| 扩展名 | 解析器 | 检测器链 | 导出方式 |
|---|---|---|---|
| `.pdf` 文本层 | PyMuPDF | Regex + Dict + Model | 内容流重写 |
| `.pdf` 扫描件 | PyMuPDF + OCR | Ocr + Regex | 栅格化重写 |
| `.docx` | python-docx | Regex + Model | run 级删除 + 属性清理 |
| `.xlsx` | openpyxl | Regex + 表格结构 | 值清空 + defined names 清理 |
| `.jpg/.png` | Pillow | Ocr + 印章检测 | 实心块 + 重编码 |
| `.tif/.tiff` | GDAL | Geo + Ocr + 人工框选 | 去 geotag + 本地系 + 降采样 |
| `.obj/.ply/.glb/.fbx/.osgb` | trimesh / Open3D | Mesh + 纹理 Ocr | 重定位 + 贴图重写 |
| `.las/.laz` | laspy | 点云统计 | 抽稀 + 加噪 |

### 3.4 双轨导出

这是产品最核心的一个分叉。**同一份文件，两个完全不同的目标。**

| | 可逆版（给 AI 读） | 不可逆版（给人看） |
|---|---|---|
| 替换方式 | 保形假值：张伟 → 陈志远 | 涂黑 / 删除 |
| 映射表 | 加密保存，可还原 | **不生成** |
| 适用 | 喂 WorkBuddy / 豆包 / Kimi | 发给对家、法院、保司、外聘顾问 |
| 残留风险 | 映射表泄露 | 无（但可读性下降） |
| 水印 | 无 | 隐站编号 + 成品哈希 |

界面上就是一个开关，但后端是两条 Exporter 路径，不能共用。

#### 保形替换的规则

不是随便编个名字。要做到"模型看不出被换过"：

- **类型一致**：人名换人名，公司换公司，地址换同城地址
- **格式一致**：身份证 18 位仍是 18 位且校验位合法；电话仍是 11 位
- **关系一致**：同一份文件里"张伟"和"张伟之妻李梅"必须映射成"陈志远"和"陈志远之妻王雅琴"——建**实体图**，不是逐处替换
- **量级一致**：金额 2,860,000.00 → 2,140,000.00（不改变数量级，否则模型算出来的结论全错）
- **语种一致**：中文合同里的外国人名不要换成中文名

### 3.5 "涂黑 ≠ 删除"

> 这是整个行业翻车最多的地方。画个黑框不算脱敏，原件还在。

| 格式 | 常见错误做法 | 数据隐站必须做 |
|---|---|---|
| **PDF** | 画黑色矩形盖住 | 用 redaction 注释并 `apply_redactions()` 重写内容流；或整页栅格化后重编码 |
| **DOCX** | 字体设黑 / 加黑底 | 删除 run；清除修订记录、批注、作者、公司、自定义属性、隐藏文字 |
| **XLSX** | 单元格填黑 | 清空值；删隐藏 sheet、defined names、外部链接、批注；**注意公式缓存值** |
| **图片** | 高斯模糊 / 马赛克 | 实心块覆盖后重编码；剥离 EXIF、XMP、GPS、IPTC、内嵌缩略图 |
| **TIF** | 只改像素 | 剥离 GeoTIFF 标签 + `.aux.xml` + `.tfw` + `.prj`；坐标变换 |
| **三维** | 只删贴图 | 顶点坐标里的工程原点、内嵌照片、建模软件元数据都要清 |

还有一堆"没人想到"的泄漏面：

- PDF 的 `/Metadata`、XMP、附件、嵌入字体子集里残留的原始文本
- DOCX 的 `docProps/app.xml`（作者、公司、修订次数）
- 图片的 ICC profile、缩略图（JPEG 的 APP1 里常存着未涂黑的缩略图）
- 打印残留：Word 的"快速保存"历史

所以 `Verify` 阶段必须做**格式级残留扫描**，而不只是重新跑检测器。

### 3.6 地理空间与三维

这两类数据的脱敏逻辑和文本**完全不同**——不是"找到敏感词涂掉"，而是"把定位能力拿掉"。

#### TIF 正射影像

| 处理项 | 做法 |
|---|---|
| 地理标签 | 剥离 `ModelTiepoint`、`ModelPixelScale`、`GeoKeyDirectory`、`GDAL_METADATA`、`RPC` |
| 坐标系 | 投影坐标（如 CGCS2000 / UTM 51N）→ 本地任意直角系：随机平移 `(dx,dy)` + 旋转 `θ`，参数存入加密映射库 |
| 精度 | 坐标取整到 10m / 100m 栅格 |
| 分辨率 | 按密级降采样（0.1m → 1m） |
| 附属文件 | `.tfw` `.aux.xml` `.prj` `.kml` `.ovr` 全部删除或同步变换 |
| 敏感地物 | 军事设施、政府大院、关键基础设施 —— **自动识别不可靠，必须人工框选** |

> 注意：坐标移了，但河流、道路、山脊的形状还在。这类数据只能"降密"，不能"匿名"。产品文案必须说清楚。

#### 三维模型（OSGB / OBJ / PLY / GLB / LAS）

泄漏点比想象中多：

1. **顶点坐标里嵌着工程原点**——倾斜摄影模型的顶点常是几十万量级的大地坐标，减掉原点重定位到 `(0,0,0)` 是第一步
2. **纹理贴图里的文字**——招牌、门牌、车牌、横幅，OCR 出来局部涂黑再重写贴图
3. **内嵌照片和 GPS**——摄影测量成果常带原始照片的 EXIF
4. **元数据**——建模软件名、项目名、坐标系名、拍摄日期
5. **点云精度**——抽稀 + 加噪，防止轮廓反推

导出时整包重写（PLY/GLB），丢弃未知 chunk 和私有扩展。

### 3.7 "不出域"的三层落实

| 层 | 措施 | 验证方式 |
|---|---|---|
| **网络层** | 引擎进程无出站权限（Windows WFP 按进程规则 / macOS 无 entitlement / Linux netns） | 启动自检：真实发起一次连接，必须失败，才点亮"未联网"徽标 |
| **数据层** | 优先 mmap 不落盘；必须落盘时走加密临时卷；退出/崩溃覆写 + unlink（不进回收站） | 单元测试断言临时目录残留为 0 |
| **行为层** | 任何外发需用户显式动作 + 二次确认；导出文件带编号水印 | 审计链记录每一次导出 |

**边界要诚实**：本地不等于绝对安全。同机恶意软件、内存 dump、剪贴板、屏幕录制都在威胁模型里。产品话术写"数据不离开这台电脑"，不写"绝对安全"。可选开屏幕水印和防截屏（Windows `SetWindowDisplayAffinity`），医院场景默认开。

### 3.8 审计：可举证，但别成为新的泄露源

每条记录：

```json
{
  "seq": 1287,
  "ts": "2026-10-19T11:42:03+08:00",
  "doc_hash": "sha256:9f2c…",
  "format": "pdf",
  "entities": {"PERSON": 12, "ID_CARD": 3, "CASE_NO": 5},
  "rule_pack": "legal-cn@2.4.1",
  "mode": "irreversible",
  "out_hash": "sha256:41ab…",
  "prev_sig": "…",
  "sig": "hmac-sha256:…"
}
```

两个原则：

1. **只记类型和数量，不记原值**。审计日志本身不能变成泄露源。
2. **链式签名**。改任何一条，后续全部校验失败。给客户/审计方一个 `verify` 就够。

### 3.9 性能预算

| 场景 | 目标 |
|---|---|
| 100 页扫描 PDF（OCR） | CPU < 60s / GPU < 15s |
| 1 GB TIF 建金字塔 | < 90s，内存峰值 < 1.5 GB |
| 200 MB DOCX 打开 | < 3s |
| 对照台首屏 | < 800ms（先出低清，再补高清） |
| 框选响应 | < 50ms（本地涂黑，异步落库） |

策略：页级并行、TIF 分块流式（512×512 窗口）、OCR 只跑无文本层的页、界面永远拿瓦片。

## 四、前端设计（设计师视角）

### 4.1 为什么是"打字机 / 密档"

用户是律师、医生、财务——**不是极客**。

科技感的深色渐变 + 发光边框，在他们眼里是"AI 玩具"，会降低信任。而档案纸、打字机、骑缝章、编号、涂黑条，传递的是**权威、留痕、可追责**——这恰好是他们的职业心智。

更妙的是：这个产品最核心的动作就是"涂黑"，视觉隐喻天然自洽。**不需要发明一个视觉语言，只需要把一个已有的文化符号做对。**

三层构成：

- **材质**：米白纸张、牛皮纸档案袋、纸张纤维纹理、装订孔
- **字体**：宋体（公文感）+ 等宽（机器感）+ 朱红印章
- **符号**：编号戳、骑缝章、"机密"红章、回形针、色带

| `--ink` | `#1A1714` | 主文字 |
| `--ink-2` | `#574F44` | 次级文字 |
| `--ink-3` | `#8C8272` | 弱化/占位 |
| `--rule` | `#CFC3A9` | 网格线、分割线 |

### 4.3 四条交互铁律

**1. 不让人做技术选择。**
界面上不出现"正则""置信度阈值""实体类型""OCR 语言"。把"严格程度"做成三档：宽松 / 标准 / 最严。

**2. 用"处"计数，不用百分比。**
"已隐去 37 处"比"脱敏率 98%"有实感。百分比会让外行追问"那 2% 是什么"。

**3. 漏了能补，补了能扩散。**
框选之后不只处理这一块，要问一句"同样的「张伟」还有 3 处，一起处理吗？"——这是体验的分水岭。

**4. 不可逆要说人话。**
不说"该操作不可撤销"，说"这 3 处一旦涂黑，就再也找不回来了"。

### 4.4 五个页面

### 4.5 核心组件

| 组件 | 职责 |
|---|---|
| `<PaperSheet>` | 纸张容器：纸纹、装订孔、页眉编号、边缘阴影 |
| `<Typewriter>` | 逐字机，支持 `speed` / `cursor` / `onDone` |
| `<RedactionBar>` | 涂黑条：宽度锁定原文字宽度、扫入动画、角标、透视 |
| `<PeekLens>` | 按住透视：300ms 延迟 + 松手复原 |
| `<MarqueeSelector>` | 框选层：拖拽、吸附到文字行、坐标换算 |
| `<EntityRail>` | 实体清单：分组、计数、定位 |
| `<StampSeal>` | 印章：缩放 + 旋转 + 墨迹扩散 |
| `<DiffStage>` | 对照舞台：同步滚动、分隔线、缩放 |

### 4.6 动效规范

| 动作 | 时长 | 曲线 | 细节 |
|---|---|---|---|
| 涂黑条覆盖 | 180ms | `cubic-bezier(.2,.8,.2,1)` | `scaleX 0→1`，origin left，末端 4px 过冲 |
| 扫描线 | 1.2s 循环 | `linear` | 1px 朱红线，自上而下，带残影 |
| 打字机吐字 | 18–30ms/字（随机） | `steps(1)` | 每字轻微 opacity 与 0.5px 位移 |
| 印章落下 | 420ms | `cubic-bezier(.34,1.56,.64,1)` | `scale 1.4→1` + `rotate(-8deg)` |
| 对照模式切换 | 240ms | `ease-out` | 交叉淡入，不位移 |
| 定位闪烁 | 900ms ×2 | `ease-in-out` | 朱红底色脉冲 |

**必须尊重 `prefers-reduced-motion`**：所有动画降为 0ms 瞬时切换。

### 4.7 可访问性

- 字号三档（小 / 标准 / 大）——医生和年长律师的刚需
- 全键盘可达：`Tab` 遍历实体，`Enter` 确认，`Alt+拖拽` 框选
- 高对比模式
- 读屏：黑条读作"已隐去：人名"，不读原值
- 色盲友好：不只用红色区分状态，同时用图标和文字

### 4.8 最后一公里：怎么把文件送进豆包 / Kimi / WorkBuddy

**这一段最容易被忽略，但决定产品生死。** 脱敏做得再好，如果比"直接拖进去"多花 15 秒，用户两次之后就会绕过你。

三条路径，按摩擦从低到高：

| 路径 | 做法 | 摩擦 | 适用 |
|---|---|---|---|
| **剪贴板直投** | 处理完自动进剪贴板，弹一句"去豆包按 Ctrl+V" | ★ | 主路径，覆盖 80% 场景 |
| **托盘常驻 + 拖放** | 隐站常驻托盘，文件直接拖到悬浮球上，处理完自动复制 | ★★ | 高频用户 |
| **剪贴板守护** | 复制任何内容时，检测到敏感项，右下角浮出"要先隐去吗？" | ★★★（需授权） | 进阶，默认关 |

**剪贴板方案的关键细节**：

- 复制的是**换名版全文**，不是文件——豆包/Kimi 的网页版支持粘贴长文本
- 复制后 60 秒自动清空剪贴板（可配），避免"忘了还在剪贴板里"
- 剪贴板内容用系统 API 写入，不走任何网络
- 复制前弹一次确认：`将要复制的是「换名版」，含 4 个假人名、2 个假案号`

**为什么不做浏览器插件**：豆包、Kimi、WorkBuddy 都有桌面端和独立窗口，插件只能覆盖网页；而且插件要大权限，专业用户会怕。桌面端的剪贴板 + 拖放已经够了。

## 六、里程碑

| 阶段 | 周期 | 交付 | 验收标准 |
|---|---|---|---|
| **M0 骨架** | 2 周 | PDF/图片 + 换名/涂黑 + 对照台 | 能完整跑通一份合同，残留检测为 0 |
| **M1 补漏** | +2 周 | OCR + 框选 + 同类扩散 + 规则包 | 扫描件识别 F1 ≥ 0.93；框选后 1s 内扩散 |
| **M2 表格** | +2 周 | DOCX/XLSX + 元数据清理 | 导出后 LibreOffice 打开无修订/批注残留 |
| **M3 地理** | +4 周 | TIF + 三维 + 坐标中性化 | 导出 TIF 用 gdalinfo 查不到任何地理参考 |
| **M4 企业** | +4 周 | 规则包市场 + 审计链 + 私有化 | 审计链可 verify；策略可下发 |

**M0 结束就要找 5 个真实律师试用**，拿"任务成功率下降几个点"这个数字——没有这个数字，后面全是自嗨。

## 七、风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| 漏检一次 | 信任崩塌 | 白名单授权 + Verify 阻断 + 框选兜底 |
| 换名后模型变笨 | 用户关掉 | 保形替换 + 实体图 + 任务成功率评测 |
| 用户直接开网页版绕过 | 产品失效 | 桌面端做本地文件右键菜单 / 打印驱动 |
| 大厂内置同类能力 | 被吞 | 聚焦"跨格式 + 地理/三维 + 可举证"，大厂不做这些 |
| 地理数据合规 | 法律风险 | 明确"降密"定位，不承诺"合规"；处理前弹合规声明 |
| 性能不达标 | 弃用 | 流式 + 瓦片 + 分级渲染，先低清后高清 |

> **数据隐站 —— 文件交给 AI 之前，最后一道本地的门。**
