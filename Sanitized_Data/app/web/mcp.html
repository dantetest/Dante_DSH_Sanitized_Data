MCP · MODEL CONTEXT PROTOCOL

让你的 Agent 自动脱敏

MCP 是 Agent 调用外部工具的通用协议。装好这个服务之后， WorkBuddy、Codex、Claude Desktop、Cursor 等支持本地 MCP 的客户端， 在把文件交给模型之前会先调用本机的脱敏工具 —— 模型拿到的永远是处理过的那一份。
2026-10-23 实测：WorkBuddy 5.8.4 与 Codex 已跑通「发现 15 工具 → 真实脱敏 → 导出」。

stdio 本地进程 不经网络 15 个工具 + 资源 WorkBuddy / Codex 已实测 无需账号
先下载安装包 → 直接看配置

它提供什么工具

Agent 能调用 15 个工具（4 个基础 + 11 个复核/Job），全部在本机执行

TOOL 01

sanitize_document

把一个本地文件脱敏，返回可外发副本的路径。支持 PDF / DOCX / XLSX / 图片 / TIF / TXT。

// 参数
{ "path": "D:\\合同.pdf",
  "mode": "ai" | "human",
  "strictness": "standard" }
TOOL 02

redact_text

把一段文本里的敏感信息就地替换，返回脱敏后的文本。适合发日志、报错、聊天内容之前先过一遍。

// 输入
委托人张伟，身份证310104198703124510
// 返回
委托人陈志远，身份证310104********4518
TOOL 03

check_support

检查某个文件格式是否支持、会被哪套规则包处理。调用前先问一句，避免白跑。

TOOL 04

list_rules

列出本机可用的规则包与规则条目（通用 / 法律 / 医疗 / 财务 / 测绘）。

L2：Job 化复核 + 工作台深链

除了四个基础工具，L2 还提供 11 个 sanitize_* 工具：先建 Job（不重复解析）， 再查实体/接受/拒绝/替换/框选补漏，最后导出并查审计。所有操作和 Web 工作台共用同一个 j_* 任务、审计链与 data/out 成品。

JOB

检测 → 复核 → 导出

// 建任务（已就绪返回 stage=ready）
sanitize_file { "path": "D:\\合同.pdf" }
// 看实体/处理待确认
get_sanitize_entities { "job_id": "j_ab12cd34" }
update_sanitize_entity { "job_id": "...", "entity_id": "...",
  "action": "accept" | "reject" | "replace", "value": "..." }
// 导出 + 审计
export_sanitize_job { "job_id": "...", "mode": "ai" }
get_sanitize_audit { "job_id": "..." }
WORKBENCH

同一 Job 打开完整工作台

复杂细修（框选补漏 / 整图涂黑 / 证件档位 / 时间模糊 / 未成年人严格模式）回浏览器：

open_sanitize_workbench { "job_id": "j_ab12cd34" }
// 返回
{ "url": "http://127.0.0.1:8760/console?job=j_ab12cd34",
  "workbench_available": true }

安装版/源码版都可以；Web 服务未启动时会返回 no_workbench 启动引导，不会给出失效深链。MCP 与 Web 共用同一数据目录与审计。

DSH / Agent 工具名：客户端里显示为 mcp__sanitized-data__sanitize_file 等；资源 sanitize://jobs/{id}/... 提供任务快照/实体/审计/页面预览。

谁可以接？先看你用的是哪类客户端

数据隐站的 MCP 是本机 stdio 服务：只能接「能启动本地程序」的桌面 / CLI / IDE Agent。 网页版、手机 App、云端 Agent（豆包、Kimi 网页版等）没有本机进程通道，请走「手动档」。

自动档

本机 Agent（MCP 直连）

WorkBuddy、Codex、Claude Desktop、Claude Code、Cursor、VS Code Copilot、Kimi Code CLI、Qwen Code、TRAE、Cherry Studio、Chatbox、DSH 等。

Agent 在把文件交给模型前自动调用本机脱敏，原文不出本机。

手动档

网页版 / 手机 App / 云端

豆包、Kimi 网页版、ChatGPT 网页、腾讯元宝等：先用「数据隐站」脱敏，再导出换名版上传/发送。

这类产品当前不开放本地进程入口，不是配置问题。

配置（复制即用）

安装版不需要 Python：command 指向 Sanitized_Data_MCP.exe，args 留空。 把 JSON 合并进对应客户端的配置文件后，完全重启客户端。 路径要改成你自己的绝对路径（反斜杠写两个）。

WorkBuddy（腾讯）· 已实测 5.8.4

配置文件：~/.workbuddy-ai/mcp.json（Windows：C:\Users\<你>\.workbuddy-ai\mcp.json） 

{
  "mcpServers": {
    "sanitized-data": {
      "type": "stdio",
      "command": "C:\\Users\\<你>\\AppData\\Local\\Programs\\Sanitized_Data\\Sanitized_Data_MCP.exe",
      "args": [],
      "timeout": 60000
    }
  }
}
① 从哪进（5.8.4 实测路径）：左侧「Experts · Skills · Connectors」→ 顶部「Connectors」→ 右上角「Custom connectors」→「MCP Server Management」。 「+ Add MCP」打开的就是 C:\Users\<你>\.workbuddy-ai\mcp.json（页面会显式显示该路径），粘贴 JSON 后保存。
② 怎么算成功：列表里 sanitized-data 显示绿点 + 15/15 tools enabled + 开关打开；没有绿点就是没启动，先查 exe 路径/权限（首次接入需信任/启用，未信任时 WorkBuddy 会静默不启动）。
③ 路径注意：5.8.4 实际读取 ~/.workbuddy-ai/mcp.json；旧文档里的 ~/.workbuddy/mcp.json 在该版本不生效。
实测（2026-10-23）：15 个工具全部发现，list_rules、sanitize_file（Job + 6 实体）、export_sanitize_job（成品 + 审计）真实跑通。

Codex（OpenAI）· 已实测

配置文件：~/.codex/config.toml（追加；Windows 用 TOML 单引号，反斜杠不用转义） 

[mcp_servers.sanitized-data]
command = 'C:\Users\<你>\AppData\Local\Programs\Sanitized_Data\Sanitized_Data_MCP.exe'
args = []
startup_timeout_sec = 120
tool_timeout_sec = 600
required = true
Codex 默认 startup_timeout_sec=10、tool_timeout_sec=60；数据隐站大文件可能超过 60s，建议如上调到 120 / 600。 Codex 目前把 MCP 当工具集使用：prompts 没有产品入口、图片预览不保证显示；核心脱敏结论以文本 JSON 为准。
非交互调用注意：在 codex exec / 自动化里调用 MCP 工具会被审批策略拦住（报 MCP tool call requires approval），需要显式放行审批或使用允许模式；交互式客户端首次调用会弹审批。

源码运行（开发者）

# 需要 Python 3.10+ 与 pip install -r app/server/requirements.txt
python -X utf8 app\server\mcp_server.py
大文件必须先 job 轮询（2026-10-24 实测）： 单次 sanitize_document 实测 30 页/1113 实体≈37s、40 页/1477≈66s、50 页/1840≈113s； 超过 30 页或 1000 个待脱敏信息，单次调用就会撞客户端超时，请改用 sanitize_file（≤15s 返回 job_id）→ get_sanitize_job 每 2–5 秒轮询 → export_sanitize_job。
阈值建议：≤20–25 页 / ≤700–800 实体可用单次；>30 页或 >1000 实体必须 job 轮询；>150 页或 >5000 实体当前桌面版后处理可能超过 10 分钟（实测 150 页停在 detecting 95%），建议按章节/每 20–30 页拆分，或改用本机工作台。
常见问题：① 配置保存后没反应 → 检查路径、WorkBuddy 的「信任」、并完全重启客户端；② 图片：sanitize_document 会返回一张 PNG 预览（服务端已回），但 WorkBuddy 5.8.4 聊天内不显示、export_sanitize_job 不返回图片 → 请打开 out_path 或本机工作台看；③ 找不到日志 → stdout 只走 JSON-RPC，日志在 stderr，客户端 MCP 日志里可见。
不同客户端的复核能力不一样（2026-10-23 实测）：
• WorkBuddy 5.8.4：MCP prompts 不会变成斜杠命令；resources 能列出但读取在本次环境报 Service error；复核请直接用工具（get_sanitize_entities → update_sanitize_entity → export_sanitize_job）。
• 图片/预览：当前 export_sanitize_job 主要返回文本 + 文件路径；图片请看 out_path 或 open_sanitize_workbench 打开的工作台，不要把「聊天里看到缩略图」当成成功判据。
• human 涂黑不可逆：客户端不会自动弹确认框；服务端会返回 confirmation_required + confirm_token（300s），需要你在对话里明确确认后再让 Agent 带 token 重试。先看实体清单与影响面再确认。
• DSH：MCP 工具链路实测 4–427ms（小工具 4–93ms），`toolCallTimeoutMs=600000`（600 秒）；工具卡/插件代理属 DSH 插件层，与 MCP 链路分开计。
• 工作台深链前提：数据隐站 Web 服务在运行，且 MCP 与 Web 共享同一数据目录（安装版同目录；源码/dev 请把 YINZHAN_DATA_DIR 指向 Web 的 data 目录）；否则返回 workbench_available=false 并给启动引导。

验证是否装好

先确认服务本身能启动

# 安装版：直接运行（会等待 JSON-RPC 输入，Ctrl+C 退出）
"C:\Users\<你>\AppData\Local\Programs\Sanitized_Data\Sanitized_Data_MCP.exe"

# 源码版：
python -X utf8 app/server/mcp_server.py
# 看到启动日志即说明服务正常（日志走 stderr，不污染协议）

在客户端里问一句

重启客户端后，向 Agent 提问：列出 sanitized-data 这个 MCP 提供的所有工具。 期望看到 15 个工具（sanitize_document、redact_text、sanitize_file、export_sanitize_job 等）。

再跑一次真实脱敏

说：用 sanitize_file 把 D:\合同.pdf 脱敏（mode=ai），再 export_sanitize_job，告诉我 job_id 和输出路径。 成功会返回 job_id、输出文件路径、实体数量与审计结果；可再用 open_sanitize_workbench 打开同一 Job 的工作台复核。

按客户端的检查入口排障

WorkBuddy：插件 → MCP 服务器（状态灯 + 信任）；Codex：codex mcp list / codex mcp get sanitized-data； Claude Desktop：Developer → MCP 日志；Cursor：Output → MCP Logs。改了配置后记得完全重启客户端。

安全边界

传输

不出本机

MCP 走 stdio，父子进程管道通信，不开端口、不走网络。

数据

临时副本即用即删

上传副本和预览中间件在任务结束或退出时清除，成品才保留。

审计

可举证

每次脱敏写一条签名审计记录，只记类型和数量，不记原值。
