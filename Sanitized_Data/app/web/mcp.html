MCP · MODEL CONTEXT PROTOCOL

让你的 Agent 自动脱敏

MCP 是 Agent 调用外部工具的通用协议。装好这个服务之后， Claude Desktop、Cursor 等支持 MCP 的客户端在把本地文件交给模型之前， 会先调用本机的脱敏工具 —— 模型拿到的永远是处理过的那一份。

stdio 本地进程 不经网络 15 个工具 + 资源 无需账号
先下载安装包 → 直接看配置

它提供什么工具

Agent 能调用 15 个工具（4 个基础 + 11 个复核/Job），全部在本机执行

TOOL 01

sanitize_document

把一个本地文件脱敏，返回可外发副本的路径。支持 PDF / DOCX / XLSX / 图片 / TIF / TXT。

// 参数
{ "path": "D:\\合同.pdf",
  "mode": "ai" | "human",
  "strictness": "standard" }
TOOL 02

redact_text

把一段文本里的敏感信息就地替换，返回脱敏后的文本。适合发日志、报错、聊天内容之前先过一遍。

// 输入
委托人张伟，身份证310104198703124510
// 返回
委托人陈志远，身份证310104********4518
TOOL 03

check_support

检查某个文件格式是否支持、会被哪套规则包处理。调用前先问一句，避免白跑。

TOOL 04

list_rules

列出本机可用的规则包与规则条目（通用 / 法律 / 医疗 / 财务 / 测绘）。

L2：Job 化复核 + 工作台深链

除了四个基础工具，L2 还提供 11 个 sanitize_* 工具：先建 Job（不重复解析）， 再查实体/接受/拒绝/替换/框选补漏，最后导出并查审计。所有操作和 Web 工作台共用同一个 j_* 任务、审计链与 data/out 成品。

JOB

检测 → 复核 → 导出

// 建任务（已就绪返回 stage=ready）
sanitize_file { "path": "D:\\合同.pdf" }
// 看实体/处理待确认
get_sanitize_entities { "job_id": "j_ab12cd34" }
update_sanitize_entity { "job_id": "...", "entity_id": "...",
  "action": "accept" | "reject" | "replace", "value": "..." }
// 导出 + 审计
export_sanitize_job { "job_id": "...", "mode": "ai" }
get_sanitize_audit { "job_id": "..." }
WORKBENCH

同一 Job 打开完整工作台

复杂细修（框选补漏 / 整图涂黑 / 证件档位 / 时间模糊 / 未成年人严格模式）回浏览器：

open_sanitize_workbench { "job_id": "j_ab12cd34" }
// 返回
{ "url": "http://127.0.0.1:8760/console?job=j_ab12cd34",
  "workbench_available": true }

安装版/源码版都可以；Web 服务未启动时会返回 no_workbench 启动引导，不会给出失效深链。MCP 与 Web 共用同一数据目录与审计。

DSH / Agent 工具名：客户端里显示为 mcp__sanitized-data__sanitize_file 等；资源 sanitize://jobs/{id}/... 提供任务快照/实体/审计/页面预览。

配置（复制即用）

把下面的 JSON 合并进客户端的配置文件，重启客户端即可。 路径要改成你自己的绝对路径。

Claude Desktop

Windows：%APPDATA%\Claude\claude_desktop_config.json · macOS：~/Library/Application Support/Claude/claude_desktop_config.json 

{
  "mcpServers": {
    "sanitized-data": {
      "command": "python",
      "args": [
        "D:\\Sanitized_Data\\app\\server\\mcp_server.py"
      ]
    }
  }
}

Cursor

项目内 .cursor/mcp.json 或全局 ~/.cursor/mcp.json 

{
  "mcpServers": {
    "sanitized-data": {
      "command": "python",
      "args": ["D:\\Sanitized_Data\\app\\server\\mcp_server.py"],
      "env": {}
    }
  }
}

其他 MCP 客户端（通用 stdio）

# 启动命令（stdio，JSON-RPC 2.0）
python D:\Sanitized_Data\app\server\mcp_server.py

# Linux / macOS
python3 /opt/sanitized-data/app/server/mcp_server.py
路径怎么写：Windows 的 JSON 里反斜杠要写两个 \\； 如果 python 不在 PATH 里，把 command 换成 Python 的绝对路径， 例如 C:\\Python312\\python.exe。 安装版可直接用 C:\\Users\\<你>\\AppData\\Local\\Programs\\Sanitized_Data\\Sanitized_Data_MCP.exe （args 留空），无需 Python。

验证是否装好

先在终端里试跑一次

python app/server/mcp_server.py
# 看到这行就说明服务本身没问题：
[sanitized-data] MCP 服务已启动（stdio），工具：sanitize_document, redact_text, ...

在客户端里提问

重启客户端后，让它调用工具：帮我把 D:\合同.pdf 脱敏后总结要点。 Agent 会先调 sanitize_document 拿到脱敏副本，再基于副本回答。

确认客户端认到了服务

在客户端的 MCP / 工具列表里应该能看到 sanitized-data， 以及它下面的 15 个工具与资源。

安全边界

传输

不出本机

MCP 走 stdio，父子进程管道通信，不开端口、不走网络。

数据

临时副本即用即删

上传副本和预览中间件在任务结束或退出时清除，成品才保留。

审计

可举证

每次脱敏写一条签名审计记录，只记类型和数量，不记原值。
