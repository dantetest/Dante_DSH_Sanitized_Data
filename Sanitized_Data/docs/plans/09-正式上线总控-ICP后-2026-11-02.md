## 0. 一页结论

1. **ICP 下来只解锁「网站能合法上线 + 能去申请支付商户号」**，不等于今天就能自动收款。真正收款要靠：企业主体 + 对公账户 + 支付商户号 + 备案网站。
2. **今天已经具备「合法开卖」的 L1 闭环**：免费版 / 14 天试用 → 对公或平台付款 → `deploy/issue_order.py` 一条命令签发授权 → 客户在「授权」页导入 → 解锁。产品代码不用改，人工发码已实测（2026-11-02，测试密钥）。
3. **你要的「扫码 → 自动给授权码 → 自动解锁」是 L3，代码已实现（2026-11-02）**：
   - ① 商业服务（`commercial/`）：订单 / 支付宝预下单（或电脑网站支付）/ 异步通知验签 / 自动 Ed25519 签发 / 服务端 QR SVG / SQLite 台账；
   - ② 本机购买页（`/purchase`）：展示二维码、轮询订单、付款后自动导入 license 并解锁；
   - ③ 客户端商业服务地址注入：`YINZHAN_COMMERCIAL_URL` 环境变量或 `commercial.json`（安装目录/数据目录；不用重新打包）。
   - 真正上线还缺的是**外部条件**：支付宝商户号/APPID/密钥、公网 HTTPS 域名与回调、真实 0.01 元联调、发布包内置默认地址。
4. **客户端自动解锁已实现，但仍守住「文件处理零外呼」**：购买页（浏览器 JS）只在用户点击时访问商业服务；本机 Python 引擎不发起外呼，文件处理链路不变。
5. 推荐上线节奏：**L1 今天—3 天可人工发码开卖（兜底）→ L3 代码已就绪，商户号下来按 [alipay-setup](../../commercial/docs/alipay-setup.md) 换真密钥 → 真实小额验收 → 灰度。** 自动化不是等 3 周的理由，先人工跑 10–20 单验证价格/转化。
6. **关键路径不在代码，在资质与页面**：商户号审批 1–2 周、微信服务号认证约 1 周、公安联网备案 30 日内、协议三件套与购买页必须先上线（支付审核会看）。L3 当前用支付宝通道，微信 Native 可后加（同一 Provider 接口）。

## 2. 目标闭环与三个「上线」定义

### 2.1 最终用户旅程（L3 已实现形态）

```text
客户下载（官网/下载页，SHA256）
   │
   ▼
安装 → 免费版可用；在「授权」页点「开始 14 天全功能试用」
   │  （不需要机器码、不需要联网）
   ▼
试用中/到期 → 点「扫码升级」→ 本机 /purchase 页（同源，带机器码）
   │
   ▼
本机购买页向商业服务下单 → 显示支付宝二维码（服务端 SVG）→ 手机扫码支付
   │
   ▼
支付宝异步通知 → 商业服务验签/核对金额/幂等 → 标记已付
   │
   ▼
服务端用 Ed25519 私钥签发 license（绑定机器码/有效期/功能位）
   │
   ▼
本机购买页轮询到 paid → 自动 POST /api/license/import → 本地验签 → 显示「已解锁 · 专业版（到期 …）」
   │
   ▼
（兜底）若自动导入失败：页面展示单行授权码，手动粘贴导入；或联系客服人工发码
```

> **口径**：文件处理引擎仍零外呼；只有本机购买页（浏览器 JS，用户主动点击）访问商业服务，不涉及用户文件。若无法访问商业服务，回落到官网购买/人工发码（L1）。

### 2.2 L1 / L2 / L3 的差别

| 级别 | 收款方式 | 授权交付 | 客户端改动 | 何时可上 |
|---|---|---|---|---|
| **L1 人工闭环** | 对公转账 / 平台店铺（微店/有赞/闲鱼）/ 客服收款 | 人工执行 `issue_order.py`，微信/邮件发授权码 | 无（可选内置购买页 URL） | **今天**（前提：官网/页面/客服就位） |
| **L2 扫码自助付** | 微信 Native / 支付宝电脑网站支付 | 支付回调后自动签发，网页/邮件给授权码 | v1.3.5 内置购买 URL（0.5–1 天） | 商户号下来后 1–2 周 |
| **L3 全自动解锁** | 同上 | 支付回调后自动签发；**本机购买页轮询 → 自动导入 → 直接解锁** | 已实现：`app/web/purchase.*` + `commercial/` | **代码已就绪**（真实支付宝待商户密钥联调） |

**推荐**：先 L1 开卖验证价格/转化，同时并行申请商户号、开发 L2；L2 上线后 L1 保留兜底（对公/团队/扫码失败）。

## 3. L1（今天—3 天）：人工发码，先合法开卖

### 3.1 业务方要做（按顺序）

1. **确认产品站域名**：建议 `buy.blctek.com` 或 `www.blctek.com/buy`（同主体、同备案号）；确认该域名/子域已在 ICP 备案中，必要时做「新增网站/接入备案」。
2. **产品站上线**（可由我做页面）：首页、价格、下载、购买说明、FAQ、用户协议/隐私政策/退款政策/EULA、页脚 `ICP 备案号（链接 beian.miit.gov.cn）+ 公安备案号 + 营业执照信息 + 客服`。
3. **提交微信支付商户号申请**：`pay.weixin.qq.com` → 普通商户；材料：营业执照、法人身份证、对公账户、备案域名+网站截图、客服电话；类目「软件开发/其他互联网服务」；PC 场景选「PC 网站」→ Native。
4. **同步申请支付宝**：`b.alipay.com` → 企业账号 → 签约「电脑网站支付」；备案主体需一致（不一致要 ICP 备案授权函）。
5. **做公安联网备案**：网站开通（联网）起 **30 日内**，`https://beian.mps.gov.cn` 提交；通过后 30 日内把公安备案号+图标放页脚。
6. **确认对公收款信息与开票信息**（户名/开户行/账号/税号；普票/专票流程）。
7. **准备客服与交付**：客服微信/邮箱、响应时间、话术（SOP §8）、退款口径；平台过渡店（微店/有赞/闲鱼）可同步开，但**不用个人收款码收经营款**。

> 微信 Native 的硬前提：需要**已认证**的服务号/小程序/移动应用作为 APPID（认证约 300 元/次、一年一审）。没有就先注册企业主体服务号并认证；这是 1–2 周关键路径之一。

## 4. L3（已实现）：扫码自助付 + 自动发码 + 本机自动解锁

> **落地状态（2026-11-02）**：本节设计已实现在 `commercial/` 与 `app/web/purchase.*`。
> - 启动商业服务：`python commercial\scripts\run_dev.py --provider mock`（生产：`--provider alipay` + `.env` 填 APPID/密钥）
> - 本机演示：`powershell -ExecutionPolicy Bypass -File commercial\scripts\demo_up.ps1` → 自动打开 `http://127.0.0.1:8799/purchase` → 点「演示：模拟支付」→ 页面自动导入并显示「已解锁」

> - 部署与支付宝配置：[commercial/README](../../commercial/README.md) · [alipay-setup](../../commercial/docs/alipay-setup.md)

### 4.1 系统架构

```text
公网服务器（2C4G 起，独立于 CKA 内测机）
  nginx 443（备案域名，如 buy.blctek.com）
   ├─ /buy.html      商业站购买页（可选；带 sku + machine_code）
   ├─ /order.html    订单结果页（已付显示授权码 + 下载/邮件，可选）
   ├─ /api/*         建单 / 查单 / 取 license / mock 支付
   ├─ /notify/alipay 支付宝异步通知（验签/金额/幂等 → 自动签发）
   └─ signer         Ed25519 私钥（只在商业服务机/独立进程）
本机（127.0.0.1）：
  /purchase 购买页（浏览器 JS）→ 下单 → 显示二维码 → 轮询 → 自动 POST /api/license/import → 本地验签解锁
```

技术选型：Python 3.12 + FastAPI + SQLite（WAL）+ Jinja/静态页 + nginx + systemd；与现有 Python 栈一致，签发直接复用 `yinzhan.licensing.issue`。规模上来再换 Postgres。

### 4.4 支付通道

> **当前实现**：支付宝 RSA2（`precreate` 扫码 / `page` 电脑网站支付）+ mock；微信 Native 尚未实现（Provider 接口已预留，后加）。金额单位/幂等/验签要求见 [alipay-setup](../../commercial/docs/alipay-setup.md) 与 [CONTRACT](../../commercial/CONTRACT.md)。

**微信支付 Native（PC 扫码，后续）**
- 下单：`POST /v3/pay/transactions/native`，参数 `appid`、`mchid`、`description`、`out_trade_no`、`notify_url`、`amount.total`（**int 分**）、`time_expire`；
- 返回 `code_url` → 购买页用本地 JS 渲染二维码（不依赖第三方 CDN）；
- 回调：验 `Wechatpay-Signature`（平台证书）、解密 `resource`，核对 `out_trade_no`、`amount.total`、`mchid`、`appid`、`trade_state=SUCCESS`；
- 幂等：`transaction_id` 唯一；重复回调直接返回成功；同一订单二次支付 → 退款队列，不重复签发。

**支付宝电脑网站支付**
- 下单：`alipay.trade.page.pay`（收银台页；用户可扫码/登录支付）或按签约产品使用扫码预下单；
- 回调：RSA2 验签，核对 `app_id`/`seller_id`/`out_trade_no`/`total_amount`（元字符串 → `Decimal*100` → int 分）/`trade_status`；
- 幂等：`trade_no` 唯一；`TRADE_SUCCESS` 与 `TRADE_FINISHED` 区分退款语义。

**对公转账**：后台人工「标记已付」→ 二次确认 → 签发；以银行流水为准，大额不凭截图。

> 费率/结算以签约页与合同为准（2026-11-02 检索：微信常见 0.6%、T+1；支付宝常见 0.6%、T+1，未取得官方费率原文）。类目选「软件开发/其他互联网服务」，**不要选「虚拟充值」**。

### 4.5 授权签发与交付

- 复用 `yinzhan.licensing.issue`：`build_payload` + `sign_license`（Ed25519，`key_id=prod-2026`）；
- **signer 独立进程/主机**，私钥权限 600、不随 web 进程；web 只发「已支付+已绑定」的签发请求；
- sku/金额/到期/功能位**由 DB 快照派生**，不接受 HTTP 传参；
- 绑定机器码在**建单时**从购买 URL 带入（`machine_code`），服务端校验格式（Crockford Base32 4×4）；同一订单只签发一次；
- 交付三件套：网页显示**单行 license 文本**（复制即可粘贴）+ `license.json` 下载 + 邮件附件（可选 SMTP）；
- 续费：新订单新 license（同机器码、新到期），旧 license 标记 `replaced`；
- 退款：未签发 7 天内可退；已签发/已激活按数字化商品不退（购买页显著提示+勾选）；退款标记后 license 置 `revoked`（离线现实：不能远程关停，靠下次换机/续费生效——见 §7）。

### 4.6 支付回调时序（幂等要点）

1. 建单落库 `pending`（金额快照、机器码、订单 token）；
2. 渠道回调 → 先落 `payment_events` 原始事件（防丢）→ 验签/金额/商户号 → `paid`（事务）；
3. `paid` 事务内创建 `license` 签发任务（同事务只允许一次）→ signer 签发 → 存 `licenses` + 交付 token；
4. 页面轮询读 `paid` → 展示授权码/下载；
5. 失败回调保留重放；金额不符/多付 → 告警 + 人工/退款，不签发。

### 4.7 安全与幂等清单（必须做）

- [ ] HTTPS + 回调地址公网可达；服务器时间同步（NTP）；
- [ ] 回调验签、金额核对（int 分）、商户号/APPID 核对、时间戳防重放；
- [ ] `out_trade_no` 随机不可枚举；`transaction_id/trade_no` 唯一索引；
- [ ] 订单查询用 **order_token**（32B 随机、只存哈希、7 天有效），错误 token 统一 404；
- [ ] 建单/查询/绑定按 IP+机器码限流；绑定失败阈值转人工；
- [ ] 私钥只在 signer；仓库/安装包无任何商户密钥；`.env` 不入库；
- [ ] 管理后台 2FA、操作审计、敏感操作二次确认；
- [ ] PII 最小化：只收交付/开票必需信息；不收集用户文件；日志脱敏；
- [ ] 备份：SQLite 每日备份 + license 台账导出；对账：每日渠道账单 vs `payments`。

## 7. 风险与红线

| 风险 | 对策 |
|---|---|
| 把 ICP 当支付资质 | ICP 只是门槛；商户号/签约是另一条链，老老实实申请 |
| 个人收款码/二次清算 | **禁止**；只用对公账户 + 商户号 + 平台店 |

| 公安备案逾期 | 网站开通 30 日内提交；通过后 30 日内挂页脚 |
| 离线授权无法远程吊销 | 退款/纠纷靠台账 + 交付记录；购买页写明数字化商品规则并勾选 |
