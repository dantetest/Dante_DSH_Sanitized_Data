## 0. 结论摘要

端到端测试里，「还原引擎」自身的问题（标签核心写法、案号空格、Excel 数值金额）
已修复；剩余问题都在**脱敏上游**，按严重度排序：

| 优先级 | 问题 | 证据强度 | 影响 | 建议 |
|---|---|---|---|---|
| **P0-1** | 近似实体归并**过合并**（法院/学校/公司被并成同一假值） | 映射库 36 组多原值，**12 组跨类别异质**，最多 1 组 11 个成员；涉及 3 个真实 job、90 条映射、最多 78 处还原会换错 | AI 视图里不同主体同名；还原时 canonical 覆盖所有出现位置 → **静默换错真值** | 收紧 ORG 同簇判据 + 簇级复核 + 映射存候选 |
| **P0-2** | 脏实体进映射（OCR/版面误检、正则过匹配） | D07 实测 5 个：`人名=公章/管理好`、`机构=按照银行/1甲方可以银行/方有权在甲方所在地人民法院` | 还原后出现语义垃圾；AI 视图噪声 | 新增实体质量闸门（校验器 + 阴影模式） |
| **P1-1** | 伪值语义不一致（身份证/固话/统一社会信用代码） | 27 对 ID：校验位/地区全对，但**性别一致仅 15/27（≈随机）**、出生年与原身份证平均差 **24.7 年**；固话 97/97 对区号被换；USCC 20/20 对地区码被换 | AI 基于假身份证推生日/性别会自相矛盾；AI 视图内部不一致 | 文档级一致性上下文（年龄/性别/城市）+ 保留地区码 |
| **P1-2** | AI 视图 PDF 文本层阅读顺序丢失 | D01 AI 视图 9 个实体值在 raw 文本里顺序与视觉顺序不一致（值被追加到内容流末尾，标签与值分离）；`get_text(sort=True)` 可恢复视觉顺序 | 依赖文本流的模型会错配字段（D01 子代理必须用 bbox 才配对） | 替换 op 按视觉位置排序 + 附「阅读顺序文本」sidecar；可选重建文本层 |
| **P1-3** | AI 基于假值的派生数字/结论无法还原 | D07 算式、D12 推算生日、D08 区号引用 | 还原后语义矛盾 | 客户提示词 + 还原报告一致性检查（低成本） |

建议落地顺序：**P0-1 → P0-2 → P1-1 → P1-2 → P1-3**。

## 2. 证据详情

### 2.1 归并过合并（P0-1，最严重）

`data/vault` 统计（按同一 job 内 `(etype, fake)` 归组）：

- 同假值对应多个原值：**36 组**，涉及 **7 个 job**。
- 其中跨机构类别的异质组：**12 组**；成员 ≥5 的大组：9 组。
- 异质组覆盖 **90 条映射**；按「canonical 覆盖所有出现位置」的现状，
  最多 **78 处**还原会换成错误原值；实际集中在 3 个 job（同一份判决书处理 3 次）。
- 典型（已打码）：
  - fake=`知行***公司`，11 个原值：类别 {公司 2、法院 3、学校 6}
  - fake=`星汉***法院`，8 个原值：类别 {法院 1、公司 7}
  - fake=`笃行***中学`，9 个原值：类别 {学校 2、公司 7}

D07 的归并组（`fake=西藏***6号`，3 个原值：`西藏***17`、`西藏***东县`、
`日喀则***17`）是**合理的 OCR 变体归并**，不能因噎废食；问题在 ORG 的
「简称别名」判据过宽。

### 2.2 脏实体（P0-2）

D07 实测检测结果（`origin` 来自实体元数据）：

| 实体值 | 类型 | 来源 | 置信度 | 备注 |
|---|---|---|---|---|
| `方有权在甲方所在地人民法院` | ORG（法院/检察院） | regex | 0.99 | 正则从句子中间起匹配 |
| `管理好` | PERSON（当事人/代理人） | model | 0.85 | 动作词被当人名 |
| `公章` | PERSON（人名） | model | 0.85 | 版面词被当人名 |
| `1甲方可以银行` | ORG（机构名称） | model | 0.82 | 数字+动词片段 |
| `按照银行` | ORG（机构名称） | model | 0.82 | 动词片段 |

映射库启发式扫描（偏保守）：`ORG 公文词` 15 条、`ORG 数字开头` 3 条、
`PERSON 公文词` 2 条（启发式有误报，但 D07 的 5 条已人工确认）。

### 2.3 伪值语义不一致（P1-1）

对 27 对身份证（原值→假值）：

- 格式/校验位/地区码：全部合法（27/27）；
- **性别位与原身份证一致：15/27（≈50%，随机水平）**；
- 出生年与原身份证平均相差 **24.7 年**（假生日 1950–2005 随机）。

当前 `_fake_id` 对 D12（原身份证 1958 年、女、文档写 67 岁）做 2000 次生成：

- 推算年龄恰好 67 岁：**1.49%**；性别为女：**49.5%**；
- 即 AI 从假身份证推出生日/年龄/性别时，几乎必然与文档保留的「67 岁/女」矛盾。

其他：

- 固话：97/97 对的区号（前 3 位）被替换成随机城市 → 与保留的地址城市不一致
  （D07 原文 028/成都，假电话变 025/南京风格）。
- USCC：20/20 对的 6 位地区码被随机替换 → 与公司/地址城市不一致；校验位合法。

### 2.4 PDF 文本层阅读顺序（P1-2）

D01 AI 视图（9 个实体值）：

- 视觉顺序（bbox y/x）：购买方名 → 销售方名 → 两个 USCC → 金额…；
- `get_text()` raw 顺序：两个 USCC → 金额 → 开票人 → 购买方名 → 销售方名
  （替换文字被追加在内容流末尾，顺序为实体处理顺序而非视觉顺序）；
- `get_text(sort=True)`：与视觉顺序一致（验证了「排序可解决」的假设）。

原 PDF 的 raw 顺序也有 1 处相邻反序；AI 视图更严重。D01 子代理明确说明
「纯文本流顺序会把购买方/销售方错配，必须用 bbox 定位」。

### 2.5 AI 派生数字（P1-3）

- D07：AI 回件引用 `122.60/205.75/205750.00` 等「按假金额推算/摘录」的数字；
  还原只换回映射里的直接值，算式与合计可能对不上。
- D12：AI 写「由身份证推算出生日期 1995-11-17」；还原身份证后该推断仍保留。
- D08：脚注「区号 025」等局部值不在映射里，还原后仍与真值语境不符。

## 4. 方案设计

### 4.1 P0-1：归并收敛 + 候选落盘

目标：**同类别、像同一个实体**才归并；归并结果可审计、可选择性还原。

1. **收紧 ORG 同簇判据**（`pipeline._org_alias_similar`）：
   - 先提取机构类别（法院/检察院、银行、公司、学校、医院、事务所、科研、政府、
     其他），**类别不同直接不同簇**；
   - `_org_alias_place_word` 扩展到「行政区名」：去掉省/市/县/区/镇/乡/街道/
     地区/盟/旗/自治县/自治州等后若为空/仅剩 1 字 → 视为地名，不构成简称；
   - 增加「OCR 噪声前缀」黑名单/剥离：`告、根据、据、案、中、后、故、完成、
     建设、证明、依法、向、与、及、系` 等出现在短 core 开头时，先剥离再比较；
     剥离后长度 < `ORG_MIN_CORE_LEN` 判否；
   - 链式并集复核：聚类后要求每个非 canonical 成员与 canonical 满足同类判据
     （不能仅靠 A~B、B~C 传递）；不满足则拆出/标记；
   - 簇大小上限（ORG 建议 ≤4，ADDRESS ≤5），超过则**不自动归并**，标记
     `needs_review`（宁可让 AI 看到不同假名，也不要静默错并）。

2. **canonical 选择**：在同类别成员里选「最完整 + 置信度最高 + 出现次数最多」；
   避免选到 OCR 噪声片段；类别由 canonical 决定（修复 fake 后缀与实体不符）。

3. **vault 保留归并候选**（向后兼容）：
   ```jsonc
   // 现有 map 不变：{etype: {orig: fake}}
   "aliases": {
     "<fake>": {
       "etype": "ORG",
       "canonical": "<canonical orig>",
       "candidates": [{"value": "...", "count": 2, "confidence": 0.85, "reason": "ocr_variant"}],
       "similarity": 0.93,
       "needs_review": false
     }
   }
   ```
   - `save_mapping` 的 `meta` 增加 `aliases`（AES-GCM 内已有加密保护，无新泄漏面）；
   - 旧版 `restore.py` 忽略新增字段，行为不变；新版：
     * 报告 `ambiguous` 列表（同 fake 多候选），默认 canonical；
     * UI 可在该映射下展开候选；P1 支持按回件上下文（后缀/领域词）自动选候选；
     * 对 `needs_review` 的簇在还原报告里置顶提示。
   - 迁移：无需回填；新导出自动带；旧 job 继续 canonical + warning。

4. **验收**：
   - D07 合理归并组保持（3 个地址变体仍同假值）；
   - 重建 `j_0b39de34`/`j_375ee670`/`j_69c3b75d`（同一判决书）时，异质组从
     12 → 0；同类簇大小 ≤4；还原报告不再出现“法院/学校换回公司名”。
   - 新增单测：`_org_alias_similar` 的法院/学校/公司交叉、县名 core、链式膨胀。
   - 全量映射扫描：异质组比例 0；`needs_review` 数量有记录。

### 4.2 P0-2：实体质量闸门

目标：**高精度地挡掉明显非实体**，宁可标待确认，不误删真实敏感值。

1. 新增 `app/server/yinzhan/detectors/quality.py`（或 `pipeline.validate_entities`），
   在 `jobs._run` 中「所有检测 + 表单补充」之后、`pipeline.decide` 之前调用：
   ```
   detect/supplement → quality.validate(entities, doc, rules) →
       accepted / pending_review / dropped
   → decide → consolidate → export
   ```
2. 分类型校验（原型已验证 D07 5 条全挡、真实实体全过）：
   - **PERSON**：2–4 个汉字（少数民族/外文名单独规则）；不在公文动作词/称谓表
     （扩展 `公章、管理好、按照、可以、有权、所在、日期、签字、盖章…`）；
     model 来源且置信度 <0.9 时，要求附近有强上下文（`_HINTS` 命中）
     或结构化字段（姓名/联系人/签字…），否则降级 `pending`；
   - **ORG**：必须有机构类别后缀（法院/检察院/银行/公司/学校/医院/事务所/
     科研/政府等之一）；拒绝数字/英文开头、以动词/OCR 噪声前缀开头；
     法院/检察院单独校验（见下）；
   - **法院/检察院正则**：
     * 收紧 pattern：优先「行政区前缀 + 法院名」，限制起始边界；
     * 保留 `strip_prefix`，新增 `validate: court_name`：前缀不得含
       有权/可以/按照/所在/甲方/乙方/向/在/于/由 等，且长度/结构合理；
       `最高人民法院/最高人民检察院` 白名单；
     * 用 D07 的坏例 + 20 个真实法院名做正负样本单测；
   - **ADDRESS**：至少含行政区/路/号/室层级，长度 ≥6；孤立的「XX县」不单独成实体；
   - **USCC/ID/PHONE/ACCOUNT**：复用/加严现有 validators（校验位、位数、号段），
     与伪值生成约束一致；
   - 对已 accepted 的视觉实体（人脸/印章）不参与此闸门。
3. 处置策略：
   - `dropped`：明显非敏感垃圾 → 不进实体/映射，计入 job.warnings
     （「已过滤 N 个低质量实体：ORG 3、PERSON 2」），审计只记数量/类型；
   - `pending_review`：不确定（如少数名族名、外文名）→ 保留现有“待确认”流程；
   - **Phase 0 阴影模式**：先只记录不拦截，跑既有测试集/用户样本 1–2 天，
     人工抽查误杀率；确认后默认开启拦截（环境变量可回退）。
4. 验收：
   - D07 的 5 条垃圾不再出现；所有原有真实实体（公司/银行/人名/地址/
     法院）全部保留；
   - 全量 QA 集实体数量变化与人工标注对比：真实实体召回下降 ≤0.5%，
     垃圾实体下降 ≥90%；
   - `human` 模式不因过滤而漏黑（垃圾实体本来不需要黑；真实实体不变）。

### 4.3 P1-1：文档级一致性上下文（伪值生成）

目标：假值之间、假值与保留字段（年龄/性别/城市）语义一致，且不增加真实泄漏。

1. **事实提取**（解析后、decide 前，`jobs._run`）：
   - `gender`: `性别[:：\s]*(男|女)`；`age`: `年龄[:：\s]*(\d{2,3})` /
     `(\d{2,3})岁`；`birth`: `出生日期/出生年月`；
   - `region/city`: 从同一文档地址/机构/USCC/ID 提取（取首个有效）；
   - 多 ID/多人场景：按实体 span 找**最近的前置标签/同一 block** 配对；
     匹配不到则退回文档级 facts（P1 先支持单证件文档）。
2. **数据模型**：
   - `udm.ReplaceContext` 增加 `facts: dict`；
   - `pipeline.Session` 增加 `facts`（或 `job.session.facts`）；
   - `surrogate._generate` 把 `ctx` 传给需要上下文的工厂
     （`_fake_id/_fake_phone/_fake_uscc` 等；其余工厂签名加 `ctx=None` 兼容）；
   - `jobs._run` 在 parse 后设置 `session.facts`；`pipeline.decide` 构造
     ReplaceContext 时带 facts。
3. **生成器改造**：
   - **身份证**：保留原前 6 位地区码；有 age/gender 时：
     出生年 = 当前年 − age（月份/日期随机且保证周岁），顺序码奇偶匹配性别，
     重算 GB 11643 校验位；无 facts 时保持现有合法随机（但记录
     `consistency="unknown"`）；未成年人严格模式下保持「未成年」属性；
   - **固话**：保留原区号（从已知号段表最长匹配；修正 `_pick_area` 的
     “0288” 贪心问题），仅替换本地号，保持分隔符/长度；
   - **USCC**：保留前 8 位（登记管理部门/类别 + 6 位地区码），随机化 9–17 位
     并重算 GB 32100 校验位；若原 USCC 前 8 位异常则回退随机；
   - **地址/机构**：现有实现已保留省市区前缀（同城），与本方案兼容；
     若地址没有街道层级而被换区县，则同步调整电话/USCC 地区码来源
     （优先用“假地址”的城市，而不是原文城市）。
4. **隐私/合规**：
   - 保留地区码/区号只到城市级，文档本身已保留地址城市，不增加识别面；
   - 身份证生日由“文档年龄”推导，不复制真实生日；性别位与文档一致；
   - 旧映射不受影响；新导出映射的 fake 仍是随机可撤销值。
5. **原型结果**（已跑）：
   - 一致性身份证 500/500 满足「校验位合法 + 年龄 67 + 女性」；
   - USCC 500/500 满足「校验位合法 + 地区码不变」；
   - 固话保留区号方案格式可行（注意区号用已知号段最长匹配）。
6. **验收**：
   - 全量映射中 ID 性别一致率从 55.6% → 100%（有 facts 的 job）；
     出生年差从 24.7 年 → 0（按文档年龄）；
   - USCC 地区码 100% 保留（有原值地区码时）；固话区号 100% 保留；
   - 新增单测：D12（女/67）、无年龄/性别回退、多 ID 配对、校验位/未成年人。

### 4.4 P1-2：AI 视图 PDF 阅读顺序

三个层次，按成本从低到高：

1. **阶段 1（推荐先做，0.5–1 人日）——替换 op 按视觉位置排序**
   - 在 `pdf_parser.export` 里把 `ops_by_page[page]` 的替换/涂黑操作按
     `(display_rect.y0, display_rect.x0)` 排序后再 `insert_text`/图片渲染；
   - 效果：替换值在 raw 文本里的相对顺序与视觉顺序一致（D01 会从
     USCC→金额→人名 变为 买方→卖方→USCC→金额）；
   - 注意旋转页/同 y 多列：先按 y 分组再 x 排序；列布局可用 UDM block 的
     x 分布做二次校验；
   - 测试：D01 raw 顺序断言；所有 PDF 导出回归通过；不改变可见内容。
2. **阶段 2（0.5 人日）——附带「阅读顺序文本」sidecar**
   - AI 视图导出时额外生成 `*_阅读顺序.txt`（`page.get_text("text",
     sort=True)` 或 UDM block 按阅读顺序拼接）；
   - 导出结果/UI/MCP 返回 sidecar 路径；客户说明「把 AI 视图 + txt 一起给 AI」；
   - 对多栏/复杂表格最稳，且零版式风险；
   - 测试：D01 文本与视觉顺序一致；客户 SOP 更新。
3. **阶段 3（可选，2–3 人日）——AI 视图重建隐藏文本层**
   - 对文本层页：渲染可见页面为图（保留视觉），再用阅读顺序文本写隐藏层
     （复用扫描页 `_write_ai_text_layer` 机制）；
   - 优点：文件本身文本层正确；缺点：文件变大、正文变图片、字体/可访问性
     下降、渲染质量需评估；
   - 建议做成显式选项（`YINZHAN_AI_TEXT_ORDER=rebuild` 或导出选项），
     默认关闭，先给客户试用收集反馈。
4. **不建议**：让 AI 自己按 bbox 读（依赖模型/工具）；或只改提示词（不可控）。

### 4.5 P1-3：AI 派生值（低优先级）

1. 产品侧提示词/客户指南：给 AI 的说明中明确「数值/字段请原样引用，不要自行
   换算、四舍五入、推算；如需计算，请标注为推算值」；
2. 还原报告增强（`restore.py`，低成本）：
   - ID 号 ↔ 文档年龄/性别一致性检查；
   - 同名字段多处值是否一致；
   - 货币数字是否满足「合计≈明细和」「大写/小写一致」；
   - 结果放入 `warnings`/新增 `manual_check` 列表，不做自动改写。
3. 不建议用映射去反推 AI 的计算结果（缩放因子反算只对固定缩放公式有效，
   对 AI 任意推算不可靠）。

## 8. 最高风险在哪、怎么保证安全

### 8.1 两类“最高风险”要分开看

1. **数据正确性最高风险：归并过合并（P0-1，已经在发生）**
   - 12 组跨类别异质簇、90 条映射、最多 78 处还原会静默换成错误真值；
   - 危害是“看起来正常、实际错误”：AI 视图里不同主体同名，还原稿交给人时
     可能被当成真的，且现有报告只有一句 warning，容易被忽略。
2. **隐私安全最高风险：质量闸门/归并收紧的“误杀”（修的时候引入）**
   - 如果新校验器把真实敏感实体（人名/账号/法院名等）误判成垃圾丢掉，
     原值就会留在 AI 视图里被外发——这是**红线泄漏**，比“换错值”严重；
   - 原则：**只有确定是垃圾才自动丢；不确定就保留/待确认；绝不能因为改动
     而降低脱敏覆盖率**。
3. P1-1 一致性生成的风险：若把真实生日/真实地区位写回假值 → 可能增加识别面；
   必须坚持“假生日由年龄推导、地区只到城市级、假值不含原值”的隐私不变量。
4. P1-2 PDF 顺序的风险较低：不改变内容/位置，主要是版式与兼容性风险。

### 8.2 安全设计原则（所有改动共用）

1. **单向安全**：任何上游改动必须让“原值外泄风险”不增加；拿不准就保留原行为。
2. **宁可少并，不可错并**：不合并只是 AI 看到多个假名（可用性下降），
   错并会污染 AI 视图和还原值（正确性事故）。
3. **宁可多报，不可漏报**：垃圾实体默认“待确认/保留”，只有高精度规则才自动丢。
4. **fail-closed**：出口 `verify` 失败、映射可逆性/一致性校验失败 → 阻断导出；
   新校验先以 warning/阴影运行，确认零误杀后再开关为阻断。
5. **可逆性不可破坏**：`map` 语义保持向后兼容；新增 `aliases` 只增不改；
   所有新假值仍能通过 vault 还原。
6. **隔离/灰度/可回退**：feature flag、阴影模式、内部灰度 → TestMode 客户 →
   正式；任何一步异常可关 flag/回滚安装包，不做破坏性数据迁移。
7. **证据先行**：金样本/标注集/差分测试/阴影期指标达标后才发布。

### 8.3 各改动的硬护栏

**A. 实体质量闸门（P0-2）**
- 自动丢弃只限“高精度黑名单/形态规则”（D07 五类），其余一律保留或进
  `pending_review`；**隐私关键类型（身份证/账号/银行/密码/密钥/证件类）永不自动丢**。
- 命中结构化字段上下文（姓名/联系人/账户/当事人/签字等）或通过校验位/
  格式校验的实体，**受保护，不自动丢**。
- **阴影模式**先上线：只记“将丢弃”清单（类型/数量/哈希，不记原值），
  在 54-job 映射库 + QA 标注集上做差分；真实敏感实体召回下降 **≤0.5%**
  才允许切 enforce；切后保留 `YINZHAN_ENTITY_QUALITY=off` 退路。
- 过滤结果写 warning/审计计数，不写原值；human 涂黑版不因过滤减少真实黑块。

**B. 归并收敛（P0-1）**
- 硬判据：机构类别不同不并；纯行政区 core 不并；OCR 噪声前缀剥离后过短不并；
  链式并集必须每个成员与 canonical 直接满足判据；ORG 簇 ≤4、ADDRESS ≤5，
  超限转 `needs_review`。
- 新增**导出前映射一致性检查**：同一 fake 的候选必须同类别/同实体；
  发现异质簇 → 不合并 + 标记 review；先 warning，稳定后对 AI 导出 fail-closed。
- 金样本：D07（3 个地址变体必须保留归并）、判决书样本（12 个异质组必须拆开）、
  其余 36 组逐组人工过一遍。
- 还原回归：canonical/候选模式下 E2E 四文档残留假值 0、换错值 0；
  报告 ambiguous 列表，不静默。

**C. 一致性伪值（P1-1）**
- 生成后校验不变量：长度/格式/校验位合法；地区码/区号保持；性别位与文档性别
  一致；出生年与文档年龄一致；假值 ≠ 原值且不包含原值；与已用假值不冲突。
- facts 冲突/多证件匹配不到 → **回退现有合法随机生成**并标
  `consistency_unknown`，不猜。
- 隐私评审：只用文档已保留的城市/年龄/性别；不复制真实生日；地区只到城市级。
- 单测 + 54-job 全量统计：ID 性别/年龄一致率 100%（有 facts 时）；
  固话区号保持 100%；USCC 地区码保持 100%。

**D. PDF 顺序（P1-2）**
- 阶段 1 只排序插入 op：断言排序前后 `(rect, text)` 多重集完全一致；
  现有文本/像素 verify 全过；旋转页/列布局金样本；开关可回退。
- 阶段 2 sidecar：只新增文件，不改 AI 视图；sidecar 文本必须不含原值
  （对 AI 视图做一遍残留校验）。
- 阶段 3（重建文本层）默认关闭，仅作为显式选项灰度。

**E. AI 派生值（P1-3）**
- 只加提示与报告检查，不自动改回件；检查失败只列“需人工核对”。

### 8.4 上线门禁（必须全绿才发）

1. `regression.py` 250 项硬检查全绿；`test_restore`/`test_mcp_*` 全绿。
2. E2E 4 文档 + 判决书样本：AI 视图 verify 通过、原值残留 0、还原残留假值 0、
   换错值 0。
3. 映射库全量扫描：异质簇 0；`needs_review` 有记录；fake→orig 可逆性 100%
   （抽取全部 fake 做 rehydrate 回环，逐条核对）。
4. 标注集：真实敏感实体召回下降 ≤0.5%；垃圾实体下降 ≥90%；
   隐私关键类型召回 = 100%。
5. 一致性指标：有 facts 的 ID 年龄/性别一致率 100%；固话区号 100%；
   USCC 地区码 100%。
6. `audit_release.py`（--no-smoke 至少）通过；安装包冒烟+TestMode 验证通过；
   回滚演练（关 flag / 换回旧安装包）一次通过。
7. 灰度路径：内部 → 1–2 个测试客户（TestMode）→ 正式；每阶段看
   warning 计数、用户反馈、审计统计，异常立即回退。

### 8.5 建议先做的“零风险护栏”（不等完整修复）

在动生成逻辑之前，先加一个**只读/可配置**的护栏：

- job 完成/导出前扫描本 job 映射：检测「同 fake 多原值且跨机构类别」和
  「簇成员超上限」→ 写 `needs_review`、在 UI/导出结果/还原报告里显式标红；
  初期只告警，稳定后对 AI 导出可配置为阻断；
- 还原报告把 `ambiguous` 候选列清楚（已有基础，补 candidates 展示）；
- 这样在完整修复前，先把“静默换错/自相矛盾”变成“显式可见、可人工拦截”，
  不影响现有导出与脱敏覆盖率。
