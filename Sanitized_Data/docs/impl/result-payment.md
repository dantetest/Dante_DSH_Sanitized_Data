# 结果付费方案 · 技术与产品设计（预览免费，满意后按一次结果付费）

> **状态**：设计规划（**本批只新增/修改文档，未改任何代码/配置/前端**）· 2026-10-24

> **一句话**：**条件方案**——默认不改变“免费 3 份/天、导出永不 gate”；**水印已否决（含预览）**；只有 D-R1 拍板后才做完整“预览免费+按结果付费”（预览仅靠限页/低清/禁下载，无水印）；否则最多做“首单 ¥9.9 获客券”。**完整版成本 31–45 人日；首单券 8–12 人日。**

## 0 结论先行

| 项 | 设计 |
|---|---|
| 产品形态 | **条件方案**：默认不改免费 3 份/天/导出永不 gate；**水印已否决（含预览）**；只有 D-R1 批准后才做“预览免费+按结果付费”，预览靠限页/低清/禁下载 |
| 计价单位 | 1 次“成功导出”= 1 个结果；同一 Job 的**换名版 + 涂黑版算 1 个结果**（不重复收）；按页数分档 |

## 1 为什么做“结果付费”（定位）

1. **降低第一次付费门槛**：用户已经在本机看到脱敏效果、自检通过，再付 ¥19，比“先买 ¥199 年费”心理阻力小；
2. **把“满意”作为收费点**：价值发生在“导出可外发成品”，而不是“打开软件/识别”；
3. **覆盖年费覆盖不到的人**：一年只用 1–3 次、但单份很重要（合同/病历/审计底稿）的用户；
4. **不破坏现有漏斗**：免费版/试用/年费/团队/机构保留；结果付费只是“超出免费额度/大文件/低频”的出口。

**不做**：不替代年费；不做团队/机构按文件；不让 MCP Agent 代付；不做“先导出后付款”（无法离线约束）。

## 2 与现有付费模式的关系

| 用户 | 现有方案 | 结果付费如何介入 |
|---|---|---|
| 第一次用、文件小 | 免费版 3 份/天 | 不需要付费；预览/导出免费 |
| 第一次用、文件大/扫描件多 | 免费版限额不够 | 预览免费 → 满意后买 1 个结果（¥19/29/49） |
| 一年 2–5 次、每次大文件 | 年费 199 不划算 | 结果付费更合适；多次后可抵扣升级年费 |
| 一年 ≥7 次 | 年费 199 更便宜 | 结果价 ×7 ≈ 年费；引导年费 |
| 专业/团队/机构 | Pro/Team/Org | 不开放结果付费（团队 credits P2 单独评估） |
| MCP/Agent | Pro | 仍返回 `license_required`；结果付费不进入 MCP |

**定价交叉点**：单份 ¥19 × **10.5 份 ≈ ¥199 ≈ 个人版年费** → **≥11 份/年应买年费**；扫描件/大文件 ¥29 × **6.9 份 ≈ ¥199** → **≥7 份大文件应买年费**；**P0 不做包**（129/149 元包会把临界点推到 13–15 份，蚕食年费）。

## 3 产品流程与 UX

### 3.1 免费预览（未付费）

- 打开文件 → 解析/识别/对照/自检全部免费（与现有工作台一致）；
- **未付费预览（需 D-R1 批准；无水印）**：
  * 低清（服务端输出像素上限）；
  * 每 Job 只给前 5 页，其余不渲染；每天最多 3 个 Job；**不可下载/导出/复制预览图**；
  * 实体清单/“已隐去 N 处”/出口自检结果照常展示（这是用户判断“满意”的依据）；
- 付费/试用/年费用户预览全页、全清晰。

### 3.2 付费导出（结果付费）

```
用户点「导出」 → 弹出「满意再付」面板
  ├─ 显示：页数、识别处数、自检结果、价格（¥19/29/49）、两种出口
  ├─ 选择：微信/支付宝（B，自动）/ 卡密或兑换码（A，回填）
  ├─ 支付成功 → 获得 1 个 result credit（B 自动导入；A 下载/粘贴 license）
  ├─ 导入成功 → 自动继续导出 → 显示 sha256/复检报告（residual 仅提示，不阻断）
  └─ 失败：不扣 credit / 客服人工核验退款；提示重试或联系客服
```

- “先预览后付费”必须让用户看到**足够判断**的内容（页数、实体、自检），但不能拿到可外发成品；
- 未付费用户可反复预览/调整（框选补漏、严格度），**满意再付**；
- 付费后 30 天内同一 Job 可重下（同一结果），不重复收费（token/credit 绑定 Job 或本地记录）。

### 3.3 MCP / Agent

- **MCP 不参与结果付费**：`export_sanitize_job` 仍只认 Pro/Team/Org，无授权返回 `license_required`；不在 Agent 侧发起支付、不返回价格。
- Agent 不得代付；用户到工作台/软件完成购买并导入 credit 后，重试工具即可；
- 纯 Claude/Cursor 无宿主 UI 时体验差，**不建议在此形态推结果付费**；MCP 仍按 Pro 订阅。

### 3.4 到期/失败/退款

- 支付后未导入/未使用：7 天内可退（订单页/客服）；
- 导入后未导出：30 天内有效，可退（未使用）；
- 导出失败/残留>0：**不消耗 credit；已扣走客服人工核验退款（不承诺自动退）**；
- 已导出：不退（数字化商品，购买页明示）。

## 4 计费规则

### 4.1 “结果”的定义

- 1 个结果 = **同一 Job 的一次成功导出**；包含 `ai`（换名可还原）与 `human`（涂黑不可还原）两种出口，不重复收费；
- 页数档按**解析后页数**（`len(doc.pages)`）：
  * ≤50 页：1 个结果（单份 ¥19 或 1 credit）；
  * 51–150 页 / 扫描件 OCR：¥29/份（result token，不消耗 credits）；
  * >150 页 / 批量 / 含审计报告：¥49/份（result token，不消耗 credits，不主推）；
- 未付费预览不消耗；失败导出不消耗；同一 Job 30 天内重下不重复消耗；
- 免费版 3 份/天仍按原规则；结果付费用于超出免费额度或大文件（见 §4.3）。

### 4.2 价格表（建议，待市场锚校准）

| SKU | 价格 | 内容 | 有效期 |
|---|---|---|---|
| 首单体验 | **¥9.9** | 1 个结果（≤20 页），限首次购买/设备；**可开票** | 30 天 |
| 单份·小 | **¥19** | 1 个结果（≤50 页） | 购买后 30 天内使用 |
| 单份·中 | **¥29** | 1 个结果（51–150 页 / 扫描件 OCR / 含复检报告） | 同上 |
| 单份·大 | **¥49** | 1 个结果（>150 页 / 批量 / 含审计报告 / 加急；不主推） | 同上 |

- **不按页收费**（用户难预测）；页数分档即可；
- 年费个人 ¥199 不限量；结果单份 ¥19 → **10.5 份≈年费**，高频用户自然转年费；单份 ¥29（扫描件/大文件）→ **6.9 份≈年费**；
- **P0 不做 10 份包/年费抵扣**：包价会把“≥11 份买年费”的交叉点推到 13–15 份，蚕食年费；P1 再评估且必须重算；
- **首单 ¥9.9** 限 1 次/机器/手机号、≤20 页；防刷（订单风控）。

### 4.3 免费额度与结果付费的边界（需拍板）

| 方案 | 免费版 | 结果付费 | 评价 |
|---|---|---|---|
| **A 保留免费 3 份/天（建议）** | 3 份/天完整导出 | 超出 3 份/天、或单份 >20 页/OCR >10 页时按结果 | 不破坏现有漏斗；结果付费是 top-up，收入有限但安全 |
| B 预览免费、导出全付费 | 3 次预览/天，不导出 | 所有导出按结果 | 更贴合“满意再付”，但免费价值下降、与 plan05 冲突，获客受影响 |
| C 混合：首份免费 + 后续付费 | 1 份/天 | 超出后按结果 | 折中；需改免费版策略 |

**建议 A**；若市场验证“预览→付费”转化高，再评估 B（需同步 plan05/免费版矩阵）。D-R1 待拍板。

**技术口径**：结果付费解锁的是“**该 Job 的导出**”，不是“整个免费版额度”：
- 免费额度仍按 3 份/天/20 页/OCR 10 页限制；**超过这些限制时，导出接口要求 result token/credit**，而不是直接拒绝；
- 校验顺序：Pro/trial → 免费额度内放行 → 否则校验 result token/credits → 通过则导出；**导出成功后扣减**，失败不扣；
- 免费额度计数不因购买结果而重置；结果导出也不占免费 3 份额度（避免双重扣）。

## 5 技术设计（离线 token / credits）

### 5.1 授权形态

| 形态 | 用途 | 签名 | 绑定 | 使用 |
|---|---|---|---|---|
| **credits license**（P0） | 预付费包/单份结果，A 静态支付也适用 | Ed25519（同产品密钥，`key_id` 相同） | 机器码（可多设备？个人 1 台） | 导入后本地计数，每次成功导出扣 1（大文件扣 2/3） |
| **result token**（B，可选） | 单次支付后自动解锁 | Ed25519 | order + job_id + 机器码 + 结果指纹 + 30 天 | 校验后允许该 Job 导出；**有效期内可重复校验该 Job，不写 used 即废** |
| 年费/团队/机构 license | 不限量 | 同现有 licensing | 机器/席位 | 不消耗 credits |

**credits license payload 扩展**（P1 才用；在 [licensing.md](licensing.md) schema 上）：

> **必须先改 licensing schema**：`sku` enum 加 `credits_*`、`term` enum 加 `credits`（`expires_at` 必填），校验分支加 credits；旧版本遇 `term=credits` 应提示“请升级客户端”，不能报 `license_invalid`。**payload 只放 `credits_total`，`credits_used` 只写本地 HMAC 状态，绝不回写 payload**（本地无私钥，不能重签）。

```json
{
  "schema": 1,
  "alg": "Ed25519",
  "key_id": "prod-2026",
  "payload": {
    "license_id": "lic_20261024_credits_xxx",
    "order_id": "ord_...",
    "sku": "credits_10",
    "edition": "结果包",
    "term": "credits",
    "seats": 1,
    "max_devices": 1,
    "machine_codes": ["K7Q2-9WXM-4TRB-EFGH"],
    "credits_total": 10,
    "credits_note": "1 credit = 1 个 ≤50 页结果；51–150/ >150 页按单份 result token 购买",
    "issued_at": "...", "not_before": "...", "expires_at": "...",
    "features": ["result_export"],
    "issuer": "BLCTEK"
  },
  "sig": "<base64>"
}
```

- 本地状态 `license/credits_state.json`（HMAC）：`used`, `last_seen`；每次成功导出递减，**只改本地 HMAC 状态，不回写/重签 payload**（本地无签名私钥）；
- **防篡改**：签名 + 本地冗余 + 时钟检测；接受一定破解（低价）；
- `result token` payload：`{token_id, order_id, job_id, job_fingerprint, machine_code, modes:["ai","human"], expires_at, price_cents, nonce}`；引擎验签后允许该 job 导出（校验 fingerprint）；**有效期内可重复校验该 Job，不写 used 即废**；本地用 `license/result_grants.json` 记录 job→token 映射，删状态走客服。

### 5.2 预览限制/付费墙（服务端；**默认不实施，需 D-R1**）

> 前置：现有 `preview?mode=out` 会下发原文/替换表，“外发版”是前端 overlay，`/file` 无鉴权，预览会落盘清晰成品。**不先做“服务端 out 预览 + `/file` entitlement + 清理临时成品”，付费墙就可绕过；这部分 5–7 人日，必须计入。水印已否决，不叠加水印；防绕过强度更低（接受截图风险）。**

- `api.preview` / `api.render` 增加 `unpaid` 判断：无 license/trial/result token 时：
  * 服务端合成 out 预览（无水印）；
  * 输出像素上限（不写 dpi，兼容 PDF/DOCX）；只给前 5 页；每天最多 3 个 Job；
- `POST /api/jobs/{jid}/export` 增加检查（**只在 D-R1 批准后改；默认永不 gate**）：
  * Pro/Team/Org/trial → 放行；
  * 免费额度内 → 放行（3 份/天规则）；
  * 否则必须有 result token/credits；**禁止只靠前端隐藏按钮**；
  * 导出成功后再扣 credit（失败不扣）；
- 前端：导出弹窗显示价格/余额；购买入口 A/B；导入 credit 后自动重试；错误码 `result_required` / `credits_exhausted`（MCP 仍用 `license_required`）。

### 5.3 支付与订单（商业侧）

- 新增订单类型 `kind=result`（P0 只做单份；`credits_pack` P1 再评估）；
- 商品：`result_first/small/medium/large`（P0 不做 `credits_10`）；
- 下单需带 `quote_id`（服务端按客户端上报的 pages 算价；**必须信任客户端页数**，页数低报是已知残留，靠抽查/退款争议约束）、`machine_code`（绑定）、`job_id`（B 模式）；
- 支付回调后签发 result token（或 P1 credits license）；A 模式给下载/兑换码；B 模式自动导入；
- 发票：每笔可开电子普票（含首单）；支持按月合并（同购买方）；不得拒开/延迟；
- 退款：未签发/未导入 7 天；已导入/已签发不退；导出失败走客服人工核验（零外呼无法自动退）；
- 管理后台：结果订单/token/退款/发票/异常（重复支付/未导入）。

### 5.4 API 变更（建议）

| 方法/路径 | 用途 |
|---|---|
| `POST /api/result/quote` | 按 job/page/mode 报价，返回 quote_id/价格/credits；免费 |
| `POST /api/result/import` | 导入 credits license 或 result token；引擎验签 |
| `GET /api/result/status` | 当前余额/可用 token/免费额度 |
| `POST /api/jobs/{jid}/export` | 增加 credits/token 校验；成功扣减 |
| `POST /api/jobs/{jid}/export/quote` | （可选）前端导出前估价 |
| MCP `export_sanitize_job` | 仍只认 Pro/Team/Org，无授权返回 `license_required`；MCP 不参与结果付费 |
| GUI `POST /api/jobs/{jid}/export` | 无免费额度/result token 时 `result_required`（**需 D-R1 批准后才加此分支**） |

商业侧：`POST /api/order` 扩展 `kind/quote_id/job_id`；`POST /api/result/issue`（内部）；后台退款/发票。

### 5.5 安全与防绕过

| 威胁 | 对策 | 残留 |
|---|---|---|
| 未付费导出 | 服务端强制校验 credits/token；前端隐藏无效 | Python 可被打补丁（接受） |
| 截图预览绕过 | 限页+低清+禁下载；**无水印** → 截图风险更高 | 可读但质量差、页数不全（接受） |
| 复制 token | 绑机器码/Job/指纹；有效期内可重复校验该 Job；本地状态 | 同机多用户可用 |
| 篡改 credits 计数 | HMAC 状态 + 冗余 + 时钟 | 清零可重置（接受） |
| 改价/伪造订单 | 服务端报价；回调验签；token 签名 | 极低 |
| 重复退款 | 订单/credit 状态机 + 审计 | 低 |
| 预览 OCR 滥用 | 3 Job/天 + 页数上限 | 低 |

## 6 团队/机构边界

- 团队/机构**不开放结果付费**（每文件开票/对账成本高、合同席位更合适）；
- 团队可购买 credits 包作为“超量补充”（可选，P1）：管理员在后台买包、分发给成员；发票按包开，不按文件；
- 机构合同内按年/席位；超量按合同附件，不进入自助结果付费。
