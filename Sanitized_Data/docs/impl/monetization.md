## 1 目标与「不做」

### 1.1 目标（P0 验收口径）

1. 用户下载安装后，**不买也能用**（免费版，按 §02 限额）；首次启动自动 14 天全功能试用。
2. 用户在官网/本机价格页看到 **4 档价格 + 机构报价入口**，能完成支付。
3. 支付成功后，用户凭 **机器码** 在线取得授权文件；在本机**导入即解锁**，全程**不需要联网校验**。
4. 支持**电子普通发票**（自动/半自动）与**增值税专用发票**（人工/半自动）申请，订单可查、可对账。
5. 授权到期前提醒、到期后 14 天宽限，宽限结束回到免费版（数据不丢）。
6. 以上链路在**引擎零外呼**的前提下成立：授权校验、免费限额、试用判断全部本地完成。

### 1.2 明确不做（本批 / 近期都不做）

- 不做联网激活/心跳/在线吊销/账号体系/遥测/自动续费；
- 不做可见水印、不降级输出质量、不上传用户文件；
- 不做「云端脱敏」或任何把文件交给服务器的功能；
- 不做实时并发席位控制（机构版靠合同与审计，见 [01 §7](licensing.md)）；
- 不在产品安装包里放支付/发票/营销代码（商业站点与产品物理分离，见 §3）。

## 2 现有架构事实（方案必须顺着它设计）

| 事实 | 对方案的影响 |
|---|---|
| 引擎是本地 Python + 标准库 `http.server`，只监听 `127.0.0.1`（`api.py`） | 授权校验不能依赖网络；只能读本地授权文件 |
| 产品承诺「引擎无出站 socket」（README/`CONTRACT.md` 安全红线） | **不能**在引擎里调支付/激活接口；购买动作只能由用户点链接打开系统浏览器完成 |
| 数据目录由 `paths.py` 决定（桌面版 `%LOCALAPPDATA%\Sanitized_Data`） | 授权/试用/计数状态放 `data/license/`，随数据目录走 |
| `cryptography>=41.0` 已是运行时依赖（映射库加密） | 可直接用 **Ed25519** 验签，不新增依赖 |
| PyInstaller onedir + Inno Setup 安装包（`desktop/`） | 公钥作为只读资源打进包；私钥只在授权服务器，绝不进包/仓库 |
| 单文件任务模型：`api.upload` → `api.create_job` → `jobs.JobManager.create` → 后台线程 `_run` | 限额与功能门禁放在 `create_job` + `JobManager.create` 双层 |
| MCP 是独立 stdio 进程（`mcp_server.py`），直接调 `jobs` | MCP 侧也必须在工具调用入口校验授权（不能只靠 UI） |
| 静态站 `app/web/` 纯本地、无 CDN、无外链脚本 | 价格页沿用 `site.css` 设计语言；购买按钮只做「打开外部链接」，本地页不埋点 |
| 已有审计链（`audit.py`） | 授权导入/续费/试用开始等事件写入本地审计（只记类型，不记敏感值） |

## 3 目标架构（商业侧与产品侧物理分离）

```
┌──────────────────────── 公网（商业侧，新增，不在安装包里） ────────────────────────┐
│                                                                                  │
│  官网静态页（首页 / 价格 / 下载 / FAQ / 协议）                                    │
│      │  购买 CTA                                                                 │
│      ▼                                                                           │
│  购买服务（独立进程/独立库，FastAPI 或 Flask）                                     │
│    ├─ 订单 / 支付回调（微信支付 APIv3、支付宝 RSA2）                              │
│    ├─ 授权签发（调用本机签名器；私钥只在此服务器，权限 600，异地备份）              │
│    ├─ 发票申请 / 开票队列（电子普票自动或人工；专票人工）                           │
│    ├─ 邮件/短信发授权文件与下载链接                                                │
│    └─ 管理后台（订单、补发、绑定、退款、发票、报表、2FA）                          │
│                                                                                  │
└───────────────▲──────────────────────────────────────────────┬───────────────────┘
                │ 用户点链接/扫码（浏览器行为，产品不参与）          │ 用户下载 license.json
                │                                                ▼
┌───────────────┴──────────────── 本机（产品侧，禁网） ────────────────────────────┐
│  数据隐站引擎（127.0.0.1，无出站 socket）                                          │
│    ├─ 无授权：免费版限额（3 份/天、页数/OCR 上限、通用规则包、无 MCP/批量/审计导出）│
│    ├─ 试用：首次启动 14 天全功能（本地状态，不联网）                                │
│    └─ 已授权：导入 license.json（Ed25519 验签 + 机器码 + 到期/宽限 + 时钟检测）      │
│                                                                                  │
│  数据（data/license/）：license.json、state.json、trial.json、备份、审计记录        │
└──────────────────────────────────────────────────────────────────────────────────┘
```

**三条铁律**

1. **产品引擎零外呼**：授权文件由用户手动下载/粘贴导入；价格页的「购买」按钮用 `target="_blank"` 打开公网地址，引擎不参与请求。
2. **私钥永不进产品**：公钥可公开嵌入；私钥只在授权服务器，签发动作有审计日志。
3. **商业服务故障不影响产品**：授权一旦导入即本地有效；买不到/服务挂了，老用户照常用（到期后进入宽限）。

> 人日口径：不含市场投放、法务审协议、客服培训；不含 macOS 签名/公证；不含 P1（团队管理台/机构交付工具）。

| 4 | 授权导入 | 导入合法 license 立即解锁对应功能；伪造/篡改/机器码不符/过期均被拒并给出可读原因 | 测试 |

| 6 | 支付闭环 | 真实小额支付→订单 paid→绑定机器码→下载 license→离线导入→功能解锁；重复回调/金额不符/伪造回调被拒 | 后端/测试 |
| 7 | 发票 | 个人电子普票可申请并收到 PDF；企业专票可提交资料并人工开具；退款可红冲（流程跑通） | 运营/财务 |
| 8 | 价格页 | 首页价格区块 + `/pricing` + 控制台入口文案/价格一致；移动端可用；无 CDN/外链脚本；文案合规（不承诺合规、不虚构原价）；**本地页标「参考价，以官网为准」，不显示倒计时/剩余量** | 前端/测试 |
| 9 | 回归 | 现有样例/红线门禁不受影响（测试环境使用测试授权）；`docs/red-lines.md` 全绿 | 测试 |
| 10 | 安全 | 私钥不在仓库/安装包/CI 日志；支付回调验签；后台 2FA；订单不可枚举；DB 备份可用 | 安全/后端 |
| 11 | 规则包零静默 | 无权/非法 pack 一律 `400 pack_requires_paid`，禁止静默过滤；`compiled` 为空或条数低于阈值 → job=`error` +「规则包未生效」，绝不导出零规则成品 | 后端/测试 |
| 12 | 打包与断网 | 安装包含 `public_key.pem`、`pricing.html`、`license.html`；断网可导入授权；新增代码无网络调用（红线门禁 + `/api/health` 仍报 `net: blocked`）；购买跳转只允许前端链接/`webbrowser.open` | 打包/测试 |

## 7 与其他会话的协作边界（重要）

其他会话正在改 `app/server/yinzhan/` 与 `app/web/` 的新功能。本线实施时必须遵守：

1. **先新增、后挂钩**：优先新增独立文件（`yinzhan/licensing/*`、`web/pricing.html`、`web/pricing.css`、`commercial/site/*`），对现有文件只做**薄 hook**（路由注册、`create_job` 一行门禁、`app.js` 授权状态条、导航一个链接）。
2. **热点文件排队**：`api.py`、`jobs.py`、`app/web/app.js`、`app/web/style.css`（控制台）、`app/web/site.css`（官网/首页）正被其他会话修改 → 等对方合并、工作区稳定后再动；改动前先 `git status`/`git diff` 确认，避免覆盖。
3. **不改契约**：授权模块只读 `Document/fmt/pages` 等现有字段；不改 `pipeline`/`parsers`/`detectors`/`replacers`；新增依赖必须离线 wheel、许可证安全（与 `docs/red-lines.md` 一致）。
4. **测试兼容**：现有 e2e/回归需要全功能 → 测试环境注入**测试授权**（测试密钥对、仅源码模式信任），不得在生产包留 bypass 开关。
5. **每包独立可回滚**：不设运行时 bypass 环境变量（会被用户利用）；回滚靠版本回退。免费限额只影响新版本，老版本不受影响。测试环境用测试授权文件（仅源码模式信任）解决「现有 e2e 需要全功能」的问题。

## 8 决策点（需用户/市场侧拍板）

| # | 问题 | 选项 | 建议 | 影响 |
|---|---|---|---|---|
| D1 | 公司是否已有微信支付商户号 / 支付宝企业账号 / 开票资质？ | 已有 / 新申请 / 先用过渡方案 | 立即核查；没有就 M0 当天申请；过渡期用对公转账+人工发授权 | 决定 M3 能否按时收款 |
| D2 | 试用期长度 | 7 天 / 14 天 / 30 天 | **14 天**（够跑 2–3 份真实文件，不拖太久） | 转化率/客服量 |
| D3 | 免费版是否开放全部行业规则包 | 仅通用 / 全部 | **仅通用**（全功能靠 14 天试用体验） | 免费版价值感 vs 付费理由 |
| D4 | 老用户/内测用户是否赠送授权 | 不送 / 送 1 年个人版 / 送终身 | **送 1 年个人版**（早期口碑与案例） | 首批口碑、收入 |
| D5 | 早鸟价与正式价上线时间 | 先早鸟后正式 / 直接正式 | 按 09 报告：早鸟 ¥99/¥299，正式 ¥199/¥499；时间等市场验证 | 收入与价格锚 |
| D6 | 首发平台 | Windows / Windows+macOS | **Windows 先发**（macOS 需签名+公证，放 P1） | 交付范围 |
| D7 | 发票首发能力 | 仅电子普票 / 普票+专票 | **普票自动/半自动 + 专票人工** | 团队/机构成交 |
| D8 | 是否上买断 SKU | 上 / 不上 | **上**（¥499/¥999，只官网直售） | 转化「反订阅」人群 |

## 9 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 商户号/开票资质审批慢 | M3 无法收款 | M0 立即申请；准备过渡方案（对公转账 + 人工签发 + 收据/后补发票） |
| 热点文件冲突（api.py/app.js） | 合并冲突、功能回退 | 先新增文件；等对方合并后挂薄 hook；每步跑红线回归 |
| 测试基线被免费限额打破 | CI 全红 | 测试环境注入测试授权；生产包不认测试密钥 |
| 私钥泄露/误提交 | 授权可被伪造 | 私钥只在授权服务器；`.gitignore` 拒绝 `*.key`；CI secret scanning；密钥轮换预案 |
| 破解/试用重置 | 收入流失 10–30% | 低价降低动机；本地冗余+时钟检测；更新与服务作为持续价值；不联网校验（守红线） |
| 价格页转化未验证 | 上线后改价成本高 | 早鸟限量；价格页 A/B；上线前用 09 报告验证计划先拿转化数据 |
| 授权把老用户挡在门外 | 口碑风险 | 老用户/内测赠送（D4）；免费版永久可用；授权导入失败有兜底客服流程 |
| 支付服务被攻击/订单伪造 | 资金与授权损失 | 回调验签、金额核对、幂等、后台 2FA、限流、对账；不存卡信息 |
