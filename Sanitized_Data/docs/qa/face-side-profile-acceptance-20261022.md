## 1. 改动（无模型）

| 改动 | 说明 |
|---|---|
| 照片场景侧脸常开 | `fmt=image/tiff` 且非白底文档页时，即使已有正脸命中，也补跑侧脸级联（含镜像）；PDF 扫描页维持“正脸 0 命中才跑侧脸”，避免逐页变慢 |
| 照片高分辨率补检 | 图片/正射预览额外跑 1200 长边的 `frontalface_alt2` + `profileface`（正常/镜像）；候选需肤色比例 ≥0.30、长宽比 0.55–2.25、尺寸合理；**PDF/内嵌图不启用** |
| 开关 | `YINZHAN_SCAN_FACE_PHOTO=1`（默认开）、`..._PHOTO_MAX_SIDE=1200`、`..._PHOTO_MIN_SKIN=0.30`；设 0 可完全回到 P0 行为 |
| 不改变 | 原有 640 分块、整头外扩、置信度、去重、告警文案不变；假级联注入测试模式自动跳过补检 |

代码：`app/server/yinzhan/visual_targets.py`（`_photo_face_pass` / `_face_skin_ratio` /
`_detect_faces`）；测试：`app/tests/test_visual.py`（**65/65 通过**，新增 4 项）。

|---|---|---|---|---|---|

| A2 | 室内大人+小孩合影 | 2 | **1/2**（仅小孩） | **2/2** | alt2 1200 补检检出低头大人 |

## 4. 导出链路实测

对 A1 走真实 HTTP：上传 → 解析 → detect → 导出 human（涂黑）→ 读取成品：

- FACE 实体 **6 个**（其中强侧脸 1 个 conf=0.768）；其余 5 个为背景正脸。
- 成品中 6 个 FACE 框内像素 **平均亮度 10.7、最大 ≤42**（纯黑），human 导出已落盘；
- 人工查看 `export_after_97.jpg`：大人脸部被遮，背景人脸被遮；同时仍可见 P0 的
  墙面/座椅小误报黑块（本轮未清理，属既有问题）。
- 本机 UI 截图：`out/_lead/ui/face_after2_97.png`（涂黑预览，接口返回 6 个 FACE 实体）。
  本轮同时补齐 `ImageParser.export_black_rects()`：图片任务的「涂黑」预览此前没有
  预览=成品钩子（UI `.box` 为 0），补后 UI 显示 **11 个黑框（11 black）**，与导出
  成品黑区一致；该钩子与 PDF 版本同口径复用导出几何，不涉及 AI/human 判定变化。

## 6. 结论与遗留

1. **无模型工程增强有效但有限**：主脸召回 4/13→8/13；合影中正脸+侧脸、观众席侧脸、
   低头大人等漏检已修复；既有正脸（B1）无回退，图像/回归/全套门禁全绿。
2. **90° 强侧脸/躺卧闭眼/遮挡仍漏**（A3、A5），加背景小脸仍不可靠；本轮不能承诺
   “侧脸全检出”。这属于 Haar 模型上限，不是工程参数能完全解决。
3. **建议下一步**：使用商用许可明确的小模型（如 YuNet 需法务确认 WIDER FACE 训练数据许可，
   或等效模型）替换/补充 Haar；预计 A3/A5 可从 0/4 提升到 3–4/4（参考模型实测），
   但需新增约 230KB 模型与打包/许可评估。
4. 现有额外误报（墙面/座椅/卡通脸）主要来自 P0 基础检测；若继续清理需增加
   “人脸结构验证”，会进一步增加耗时，建议与模型升级一起做。
