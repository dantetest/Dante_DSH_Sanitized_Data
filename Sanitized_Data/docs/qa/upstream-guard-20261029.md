## 1. 结论

- 已落地：映射一致性护栏（默认 warn，可 block）、实体质量闸门（默认 enforce，
  可 shadow/off 回退）、归并收敛（类别兼容 + 行政区 core + 链式复核 + 簇上限）。
- 实测效果：D07 的 **5 个脏实体**、D08 的 **2 个句子片段机构**被精确剔除，
  合法实体 0 丢失；4 份 E2E 文档还原**残留假值 0、原值命中 100%**；
  AI 视图**原值残留 0**；回归 250 项硬检查全绿。
- 未做（下一轮）：伪值一致性（P1-1：身份证生日/性别、固话区号、USCC 地区码）、
  PDF 阅读顺序（P1-2）。这两项是当前 E2E 中仍可见的问题。
- 归并过合并的修复已由单测/历史映射扫描验证；**真实判决书源文件不在工作区**，
  未能对那份文件重跑脱敏，因此其现网效果需拿到源文件后再回归一次。

## 2. 代码改动

| 文件 | 改动 |
|---|---|
| `app/server/yinzhan/quality.py`（新增） | 实体质量分类（PERSON/ORG 高精度垃圾）、shadow/enforce、映射一致性检查（同假值跨类别/超大簇）、只含计数/掩码的报告与 warning |
| `app/server/yinzhan/pipeline.py` | ORG 归并收紧：类别兼容、纯行政区 core 拒绝、OCR/句子噪声前缀剥离、ORG 簇内 canonical 复核、ORG≤4/ADDRESS≤5 上限；`review_groups` 计数 |
| `app/server/yinzhan/jobs.py` | decide 前质量闸门、任务完成/导出前映射检查；导出记录/snapshot/审计/vault meta 带护栏结果；`YINZHAN_MAPPING_GUARD=block` 时阻断 AI 导出 |
| `app/server/yinzhan/restore.py` | 还原时重新检查映射（旧 job 也生效），报告提示跨类别归并/超大簇 |
| `app/tests/test_upstream_guard.py`（新增） | 42 项：分类、shadow/enforce 保护、默认开关、映射检查、block 导出阻断、归并类别/行政区/上限 |
| `app/tests/run_all.py` | 注册 `upstreamguard` |

开关（均可运行期回退，默认值已按安全优先设置）：

```
YINZHAN_ENTITY_QUALITY=off|shadow|enforce   # 默认 enforce
YINZHAN_MAPPING_GUARD=off|warn|block        # 默认 warn；block 只阻断 AI 导出
```

安全语义：
- 质量闸门只处理 PERSON/ORG；身份证/账号/银行/密码等隐私关键类型永不自动丢；
- 只丢“几乎不可能出现在真实实体”的高精度类别（印章词/动作词/句子片段/含“的”
  的机构串），数字/英文开头、无机构后缀只进入 review，不自动丢；
- 报告/warning/审计只写类型、数量、原因、掩码假值，不写原值或完整假值。

## 6. 仍存在的问题（下一轮）

1. **P1-1 伪值一致性未做**：D12 假身份证仍是随机生日/性别（AI 回件自己也指出
   “年龄 67 与身份证 1995 年不自洽”）；固话区号、USCC 地区码也未保留。
   还原后 ID 会换回真值，但 AI 在回件里写下的“推导/备注”仍是基于假值的，需人工复核。
2. **D12 同一住院号生成两个假值**：原文有两个写法（`住院号：…` 与 `住院号 …`），
   被当成两个实体，AI 视图出现 `WR…` / `HT…` 两个住院号，自相矛盾。
   建议 P1 一致性阶段按“标签+核心值”归一后再生成。
3. **P1-2 PDF 阅读顺序未做**：D01 仍依赖 AI 工具按 bbox 读，纯文本流顺序与视觉顺序
   不一致（方案 §4.4 阶段 1/2 未实施）。
4. **D08 测试集标注错误**：文件是委托代理协议，不是判决书；后续 E2E 应改任务名
   或换真实判决书，否则指标不可比。
5. **过合并修复未在真实判决书源文件上回归**：源文件不在工作区，需补测。
6. D07 合法地址变体还原仍会提示“同假值多原值”，属预期；如要逐处区分，
   需要 P1-C 候选落盘/上下文消歧。
