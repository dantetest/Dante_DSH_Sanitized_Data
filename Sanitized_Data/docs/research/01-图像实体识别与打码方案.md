## 0 结论摘要

### 0.1 五类目标：当前产品到底能不能识别并涂黑

| 目标 | 能否自动识别 | 能否涂黑 | 当前实际能力（依据见 §1、§附录A） | 结论 |
|---|---|---|---|---|
| **人脸** | ❌ **不能** | ❌ 不能（没有框可涂） | 图片/TIFF 解析器只做 OCR→文本规则；视觉标记 `visual.py` 只接在 PDF 解析器里，且只找红章/手写签名。纯人脸照片实测 0 个 OCR 行、0 个实体 | **不能** |
| **车牌** | ⚠️ **部分** | ⚠️ 部分 | 只有"OCR 恰好把车牌文字读对 + `cn.plate` 正则命中"这一条路。合成蓝牌/绿牌（8 位新能源）能命中；OCR 插入 `·`/空格、小写、全角时全部漏；7 字符警车号牌（省+字母+4位数字+警）正则漏；自带俄车牌级联对中国牌不可用 | **部分（依赖 OCR 文字）** |
| **路牌** | ❌ **不能** | ❌ 不能 | OCR 能把"中山北路"读得 100% 正确，但没有任何规则/检测器消费它；"中山东一路"还会被 OCR 切成 3 行。实测全部 0 实体 | **不能** |
| **门牌（门址）** | ⚠️ **部分** | ⚠️ 部分（且会漏关键数字） | 带"市/区"的完整地址、且一行写完：能（实测 100% 覆盖）；只有"XX路XX号"没有行政区：不能（0 实体）；地址被 OCR 分成两行：只涂路名行，**门牌号"123号3栋502室"原样泄漏** | **部分（风险高）** |
| **证件**（身份证/护照/驾驶证/营业执照/银行卡/社保卡…） | ⚠️ **部分，且高危** | ⚠️ 只能涂"号码文本"，涂不掉照片/二维码/印章/MRZ | 身份证号、统一社会信用代码、银行卡号等**号码**可被规则命中；姓名、照片、二维码、有效期、签发机关、MRZ 基本识别不到；实测字符覆盖率：身份证 49%、营业执照 52%、驾驶证 25%（且证号被误判成银行卡号）、护照 0%、银行卡 0% | **部分（不能只涂号码）** |

**一句话**：当前产品对"照片里的东西"**没有图像级检测能力**，能命中的只有 OCR 读出来的文字；人脸、路牌是 0 覆盖，车牌/门牌/证件是"文字可读时的条件覆盖"。用户直接问的五类，按"自动识别并可靠涂黑"的标准，**5 类里 0 类全支持、3 类部分、2 类不支持**。

### 0.2 最大缺口（三条，按危害排序）

1. **证件照只涂号码 = 假脱敏**：证件上最要命的照片、二维码、印章、MRZ 都不是文本，规则永远看不到；实测证件照片里的二维码可被 `cv2.QRCodeDetector` 离线解码还原出"身份证号|姓名|住址"（§3.5）。
2. **没有"视觉检测"这一层**：`image_parser`/`tiff_parser` 完全不调用 `visual.py`；`pipeline.detect` 会直接丢弃 `value` 为空的实体；即便修好这一处，`_merge` 又会把同 `(etype,value)` 的多个空值框合并成一个——即使检出了人脸，现有管线也会把它丢掉/合并。
3. **出口自检对视觉残留是盲的**：`pipeline.verify` 只查"原文文字是否还在 + 元数据"，不重跑检测器。人脸/车牌/证件涂没涂上，它都报"残留 0、通过"。

## 1 现状核对（file:line 证据）

### 1.1 图片类解析器：只有 OCR 文本块，没有图像目标

`app/server/yinzhan/parsers/image_parser.py`

- 文件头注释直接写明定位：`解析：PIL 读取像素尺寸，OCR 识别行作为 UDM block（ref 里存像素矩形）`（`image_parser.py:1-4`）。
- 解析流程 = PIL 打开 → 页面尺寸=像素尺寸 → `_ocr_blocks()`（`image_parser.py:409-431`）。**没有任何 cv2 级联/检测模型调用**；全文件只有 OCR 一条图像处理路径。
- OCR 前把最长边缩到 `OCR_MAX_EDGE = 2400`（`image_parser.py:28`），识别框再按 `1/scale` 换算回原图像素（`image_parser.py:142-143`）——这是新检测器必须复刻的坐标约定。
- 多帧图片（GIF/WebP/TIFF 中间件）只处理第 1 帧并告警（`image_parser.py:425-426`、`:445-446`）。
- 导出：按实体 `Span.rect` 画实心矩形（`image_parser.py:301-308`、`:267-314`），`black` 直接填墨色 `INK`（`image_parser.py:218-228`），重编码剥离 EXIF/XMP（`image_parser.py:319-357`）。**矩形坐标涂黑能力现成可用**。

`app/server/yinzhan/parsers/tiff_parser.py`：逐帧 OCR（`:132-142`），`page.ref={"frame": index}`（`:140`），复用 `image_parser` 的 `_ocr_blocks/_apply_decisions`（`:17-19`）。同样**没有任何视觉目标检测**。

### 1.2 已有的"视觉标记"：只服务合同红章/签名，而且只接在 PDF

`app/server/yinzhan/visual.py` 的定位（`visual.py:1-14`）：

- 红章：`redness = R-(G+B)/2` + 16×16 块聚合 + 尺寸过滤（`visual.py:27-124`），注释给了经验阈值（真实红章 p99>25、像素占比 2%~20%）。
- 手写签名：抠掉 OCR 文字框后找墨迹团块（`visual.py:132-172`），一律交上层标待确认。
- 页级入口 `analyze_page()`（`visual.py:177-196`）只返回 `seal/signature` 两类。

**接入情况（关键事实）**：

| 解析器 | 是否调用 `visual.analyze_page` | 证据 |
|---|---|---|
| PDF | ✅ 每页 150dpi 渲染后调用 | `pdf_parser.py:202-229`（`VISUAL_DPI=150` 在 `:26`，`get_pixmap(dpi=VISUAL_DPI)` 在 `:213`，`analyze_page` 在 `:222`），每页解析后调用在 `:553-554` |
| 图片（jpg/png/webp…） | ❌ 从未调用 | `image_parser.py` 全文无 `visual` import / `analyze_page` 调用（grep 全仓仅 `pdf_parser.py:222` 一处调用） |
| TIFF | ❌ 从未调用 | `tiff_parser.py` 全文无 `visual` |

结论：**"照片/扫描图里有红章"这件事，图片文件根本不会检测**；PDF 里会，但只找合同印章/签名，不找人脸/车牌/证件。

### 1.3 检测器与规则：现有 3 个文本检测器，没有图像检测器

- 契约：`Detector.from_spec/detect`，`detect` 是自由 dict（`CONTRACT.md:152-166`；`registry.py:47-57`、`:78-82`）。
- 实际注册的检测器（`registry.py:103-108` 静态兜底清单）：`regex_det`、`dict_det`、`ner_det` 三个，全部只读 `block.text`（`registry.iter_text_blocks`，`registry.py:157-161`）。
- `DESIGN.md:190-212` 列了 6 类检测器（含 `OcrDetector`、`ModelDetector`、`GeoDetector`、`MeshDetector`）——是规划稿，与当前实现不符，**不能当作现状依据**。
- 与五类目标相关的现有规则：
  - `cn.plate` 车牌号：`regex`，scope 含 `image/tiff`（`rules/common.yaml:89-98`）；
  - `cn.idcard` 身份证号：18 位 + GB 11643 校验位（`rules/common.yaml:32-42`，校验实现 `detectors/regex_det.py:59-83`）；
  - `cn.bankcard` 银行卡：Luhn 校验（`rules/common.yaml:44-54`，`regex_det.py:91-109`）；
  - `cn.uscc` 统一社会信用代码：`rules/common.yaml:100-109`；
  - `cn.address` 地址、`cn.person` 人名、`cn.org` 机构：都是**启发式 NER**（`rules/common.yaml:135-166`，实现 `detectors/ner_det.py:730-894`）；
  - 地址启发式要求"行政区划链"打头（`ner_det.py:359-373`、`:560-597`），所以"XX路XX号"这种门牌写法天然不匹配（§1.7 实测）；
  - 人名启发式要求"名"字落在 800 字常用名字表里（`ner_det.py:70-84`），"张三/李四/王五/赵六"这类名字实测漏（§1.7）。
- **没有任何**证件类型（document-type）判定、MRZ 解析、车牌/路牌/门牌专用规则；也没有视觉类规则。

### 1.4 决策与导出：矩形 span 通路是通的

- `Span(rect=..., page=...)` 模型（`udm.py:117-140`；契约 `CONTRACT.md:75-80`）支持图像矩形。
- `jobs.mark()` 把前端归一化框换算成页面坐标并落 `Span(rect, page)`（`jobs.py:308-318`），`decision=black`（`jobs.py:332`）。
- 管线 `decide()` 为实体算替换策略，`black` 走涂黑（`pipeline.py:180-223`；`replacers/black.py`）。
- 导出侧：图片 `_apply_decisions` 处理 rect span（`image_parser.py:301-308`）；PDF 把 rect span 换算成 redaction 注释（`pdf_parser.py:389-398`、`:597-611`），真正删内容流而不是盖黑框（README.md:195、DESIGN.md:238-258）。
- **但**：`pipeline.detect()` 在收结果时直接 `if not e.value: continue`（`pipeline.py:78-80`）——人脸/证件这类没有文字值的视觉实体**生下来就会被丢掉**；`_merge()` 以 `(etype, value)` 为 key（`pipeline.py:108-146`），空值会把多张人脸合并成一个实体。这两处是集成时必须改的最小点（§4.3）。
- 现有视觉实体是**绕过 detect 直接 append** 的：`jobs._run()` 里 `SIG_BLOCK`/`_visual_entities()`（`jobs.py:232-250`、`:548-569`），类型映射 `_VISUAL_SPEC`（`jobs.py:506-509`）——证明"rect 实体 → 涂黑导出"链路已经在生产环境跑通（红章 19/19 检出，README.md:176）。

### 1.5 出口自检：只查文字残留与元数据，不重跑检测器

`pipeline.verify()`（`pipeline.py:511-552`）实际做两件事：

1. 重新解析成品，把每个实体 `value` 当 `needle` 在全文里 `in` 匹配（`pipeline.py:524-531`）——`value=""` 的视觉实体直接被 `if ... or not e.value: continue` 跳过；
2. 检查元数据黑名单（`:536-547`）。

**与契约不一致**：`CONTRACT.md:222-228` 要求"用全部检测器重跑成品，residual 必须为 0"，实现里并没有重跑检测器，只查文本。对图像涂黑而言：黑框区域 OCR 读不出字 → 文本残留恒为 0 → **即使人脸/车牌/证件完好无损，自检也会通过**（§4.8 修）。

### 1.8 现状小结（逐条）

1. 图片文件 = OCR 文本 → 规则匹配，**没有图像目标检测**；
2. PDF 有视觉标记，但只有红章/手写签名，且只针对合同落款场景；人物照片/车牌照片里这些启发式也不适用；
3. 人物照片、车牌照片、路牌照片、门牌照、证件照，目前**只能靠 OCR 读出的文字撞规则**，读不出/读错/被 OCR 分行就漏；
4. 证件场景下"漏"不是少涂一条号码，而是照片/二维码/印章/MRZ 完全裸奔；
5. 现有管线具备 rect 涂黑/框选补漏/破坏性导出能力，**缺的是"发现框"和"出口复检"两层**。

## 2 需求与目标

### 2.1 目标

给照片（JPG/PNG/BMP/WEBP）、扫描件（TIFF 多帧、PDF 扫描页）增加**离线、CPU 可跑、模型随包**的图像目标检测，输出 `Entity + Span(rect, page)`，默认涂黑并纳入出口复检。验收口径：检出即涂黑、导出后复检残留为 0。

**非目标**（本轮明确不做）：

- 不做人脸识别/比对/身份归属，不输出 embedding、不识别"是谁"；
- 不做车牌识别入库、不做证件真伪鉴别、不做 OCR 内容语义理解；
- 不引入联网模型、不引入新运行时依赖（ONNX 模型是数据文件，不算依赖）；
- 不改现有涂黑/换名语义（视觉目标默认涂黑；不生成假人脸/假车牌）。

### 2.2 口径

| 结论 | 定义 |
|---|---|
| **能** | 无需人工即可检出并默认涂黑，且导出后复检通过 |
| **部分** | 某条件下能（文字可读 / 单行地址 / 正面照），其余条件会漏 |
| **不能** | 现有代码没有任何路径能产生对应矩形 |

### 2.3 法规口径（引用，不替代法务）

### 3.1 人脸

**方案 A（P0，推荐）：OpenCV Haar 正脸级联**

- 模型：`haarcascade_frontalface_default.xml`（首选）+ `haarcascade_frontalface_alt2.xml`（备选合并）→ 两套结果 NMS/并集去重。
- 参数（初值）：`scaleFactor=1.1`、`minNeighbors=5`、`minSize=32×32`；`equalizeHist` 提高逆光召回；灰度、多尺度。
- 涂黑范围：**检测框外扩 12%**（覆盖发际/下巴；比"只涂框内"更安全），不整张照片黑。多人（>8 张脸，如合影/人群）→ 整图涂黑并标 pending。
- 误报/漏报预算（自建集验收，P0）：正脸 ≥48px 召回 ≥90%；侧脸 ≥60%；非人脸照片误报 ≤1 个/20 张；单页 ≤2400px 耗 ≤250ms；体积新增 0。
- 依据（实测）：合成尺度梯度 5/6 召回（漏 40px 小脸）；退化条件召回 blur 4/6、JPEG 4/6、低光 5/6、噪声 4/6、旋转 7° 3/6、旋转 20° 1/6（`exp2.log`）→ **侧脸/大角度靠 Haar 不够，属 P1/P2**。

**方案 B（P1/P2）：YuNet 2023mar（ONNX，227KB，MIT）**

- `cv2.FaceDetectorYN.create(model, "", (w,h), 0.6, 0.3, 5000)`，返回框+5 关键点+分数；2023mar 是固定输入形状模型，OpenCV 4.x 按输入尺寸推理；模型卡称可检测 **10×10～300×300 像素**的人脸；WIDER Face AP：easy 0.8844 / medium 0.8656 / hard 0.7503。
- 用法：先把长边缩到 ~640/960 跑一遍（30–55ms），小脸场景再按 2×2 分块跑一遍；坐标按缩放比回算。
- 依赖：OpenCV DNN 自带 ONNX 导入，**无需 onnxruntime**（虽然包内本来就有）；新增只有 232,589 B 模型文件 + MIT LICENSE 文件。
- 实测：320² 5.8ms、640² 30.1ms、2400² 486.9ms；合成尺度梯度 target=1280 召回 4/6；退化条件比 Haar 略好（rotate7 4/6、dark 5/6）。
- 结论：**P1 再加，P0 先用 Haar**；若用户要求"侧脸/多人合影"指标，则 P0 后置换 YuNet（决策点 D3）。

**默认全脸涂黑 vs 只涂识别到的**：产品语义上"全脸涂黑"指"检测框+外扩整体涂黑"，不是"整张照片黑"；唯一整图黑场景是证件命中/超多人合影（见 §4.6）。

### 3.2 车牌

**能不能用现成级联？不能。** `cv2.data` 自带的是 `haarcascade_russian_plate_number.xml`、`haarcascade_license_plate_rus_16stages.xml`（俄车牌制式），实测在中国蓝牌/黄牌上 0 检出、合成绿牌图 2 个误报（`exp4.log`）；且中国号牌颜色/尺寸（GA 36-2018：蓝牌、黄牌、新能源 8 位号牌等）与俄牌差异大，直接套用没有意义。**当前也没有任何中国车牌检测模型随包。**

**方案（P0）：OCR 文本命中 + OCR 行框扩边**

- 复用现有 OCR 行（无额外 OCR 成本）：命中 `cn.plate` 的行 → `rect = OCR 行 bbox` 外扩 6%（行框就是车牌区域时足够）；同一车牌多行（竖排/两行）按 IoU 合并。
- 先修正正则鲁棒性（实测 `exp3.log`）：
  - `沪A12345` ✅、`粤BD12345` ✅（8 位新能源）、`沪AD12345` ✅、`京C88888` ✅；
  - `沪A·12345` ❌、`沪A 12345` ❌、`沪a12345` ❌、`沪Ａ12345` ❌——OCR 极常见；需预处理（去 `· . -` 空格、`I→1/O→0`、大小写归一、全角 NFKC 后仍保留 `·`，要显式清洗）；
  - `沪A1234挂` ❌、`苏E1234学` ❌——这两条是我按 7 字符构造的测试串；**挂/学号牌的真实式样要以 GA 36-2018 核对后再补正则分支与测试用例**；
  - `京A0001警`、`川AA001警` 这类警车号牌：GA 36-2018 式样为「省+字母+4位数字+警」（7 字符）或「省+字母+1字母+3位数字+警」（8 字符，现有分支可覆盖后者），**7 字符那类会被漏**；
  - `沪A12345（临）` ✅（前缀匹配）。
- **漏读兜底（P0 可选）**：颜色分割出候选框（蓝/绿/黄），对候选框裁剪后 **二次 OCR**；二次结果仍命中 `cn.plate` 才涂黑。
  - 实测：1600px 图 23–37ms；蓝底蓝牌、蓝底路牌都会出候选 → **必须 OCR 复核，否则误报**；
  - 注意颜色极性：蓝/绿牌是白字，黄牌是黑字——白字比例过滤不能通用于黄牌（实测合成黄牌因黑字被过滤漏掉）。
- 误报/漏报预算（P0）：OCR 可读车牌召回 ≥95%（合成/清晰），全场景（角度/夜间/脏污）≥60–75%；误报 ≤2%（主要靠正则+校验，颜色候选只在复核命中时生效）；额外耗时 ≤50ms/图。体积 0。许可证：自有代码 + 现有 OCR（Apache-2.0）。
- **P2 路线**：小型车牌检测模型（CPU 30–100ms），训练数据可用 **CCPD（MIT，含 CCPD-Green 8 位新能源子集）**；模型结构自选（如 MobileNet-SSD/轻量 YOLO 变体），**避免 AGPL 的 Ultralytics YOLO 默认许可证**（闭源分发需另行购买商业授权）。检测到框后再 OCR 识别，形成"检测框 + 识别文本"双保险。

### 3.3 路牌

**方案（P1，纯规则 + 版式启发式，零模型）**

- OCR 已能读出大字路牌（实测 `中山北路` score 1.0）；问题是没有规则消费它，且大型路牌可能被 OCR 切成多行（`中山东一路` → 3 行）。
- 规则：`[\u4e00-\u9fa5]{2,10}(?:路|街|大道|大街|巷|弄|道|公路|高速|桥|立交|环岛)` 作为 **ROAD_SIGN** 候选；配合"大字 + 高频白字/蓝绿底"的版式特征（OCR 行高度占比、区域色块）给 confidence。
- 涂黑范围：不只涂文字行，而是**整块标志区域**（色块连通域外扩），避免只涂半截字；这样即使 OCR 漏字，只要块被命中也不会残留。
- 误报/漏报预算：清晰近景（文字高 ≥40px）召回 ≥80%；普通照片误报 ≤5%；耗时 ≈ OCR + <10ms；体积 0。弱点：远景/斜视/遮挡/光照弱时 OCR 读不出 → 漏，属 P2（可加矩形色块检测 + 透视矫正后再 OCR）。
- 依据：实测 `中山北路` 0 实体、`中山东一路` OCR 分 3 行 0 实体；合同正文里出现"XX路"通常本来就是地址信息，规则命中导致涂黑可接受（用户可 reject）。

### 3.4 门牌（门址）

分三种情况，**P0 只保证第 1 种，P1 补齐 2/3**：

| 情况 | 现状 | 方案 |
|---|---|---|
| ① 单行完整地址（含市/区+路+号） | ✅ 已能（实测 100%） | 沿用 `cn.address`，rect 即 OCR 行 bbox |
| ② 无行政区门牌（只有"XX路XX号/XX弄XX号/XX路XX号XX室"） | ❌ 0 实体 | 新增 `cn.door_address` 正则/启发式：`[\u4e00-\u9fa5]{1,12}(?:路|街|大道|巷|弄|胡同|里)[0-9]{1,5}(?:号|弄)(?:...室|栋|楼|单元)?`，命中后整行涂黑；误报预算 ≤3% |
| ③ 地址被 OCR 拆成多行（路名一行、号码一行） | ⚠️ 只涂路名，号码泄漏 | 行合并启发式：相邻 OCR 行（纵向间距 <1.5 倍行高、横向重叠 >50%、下一行以数字/号/室/栋/楼/单元开头）→ 合并成 DOOR_ADDRESS，rect 取两行并集；实测样例行 10 跨行合并后可从 50%→100% |

- 涂黑范围：整行/整门牌区域（若识别到门牌底色块，外扩色块）。
- 误报/漏报预算：单行 ≥90%、跨行 ≥80%、无行政区 ≥85%（自建集）；误报 ≤3%；耗时 ≈ OCR + <5ms；体积 0。
- 注意：`cn.address` 的 NER 也会把"本合同签订于上海市…"整段吞进地址值（实测），跨行合并时要限制只并入"像门牌"的短行，避免把正文整段涂黑。

### 3.5 证件（身份证 / 护照 / 驾驶证 / 营业执照 / 银行卡 / 社保卡 …）

**核心原则：证件命中后涂整卡/整页，绝不只涂号码。**

理由（实测 + 机制）：

1. 号码之外的字段规则基本覆盖不到：身份证字符覆盖率 49%（姓名、性别、民族、出生全漏）、护照 0%、驾驶证 25%、银行卡 0%（`exp3.log`）；
2. 证件上的照片、二维码、印章、MRZ、全息标都不是 OCR 文本；实测把二维码放进证件照片后，`cv2.QRCodeDetector.detectAndDecode` 能**离线解码出 `11010519491231002X|张三|北京市朝阳区建国路88号` 共 34 字节**——只涂号码等于没脱敏（`exp4.log`）；
3. 人脸检测单独跑会漏小尺寸证件照；"整卡黑"一次覆盖所有字段，逻辑最简单、残留风险最低。

**检测方法（P0，纯 OCR 文本锚点，零额外耗时）**

- 证件类型锚点表（用 OCR 行做子串匹配，大小写/全半角归一后）：

| 证件类型 | 强锚点（1 个即可） | 弱锚点（≥2 个） | 号码形状 |
|---|---|---|---|
| 居民身份证 | 中华人民共和国居民身份证、公民身份号码 | 签发机关、有效期限、住址、出生 | 18 位 GB 11643 |
| 护照 | 中华人民共和国护照、护照号码 | P<CHN（MRZ）、出生日期、签发日期 | E+8 位 / MRZ |
| 驾驶证 | 机动车驾驶证、准驾车型 | 证号、有效期限、初次领证日期 | 18 位（与身份证同形） |
| 营业执照 | 营业执照、（副本） | 统一社会信用代码、注册资本、法定代表人、经营范围 | 18 位 USCC |
| 银行卡 | （卡面银行名+卡号） | 有效期、CVV、卡组织标志 | 16–19 位 Luhn |
| 社保卡/医保卡 | 社会保障卡、医保卡 | 社会保障号码、卡号 | 18 位（身份证号） |

  命中规则：≥1 强锚点，或 ≥2 弱锚点，或 1 弱锚点+号码形状 → `ID_DOCUMENT`，confidence 按锚点强度给。
- 区域：所有命中 OCR 块 bbox 的并集 + 外扩 4%；若并集面积 ≥ 单页面积 25%，或图片只有证件（无其它文字块）→ **整页/整图涂黑**。
- 误报控制：正文里出现"营业执照复印件"这类句子只有 1 个弱锚点且无号码形状 → 不触发；若只有 1 弱锚点 → 只涂锚点所在区域并标 pending。
- 误报/漏报预算：6 类证件（清晰扫描/翻拍）锚点召回 ≥95%；整卡覆盖率 100%（涂黑后复检 0）；反例误整页 ≤1%；额外 OCR 成本 0；体积 0。
- P1 扩展：社保卡/医保卡/居住证/港澳通行证/军官证锚点补齐；**护照 MRZ**（P2）：对页面下半部裁剪 → 放大 → 二次 OCR → 按 ICAO 9303 校验位验证，提升护照召回。

### 4.2 新增 `VisualDetector`（建议 `detectors/visual_det.py` + `detectors/visual_utils.py`）

```python
class VisualDetector(Detector):
    id = "visual"

    @classmethod
    def from_spec(cls, spec: dict) -> "VisualDetector":
        # spec: {"type": "visual", "kinds": ["face", ...], "min_conf": 0.6, "max_edge": 1600}
        ...

    def detect(self, doc, rule, ctx) -> list[Entity]:
        # 1) 只为 scope 命中的 fmt 跑（image/tiff/pdf）
        # 2) 逐页取位图（内存临时，命完即弃；同一 detect 调用内缓存）
        # 3) 按 kinds 跑子检测器；OCR 文本类子检测器直接复用 doc.pages[*].blocks（不再 OCR）
        # 4) 坐标换算回页面坐标；产出 Entity(origin="visual", spans=[Span(rect=..., page=...)])
```

**页位图来源（关键，避免解析器/检测器重复渲染）**：

| fmt | 位图来源 | 坐标换算 | 备注 |
|---|---|---|---|
| image | `PIL.Image.open(doc.path)`（当前页=第 1 帧） | 检测缩放 `s` → 原图像素 `x/s`；`page.width/height` 就是像素 | 沿用 `OCR_MAX_EDGE=2400`、`MAX_RENDER_EDGE=2000` 的约定（`image_parser.py:28-30`） |
| tiff | `PIL.Image.open(doc.path).seek(page.index)` | 同上（每帧独立 `page.width/height`，`tiff_parser.py:138-140`） | 多帧必须逐页 |
| pdf | `fitz` 渲染 150dpi（与 `pdf_parser._collect_visual` 一致，`pdf_parser.py:213`） | `pt = px * 72 / VISUAL_DPI`；`page.rect` 已含旋转，渲染图与 `page.width/height` 同向 | 无图的纯文本页 `page.get_images()` 为空 → 跳过人脸/车牌（省 100–300ms/页）；扫描页必有一张整页图 |

**检测尺度**：长边 cap 1600（人脸 Haar 实测 1600×1000 合成图 55–80ms；2400² 到 300ms）。超过 cap 时记录 `doc.warnings`（"图像较大，已按 1600 长边检测，极小目标可能漏"）。坐标一律 `x/s` 回算，与 `image_parser._ocr_blocks` 的 `1/scale` 完全同构（`image_parser.py:142-143`）。

**子检测器复用**：

| kind | 实现 | 数据来源 | 输出 |
|---|---|---|---|
| face | Haar（P0）/ YuNet（P1） | 页位图 | rect + conf |
| plate | ① OCR 行文本命中 `cn.plate`（复用 `doc.blocks`）；② 颜色候选 + 二次 OCR 复核（可选） | `doc.blocks` + 位图 | rect（OCR 行框外扩）+ OCR 文本 value |
| road_sign | OCR 行文本命中路名模式 + 色块扩展（P1） | `doc.blocks` + 位图 | rect + value |
| door_address | 正则 + 跨行合并（P1） | `doc.blocks` | rect + value |
| id_document | 锚点表 + 并集区域（P0） | `doc.blocks` | rect（整卡/整页）+ 空 value |

**去重与套嵌**：`ID_DOCUMENT` 命中后，落在其区域内的 FACE/PLATE/SEAL 实体合并（保留面积最大的实体，其余丢弃）；人脸框之间 IoU>0.3 做 NMS 合并。

### 4.8 Verify 复检（出口硬门槛）

**问题**：视觉实体 `value=""`，现有文本残留检查（`pipeline.py:524-531`）永远通过；必须改为"在成品上重跑同一视觉检测器"。

**设计**（`pipeline.verify` 内追加，Lead 实现）：

```
对每个 status != rejected 且 origin == visual 的实体：
  在 re_doc（成品重新解析后的 UDM）上，用其 etype 对应的 VisualDetector 重跑该类检测
  若存在新检测框与原 rect 的 IoU ≥ 0.3  → residual += 1
residual > 0 → 抛 VerifyError（沿用现行为：删成品，jobs._export_to 捕获）
返回 verify: {verified: true, residual: 0, checked: N, visual_checked: M}
```

- 成本控制：只对"有视觉实体的页"重跑（按 `span.page` 去重）；图片 1 页 +100–300ms；100 页 PDF 若只有 3 页含视觉实体，只多 ~1s。
- 黑框本身不会骗过检测器：实心黑块上 Haar 检出 0，OCR 读不出字（车牌/证件文本残留在黑块上不会再命中）；PDF 走 `apply_redactions` 内容流真删（`pdf_parser.py:597-611`）。
- **复检只能证明"已检测到的框被涂掉了"，不能证明"没漏检"**——漏检靠测试集指标（§6）与用户在对照台目视 + 框选补漏（已有）兜底；这点要写进产品文案，不能宣称"100% 检出"。
- `jobs._export_to` 的 record 已有 `verify` 字段（`jobs.py:485-494`、`:457-463`），新指标直接带上即可。

## 7 风险与边界

| 风险 | 说明 | 缓解 | 残余风险 |
|---|---|---|---|
| **误报把正文涂掉** | 人脸级联对插画/海报/雕塑误报；证件锚点把"营业执照复印件"误判 → 整页黑 | 置信度分级（accepted/pending）、整页黑强制 pending、UI 提示、可 reject；阈值用自建集调 | 用户不确认直接导出时按"宁可多涂"处理；扫描件正文可能被误涂 |
| **漏报即泄漏** | 侧脸/遮挡/低分辨率/手写门牌/无文字证件/小目标、证件反光 | 测试集指标 + 框选补漏（已有）+ P2 模型/MRZ/矫正；产品文案明确"自动检测不保证 100%" | 漏检在导出后复检里也发现不了（复检只验证已检出目标） |
| **性能** | 大图/多页 PDF 双倍检测成本；12MP 照片 OCR 已 1.7s | 长边 cap、PDF 无图页跳过、只复检有视觉实体的页、进度上报（`jobs.on_progress`） | 低端机（4 核以下）耗时约 1.5–2× |
| **许可证** | 模型/数据许可证是发布合规重点 | 只用 Apache-2.0/MIT：OpenCV(4.5+)、RapidOCR/PaddleOCR、YuNet(MIT)、CCPD(MIT)；随包附 LICENSE/NOTICE；模型哈希固定；**不用 AGPL 的 Ultralytics YOLO 默认许可** | 训练数据（CCPD 含真实车牌）的图像合规需法务确认后再用于产品模型 |
| **隐私** | 检测过程本身接触原始像素；不能新增泄漏面 | 位图只在内存、不落盘、不上传、不记日志内容；审计只记类型数量（`audit` 现有口径）；不提取/保存人脸 embedding | 同机恶意软件/内存抓取（README.md:256-260 已有边界声明） |
| **合规口径** | 人脸/证件 = 敏感个人信息 | 沿用"已隐去 ≠ 匿名化/合规"口径；证件场景提示用户 | 法律定性由用户/法务判断 |
| **坐标错位** | 缩放/旋转/多帧算错 → 涂错位置或涂不到 | 单测覆盖回换算；对照台人工确认；导出后复检只能发现残留、发现不了"涂错位置" | 旋转 PDF/扫描歪斜的极端页 |
| **不可逆** | human 模式黑块无法恢复；AI 模式下视觉目标也黑 | 导出前 UI 明确两种模式差异（README.md:186-195）；视觉目标不生成假值 | 用户误选模式 |
| **功能边界** | 不做人脸识别/车牌入库/证件真伪；不保证所有证件类型、所有角度 | 文档与 UI 明确"检测范围" | 非标证件（军官证、台胞证等）P2 之后再补 |

**明确不承诺**：

1. 不承诺"所有照片里的人脸都能找到"（侧脸/遮挡/极小脸必漏）；
2. 不承诺"证件上的二维码/照片一定被单独识别"——但整卡黑后它们必然被覆盖；
3. 不承诺 PDF 中嵌入图片（非整页扫描）里的小目标可检测（150dpi 渲染后小脸可能 <32px）；P1 可考虑对 `page.get_images()` 的嵌入图单独放大检测。
