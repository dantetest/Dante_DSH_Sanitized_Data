# 08a · PIPL 图像类敏感信息查漏补缺（调研稿）

> **状态**：调研稿 · **未动任何源码/规则/前端/依赖** · 2026-10-20 · 仓库 HEAD `13c89ef`
> **范围**：以《个人信息保护法》（PIPL）敏感个人信息与去标识化要求为纲，逐项核对**图片优先**（JPG/PNG/WEBP/BMP、TIFF 帧、PDF 扫描页/页面内图片元素）的识别与打码现状；只出方案与工作量，不改代码。
> **前提基线**：mediascan 扫描扩展点 + `visual_targets`（face / id_document / plate；road_sign、door_address 占位恒空）+ `barcodes`（QR/1D 默认全打码）+ seal/signature（PDF）+ 解析器接入 + Verify 视觉复检；图片/TIFF/PDF 元数据清理；E2E/回归门禁（167 项）全绿（Lead 2026-10-20 基线）。
> **法律边界（先说清楚）**：本产品只承诺「已隐去 / 去标识化」，**不承诺「匿名化」「合规」**。按 PIPL 第 73 条与 GB/T 37964-2019、GB/T 42460-2023，去标识化数据在不借助额外信息时仍可能被重识别，仍属个人信息；本报告所有"能加"的能力都只提升去标识化强度，不会把产品变成匿名化产品。

| PIA/合规审计 | PIPL 第 55/56 条、GB/T 39335-2020；《个人信息保护合规审计管理办法》（2025） | 产品可提供"处理记录/PIA 摘要"辅助，不能替代用户评估 |

## 3 关键缺口深挖（为什么值得先做）

### 3.1 人脸：当前真实照片覆盖不可靠（P0 最该补）

- **证据链**：cap=640（`visual_targets.py:279-281`）→ 12MP 照片缩 6.25 倍；实测合成合影（带纹理背景，脸 400/600/800px）**0/6 检出**；1600×1200（脸 64~384px）**3/6**；12MP 全页扫描（含条码）实测约 1.5s。仓库样例无人脸照片，E2E/回归的 167 项**没有一项能证明真实人脸被检出**。
- **为什么 640 是红线风险**：手机照片普遍 12MP（4000×3000）；合影中 150-300px 的脸（约占画面 1%-2%）在 640 缩放下只有 24-48px，接近 Haar minSize(24) 与可分辨极限 → 漏检；而 UI/README 没有任何"可能漏检"提示（`visual_targets.py` 无 downscale warning；`docs/impl/visual.md:78` 只在实现文档内部写了）。
- **方案**：P0 分块（长边>1600 → 2×2/3×3，每块 cap 640/960；坐标映射回原图）+ 漏检告警 + 整图按钮；P1 portrait 模式（单脸占画面>10% 时扩到头肩/整图）+ YuNet（227KB MIT，cv2 自带 API）提侧脸/小脸；真实测试集由用户提供后按 §5 标定。
- **验收**：4000×3000 合影（脸≥150px）召回≥90%；12MP 单人肖像≥95%；负样本 0 误报；扫描耗时增量≤1.5s；导出后 verify=0。

### 3.2 PDF 隐藏数据：实测会原样带出（P1 高优先）

- **证据**：构造含附件 `secret.txt` 和含手机号批注的 PDF → 当前 human 导出后 `embfile_count=1`、注释内容 `王五/批注内容手机号 13700000000` 原样保留；metadata 已清（title/author 空）。代码无 `embfile`/`annots`/`widgets` 处理（`pdf_parser.py` 只有 redaction + metadata/XMP）。
- **影响**：合同/病历常见"附件=原件扫描件""批注=审阅意见（含姓名/电话）"；只做文本脱敏等于漏掉整份附件。
- **方案**：解析记录附件/注释/表单数量与名称（不读内容）；导出剥离附件（`embfile_del`）+ 删除注释/清空表单值；Verify 重解析成品后 0 附件/0 注释才允许落盘；默认剥离+warning，或严格模式阻断确认。
- **验收**：附件/批注/表单 PDF 导出后 0 残留；e2e 5/5 与回归 167 项不退化。

### 3.3 文件名与审计：与"不记原值"话术冲突（P1，需用户决策）

- **证据**：`jobs.py:486-489` 输出名保留原 stem；`audit.py:20-37` 存 `doc_name`；`data/yinzhan.db` 实测 `doc_name='民 24593-包罗.pdf'`、out_name 同 stem；`api.py:129-130` 上传副本名含原文件名；`mcp_server.py:159-160` 同理；README:243 声称"只记类型+数量，不记原值"。
- **影响**：文件名可能是"张三的身份证.jpg""某某案判决书.pdf"；审计库/成品名给第三方即泄漏。属**隐藏数据**类 PIPL 风险，且是"话术诚实"红线（red-lines S5/S8）。
- **方案**：默认导出名不含原 stem；审计改存 `doc_name_hash+ext`（HMAC/sha256 截断）或 vault 加密；上传临时名只用 uid；MCP/README/CONTRACT 同步；保留"原名仅本机 UI 展示"的选项由用户决定（决策点 D3）。
- **验收**：审计 INSERT 无原文件名；导出名不含 PII；回归列检查更新；文档口径一致。

### 3.4 规则 scope 与证件类型面：最便宜的覆盖提升（P0/P1）

- 10 条敏感规则 scope 缺 image/tiff（清单见 A4 注）：修 scope 即可让**图片扫描件**用上病历诊断/科室、授信额度/余额、IBAN、支付平台账号、律师执业证号、当事人等规则；成本 0.5 人日，风险主要是图片 OCR 噪声误报（需回归 + 合成样例）。
- 证件类型面：id_document 只 5 类（`visual_targets.py:388-414`），补银行卡/工作证/居住证/通行证等锚点成本 1.5 人日；护照号、银行卡号规则可补文本层漏检（0.5～1.0）。
- **验收**：新增规则在既有样例零新增误报（红线允许新增命中但需逐条解释）；证件/图片样例整卡覆盖。

### 3.5 未成年人：确定性与合规价值最高的低成本项（P1）

- ID_CARD 号码生日可直接推断年龄（18 位第 7-14 位，GB 11643 校验已存在）；文本层/图片 OCR 都能触发；<14 需监护人同意与专门规则（PIPL 31、办法 7、未保条例）。
- 产品无法取得监护人同意 → 只做"提示 + 严格模式"，不做自动判断/拒绝；人脸年龄估计不建议（见 D2）。
- **验收**：合成 <14/≥14 身份证样例提示正确；审计只记 minors=true；回归不变。

### 3.6 场景照片/组合效应：产品级设计问题（P1/P2）

- 现状无组合风险、无场景模式、无一键整图；门牌/路牌只是占位（`visual_targets.py:696-706`）。
- 建议分两步：**P0/P1 先给工具**（一键整图涂黑 + "疑似场景照片/可能组合识别"提示）；**P2 再做评分**（face+plate+doorplate、person+badge、plate+timestamp 等规则）；不做 k-匿名自动验证（单照片场景不适用；去标识化效果评估可参考 GB/T 42460-2023）。
- **验收**：街景样例触发提示；普通文档不触发；整图黑导出复检 0。

### 3.7 生物识别边界（指纹/虹膜）：诚实的能力边界

- 不做自动识别：指纹需专用高分辨率采集（NIST NFIQ2/NISTIR 8382 是面向指纹图像质量的评估工具，手机翻拍通常达不到采集质量）；虹膜需近红外成像（ISO/IEC 19794-6 定义的虹膜图像数据类型），普通可见光照片通常不足以稳定成像；引入不可靠模型会给用户"已识别"错觉，反而增加合规风险。
- 建议：UI/README 明示"不自动识别指纹/虹膜等，请人工框选或整图涂黑"；P2 如需可做"眼部/手指特写"弱提示（仅提示，需用户决策）。

## 6 风险与边界

| 风险 | 说明 | 缓解 | 残余 |
|---|---|---|---|
| **过度承诺（法律）** | 产品只能去标识化；组合信息/背景/文件名/附件都可能重识别 | 话术统一（README:259 已有"去标识化≠匿名化"）；新增能力全部写"降低风险"不写"合规/匿名" | 重识别风险始终存在；不能替代用户 PIA/同意 |
| **漏检=泄漏** | 人脸小目标、不可读车牌、手写/低质 OCR、无证件锚点、指纹/虹膜 | 分块/告警/整图模式/人工框选；P2 模型；真实测试集标定 | 自动检测永远有漏检；产品需明示"不保证 100%" |
| **误报=过度涂黑** | 分块人脸、门牌/路牌/店招、聊天截图、PDF 附件剥离 | 置信度分级（accepted/pending）、默认 pending、UI 可 reject、严格模式开关 | 用户不确认直接导出时按"宁可多涂"或按默认策略 |
| **性能** | 分块人脸 + 大图条码 + PDF 附件/注释扫描 | 仅图片/扫描页执行、cap/分块上限、纯文本页跳过、进度提示 | 低端机 1.5～2× 耗时 |
| **许可证/依赖** | 新增模型（YuNet MIT、车牌模型/训练数据许可）、指纹/虹膜模型不引入 | 只允许 MIT/Apache/BSD/PSF；模型随包+LICENSE；不引入 AGPL/需联网组件 | 训练数据（CCPD 含真实车牌）图像合规需法务确认 |
| **隐私（工具自身）** | 新扫描器/规则不能新增外呼/落盘/日志泄漏；二维码 note 已不写 payload | 沿用禁网/审计不记值/临时目录清理；新增代码静态扫描 | 同机恶意软件/内存抓取（既有边界） |
| **误判未成年人** | 生日伪造、无 ID 号儿童照片无法推断 | 只提示不判定；不自动拒绝 | 仍需用户人工确认监护人同意 |
| **UI/话术不一致** | 前端 TYPE_CN 有 DATE/IP 但后端无规则；README 支持表未列人脸/证件/二维码；审计话术冲突 | 本报告 P0 的文档修正 + P1 审计改造 | 用户预期管理 |
