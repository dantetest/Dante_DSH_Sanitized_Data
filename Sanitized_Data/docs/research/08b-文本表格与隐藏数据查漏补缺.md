## 0. 结论摘要

1. **规则底数 71 条**（common 16 / finance 22 / legal 9 / medical 4 / trade 15 / geo 5，实测 `load_packs()`；6 包），覆盖身份证、银行卡、手机/固话、邮箱、USCC、金额、地址、案号、工商、发票、SWIFT、审计、贸易号码等。**文本侧最大缺口是"准标识符与设备/账号类"**：社交账号 ID、昵称/群名、快递物流单号、票号、VIN、IMEI/SN/MAC、IP、航班/车次/座位、独立门牌号、精确时间——**实测这 13 类在 5 个基线样例上 0 命中**（除 medical 包已覆盖的诊断/住院号）〔实测 T9〕。
2. **"能加"**：上述 13 类都能用**纯规则 + 校验器**落地（P0，约 **3–4 人日**），且候选正则在既有 5 样例上的误报扫描只有"日期"一类命中（medical 的 `2025-03-17/29`）——因此**日期类只做"带时刻的时间"或严格模式开关，默认不动日期**，即可保证不破坏基线。
3. **表格是结构级盲区（最值得先做）**：XLSX 只把 `cell.value` 当文本逐条跑规则（`xlsx_parser.py:206-257`），**纯数值金额/账号/日期无单位不命中**（实测利润表金额 0 命中）；**无表头列级语义**。但块元数据 `ref={sheet,cell,row,col}` 与 DOCX 表格 `ref={t,r,c}` 已存在（`xlsx_parser.py:242-256`、`docx_parser.py:693-698`）——**新增 `table_column` 检测器可零解析器改动落地**：原型对一张 3 行表拟生成 10 个实体，现有规则只覆盖 3 个（漏姓名、空格手机号、缺位身份证、单位、工资）〔实测 T12/E〕。
4. **纯数值单元格**需要一个小的解析器改动：当前 cell block 只有 `attrs={"formula": ...}`（`xlsx_parser.py:254`），不带数值类型/`number_format`/日期标记；建议**只加 attrs（不改解析/导出语义）** + 新增 `numeric_cell` 检测器，金额交给现有 `amount_consistency`，日期列按"保留/可选模糊"策略。约 **2–3 人日**。
5. **隐藏数据最严重的三条（实测已泄漏）**：
   - **PDF 附件（embedded files）与 PDF 注释原样保留**：成品 `embfile_names=['secret.txt']`、注释内容 `批注：王五 13800138000…` 仍在，而 `pipeline.verify` **判 verified=True**〔T1/T14〕——这是当前最该补的隐藏数据缺口（1–1.5 人日）。
   - **导出文件名保留原 stem**：`jobs.py:486-489`，实测源名 `张三_离职证明_含身份证310104198703124510.txt` → 成品名原样带 PII；**审计记录 doc_name/out_name 也是原名**（`audit.py:20-37,53-77`；实测 T7）。建议默认中性名 + 审计清洗名/哈希（1 人日）。
   - **Office 图表/文本框/OLE 走"只告警/二次确认"**：DOCX 图表 XML 里 `张三工资趋势` 在成品中保留且**不触发媒体确认**（`docx_parser.py:838-854` 只把 media/embeddings 计入 `embedded_media`），`verify` 通过；XLSX 图表同理（`xlsx_parser.py:258-281` 只计数、`282-296` 只统计 `xl/media/`），图表标题/系列名可含 PII 且无任何拦截〔T2/T10〕。OLE 在 DOCX 中"确认后原样保留"，XLSX 中则被 openpyxl 静默丢弃（无告警、无确认）——策略需要统一（P1）。
6. **CSV/TSV**：`.csv` 被当纯文本按行处理（`text_parser.py:125`，无列语义），`.tsv` **完全不支持**（实测 `暂不支持这种文件：.tsv`）。合并单元格只保留左上角值（`docx_parser.py:710`；XLSX 同理），多级表头/合并表头无列继承。
7. **未成年人**：当前**零识别**——实测一张 `310104201503124510`（2015 年生、约 11 岁）只产出 `ID_CARD` 实体，无 年龄/未成年人提示、无严格模式；身份证生日解析已存在（`regex_det.py:59-82`，仅用于校验），**从已识别 ID 推断年龄是文本层可做的 P1（2–3 人日）**。人脸年龄估计不建议（误判/偏见/法律风险）。
8. **元数据清理总体到位**：JPG/PNG/WEBP/BMP 重编码后 EXIF/文本块=0、TIFF 仅保留方向/分辨率、PDF metadata+XMP 清空、Office 属性清理——这点优于多数产品；**缺口不在"元数据"，而在"文件里其它携带原文的容器"**（附件、注释、图表、OLE、公式字符串、文件名）。
9. **P0 建议包**（按收益/风险排序）：`table_column` 表头列级（2–3 人日）+ 文本规则 13 条（3–4）+ `numeric_cell`（2–3）+ PDF 附件/注释清理（1–1.5）+ 文件名/审计清洗（1）+ 补空格分组手机号/独立门牌（1）≈ **9.5–13.5 人日（约 10–14）**；P1 约 **14.5–22 人日**（未成年人、公式/图表/OLE 策略、CSV/TSV、合并表头、时间模糊、组合风险提示、PDF 内嵌图 OCR）；P2 为 HEIC/GIF、聊天截图模式、语义级关系。
10. **红线不变**：改动不得让 e2e 5/5、residual=0、`regression.py`（实测 166 项硬检查全绿/1 软提示）变红；新增识别/新增规则按门禁算"软变化"，但**新增误报必须逐条解释**（`docs/red-lines.md:39`、`app/tests/README.md`）。

## 1. 范围、方法与法律口径

### 1.1 为什么本轮聚焦"文本 / 表格 / 隐藏数据"

用户要求按 PIPL 做查漏补缺。图像侧（人脸/证件/车牌/码类/聊天截图视觉）已有 `08`/`08a` 覆盖；本报告补的是**引擎最容易漏、又最容易做**的三块：

1. **文本规则缺口**：新增 10–14 条规则即可覆盖社交/设备/准标识符，零架构改动；
2. **表格结构缺口**：表头语义与数值单元格是"规则引擎只吃文本"的天然盲区，但 UDM 的 `ref` 已经带行列号，**可零/小改落地**；
3. **隐藏数据缺口**：附件/注释/图表/OLE/文件名/审计这些"不在正文里"的原文载体，是 Verify 目前最大的漏检面。

### 1.2 PIPL / 国标相关条款（官方原文入口）

### 4.2 新增校验函数草案（`detectors/pipl_validators.py`）

| 校验名 | 用途 | 算法/依据 | 复杂度 |
|---|---|---|---|

### 4.3 表头列级检测器 `table_column`（P0 核心）

伪代码（`detectors/table_det.py`，约 150 行）：

```
for page in doc.pages:
    blocks = [b for b in page.blocks if b.kind == "text" and b.text]
    groups = group_by(blocks, key=ref_sheet_or_table)      # xlsx: ref["sheet"]; docx: ref["t"]
    for group in groups:
        cells = {(ref["row"], ref["col"]): block}
        header = 在前 header_rows 行内，按列取最近非空文本（处理合并表头：空槽继承左侧/上方）
        for col_index, header_text in header.items():
            spec = HEADER_MAP.get(header_text.strip())
            if not spec: continue
            for (row, col), block in cells where col == col_index and row > header_row:
                if not block.text.strip(): continue
                if is_formula_or_numeric(block): continue    # 数值交给 numeric_cell
                entity = Entity(etype=spec.entity, value=block.text,
                                spans=[Span(block_id=block.id, start=0, end=len(block.text))],
                                level=spec.level, confidence=0.90, origin="table")
                append(entity)
        # 与已有规则结果在 pipeline._merge 阶段按"同值合并/重叠取更长值+更高密级"合并
```

**原型实测**（T-E）：一张 `姓名/身份证号/手机号/单位/工资` 表 3 行数据 → 拟生成 10 个实体（现有规则 3 个，漏 7 个）；字段覆盖：姓名 2/2、身份证 2/2（含缺位 1）、手机号 2/2（含空格 1）、单位 2/2、工资 2/2。**误报预算**：整列处理可能放大误报 → 默认只对白名单表头生效；对既有 `对账单.xlsx` 会产生"客户名称/账号/证件号/金额/联系电话"列级新增实体（门禁允许新增识别，但需 qa 复核并更新软记录/基线）。

### 4.4 纯数值单元格 `numeric_cell`（P0，需要最小解析器改动）

现状（`xlsx_parser.py:218-257`）：

```python
value = cell.value
text = str(value)                     # float 28600.0 → "28600"；无单位 → cn.amount 不命中
formula = getattr(cell, "data_type", None) == "f"
blocks.append(Block(..., text=text, ref={...,"row":row,"col":col}, attrs={"formula": formula}))
```

**最小改法（只加元数据，不改解析/导出语义）**：

```python
attrs = {
    "formula": formula,
    "numeric": isinstance(value, (int, float)) and not isinstance(value, bool),
    "date": isinstance(value, (datetime.datetime, datetime.date, datetime.time)),
    "number_format": str(getattr(cell, "number_format", "") or ""),
}
```

检测器 `numeric_cell`（`detectors/numeric_det.py`）：
- 仅对 `attrs["numeric"]` 且列语义 ∈ {金额/余额/工资/收入/成本/利润/税额/账号/卡号} 的单元格生成实体；列语义来自表头（复用 `table_column` 的 HEADER_MAP）。
- 数值金额：定义 `attrs["unit"]="元"`（无单位默认元）与 `attrs["decimals"]`（从 `number_format` 的 `0.00` 推断），交给 `amount_consistency`（需扩展 `_parse_token`：数值实体无"元"文本时按 attrs 处理；见下）。
- 数值账号：表头为账号/卡号且长度 ≥8 → ACCOUNT/BANK（Luhn 可校验）。
- 数值日期：日期列默认 **keep**（业务常需要），严格模式/时间模糊开关再处理（D2）。
- **导出必须写数字而不是字符串**：`xlsx_parser.export` 当前 `cell.value = current`（字符串）。若替换值是数字字符串，且原 cell 是数值/金额列，应 `cell.value = Decimal/int/float` + 保留 `number_format`；否则公式引用/求和/图表全部失效（这是本设计里**唯一需要改导出语义**的点，约 0.5–1 人日）。
- 金额一致性引擎扩展：`_parse_token` 识别 `attrs["numeric"]` 的 AMOUNT 实体 → `unit_scale=1, decimals=attrs["decimals"]`；合计=分项重算在报表内仍然成立；`xlsx` 数值写回后 `verify` 重新解析能读到数字（`str()` 仍为数字串，若保留额外 attrs 可校验勾稽）。

**收益/风险**：解决"财报/工资表纯数值金额 0 命中"这一最严重表格缺口；风险是数值写回类型/公式重算/百分比列误判（表头白名单 + `number_format` 含 `%` 排除）。

### 4.5 CSV / TSV / 文本表格（P1）

- `text_parser` 扩展名增加 `.tsv`（`text_parser.py:125` 当前只有 `.txt/.md/.csv/.json/.log`）。
- 新增 `csv_parser`（或 text_parser 内分支）：用 `csv.reader` 读取（保留 `dialect`/引号/换行），每个字段一个 Block，`ref={"row","col","line"}`；导出用 `csv.writer` 按原方言重写（或字段级替换后保持原文引号策略）。
- `table_column` 检测器直接复用；无表头的 CSV 退化为现有文本规则 + 地址/号码规则。
- 注意：CSV 大文件（几十万行）需要流式/分页，避免一次载入内存；编码沿用现有 UTF-8/GB18030 探测（`text_parser._decode_text`）。

### 4.6 隐藏数据清理（P0/P1）

1. **PDF 附件/注释**（P0）：`parse` 时 `pdf.embfile_names()`、`page.annots()` 计数写 meta/warning；`export` 默认 `embfile_del` 全部 + 删除/替换非 redaction 注释；`standard` 二次确认（复用 `media_confirmation_required` 机制，新增 `pdf_attachment_confirmation_required`）；`verify`（E2 钩子）重解析成品：`embfile_names()==[]`、注释内容不含原文/已替换；测试夹具见附录 B T1/T14。
2. **Office OLE/图表/文本框/域/脚注**（P1）：解析器写 `doc.meta["hidden_objects"]`（count/parts/types）；导出 `strict` 剥离（zip 级删除 + rels/content-types 清理，参考 `docx_parser.py:509-560`），`standard` 二次确认；XLSX 图表计入媒体确认；XLSX `xl/embeddings` 显式 warning（当前 openpyxl 静默丢）。
3. **文件名/审计**（P0）：默认中性名；`business` 模式对 stem 跑规则；审计存清洗名/hash；vault TTL。
4. **Verify 扩展**（P0/P1）：在 `pipeline.verify` 增加"附件/注释/图表/公式/列级残留/文件名"检查（E2 可注册 verifier 机制已在红线 E2 规划；Lead 维护）。

### 6.2 建议补充到 `regression.py` 的断言（交 qa）

1. **文本规则**：5 样例"v1 包 vs 新包"检测对比——`missing=0`；`added` 逐条白名单解释（沿用财务 P0 的做法）。
2. **文件名/审计**：导出名不含原 stem 敏感 token；审计新记录 `doc_name` 为清洗名或 hash；`out_name` 同步。
3. **PDF 附件/注释**：构造带 PII 附件/注释的 PDF，导出后 `embfile_names=[]`、注释为空，`verify` 通过；保留选项走审计。
4. **表格**：列级实体数 ≥ 原型；数值单元格导出后 `isinstance(cell.value, (int,float))`；公式单元格重算值正确；`xlsx` 成品无 `xl/charts`/`xl/embeddings`（strict）。
5. **CSV/TSV**：表头列级命中；导出列数/引号/编码一致。
6. **未成年人**：<14 提示字段存在、审计只记提示；普通样例不受影响。
7. **组合风险**：2 类准标识符样例触发 warning；审计 risk_level 存在且不含原值。
8. **不回归**：e2e 5/5、residual 0、元数据/Geo 断言、服务/MCP/桌面入口保持（既有 166 项硬检查全绿）。

### 6.3 基线更新说明

新增识别（列级/数值/文本规则）会让样例实体数变化——按门禁**允许**（`docs/red-lines.md:39`），但须：
1. 先跑普通回归确认无硬项失败；

## 附录 D：术语

| 术语 | 含义 |
|---|---|
| 直接标识 | 单独即可识别特定自然人的信息（姓名、身份证号、手机号、社交账号等） |
| 准标识符 | 单独不识别、组合后可识别（地址、生日、时间、车牌、设备号、行程等） |
| 去标识化 | 处理使其在不借助额外信息时无法识别（PIPL 73-3）；可逆/不可逆均属此列 |
| 匿名化 | 无法识别且不能复原（PIPL 73-4）；门槛高于去标识化 |
| 组合效应 | 多个准标识符叠加导致重识别（GB/T 37964 要求评估） |
| 表头列级 | 按表格首行/前几行的列名语义，对整列数据生成实体（不依赖逐个值命中） |
| keep | 规则显式保留（如 HS 编码/价格条款/船名），不修改只标记 |
