## 0 结论摘要

**一句话：三维能力仍停留在「4 种桌面中间格式的文本清理 + OBJ/PLY 顶点减包围盒中心」，且是穿在页面（A4 `Page`/`Block`）模型外衣里的文本管线；无人机倾斜摄影的真实交付形态（OSGB / 3D Tiles / LAS-LAZ / OBJ+MTL 整包）支持为 0，出口自检对几何/贴图/内嵌图完全不可验证，三维自动化测试与样例均为 0。**

### 3.2 OBJ：文本层可用，关联文件与名称层缺失

`[测]`：
- parse：1 页 / **7 个 text Block**（3 条注释 + mtllib + o + g + usemtl）；meta `{format: obj, vertices: 3, coordinate_offset: True}`；warning「疑似大地/工程坐标，导出时将减去包围盒中心」。
- detect+decide：**3 个实体** — `SHEET_NO H50G003004`→surrogate `T92E779217`、`CONTROL_POINT 控制点号 CP-2025-117`→surrogate、`CRS CGCS2000`→**black**。
- export ai/human：316B/360B；warning「OBJ 顶点已减去包围盒中心重定位到原点」+「已覆盖 3 处敏感文本」。
- verify：两次均 `verified=True, residual=0, checked=3, visual_residual=0, media.count=0`。
- 产物对照：注释/图幅号/控制点号被替换（human 为 `████████`）；`v` 行 → `-1 -1 -1 / 1 1 0 / 0 0 1`；**`mtllib 项目模型.mtl`、`o/g Tile_+000_+000_L20`、`usemtl Material_0`、`# 项目：XX新区…` 原样**；输出目录**没有** `.mtl` / 贴图文件（悬空 `mtllib` 引用）。
- 结论：🟡 文本清理按规则命中生效，但「项目名/瓦片名/材质名」与「OBJ 整包（MTL+贴图）」是缺口；几何只有平移。

### 3.3 PLY：ascii 可用；**binary + black 有数据损坏缺陷（新发现）**

`[测]` ascii：
- parse：2 个 Block（comment/obj_info）；detect **2 实体**（CONTROL_POINT→surrogate、CRS→black）；export 296B/320B；verify 均 True（residual 0, checked 2）。
- 产物：`comment 项目 XX新区 ████████ ContextCapture`、`obj_info ████…`；顶点 → `-1 -1 -1 / 1 1 0 / 0 0 1`。
- 注意：header 被写入 UTF-8 多字节 `█`（`[测]` 输出 header 含 `\xe2\x96\x88`）→ **若源 header 本为纯 ASCII，成品 header 会变成非 ASCII**，严格 PLY 读取器可能拒绝（PLY 规范 header 为 ASCII）。

`[测]` binary：
- 基线（header 无命中，`b1_nohit.ply`）：输出 218B = 输入，顶点/面逐字节一致，verify True。
- **缺陷（命中 black）**：`comment CGCS2000` → 替换为 8×`█`（UTF-8 24B，原 8B）→ 新 header 202B > 输入 `data_offset` 186B；`_export_ply_binary` 用 `output[:data_offset] = header_bytes` 造成整体后移 16B，随后仍按**输入** `vertex_offset` 写顶点（`[码] mesh_parser.py:979-1015`：`vertex_offset = header["data_offset"] + start`）→ 新 header 尾部被顶点字节覆盖、几何错位。
- `[测]` 输出：文件 235→251B；重解析报 `三维文件解析失败（.ply）：PLY 头部缺少 end_header`（0 页 0 block）；**`pipeline.verify` 仍返回 `verified=True, residual=0, checked=1`**（parse 降级为空 Document，文本比对天然通过）。
- 对照实验（同长度 ASCII surrogate，`comment H50G003004→T92E779217`）：header 188B→188B，顶点/面与输入一致、重解析正常 → **根因是「header 字节长度变化」，不是 numpy/写回本身**；只要命中项被 `black`（`█` 3 字节/字符）或 surrogate 长度不同，二进制 PLY 就可能损坏。
- 附：`PLY_BINARY_MEMORY_LIMIT=256MB`（`:54`），超限只清头并 warning（未实测超限）。

### 3.4 STL：头清理可用且「按命中触发」，几何完全不处理

`[测]`：
- parse：1 Block = 80B 头文本；detect **1 实体**（CRS→black）；export 134B（=输入），warning「二进制 STL 头含敏感信息，头部 80 字节已整体置零」+「STL 该格式暂不支持几何重定位」。
- 产物：80B 头全 `\x00`；**84B 之后（三角形数 + 三角形数据）与输入逐字节一致**；verify True。
- 无命中对照（头为 `XX新区倾斜摄影项目 ContextCapture 10.20 2026-10-20`，无规则词）：**头 80B 原样保留**（项目名/软件名/日期泄露），verify True → 头清理是「命中才清」，不是「默认清空」。
- ASCII STL：代码另有等长空格覆盖分支（`:1036-1050`），本次未单独构造（不在 4 格式主链路内）。

### 3.5 GLB：只做 JSON 字符串等长覆盖，BIN/内嵌图/几何原样

`[测]`：
- parse：**9 个 Block**（generator/copyright/version/extras.crs/scenes 名/node 名/mesh 名/image uri/mimeType），meta `{format: glb, json_texts: 9}`；detect **1 实体**（`CRS CGCS2000`，2 处 span）；export 804B（=输入），warning「JSON chunk 内已等字节长度覆盖 2 处敏感文本（chunk 长度不变）」+「GLB 暂不支持几何重定位」。
- 产物：JSON chunk 716B→716B、JSON 仍可解析；**BIN chunk 60B 逐字节一致**（含假 JPEG）；`CGCS2000` 被替换为 **8 个半角空格**（`[测]` `nodes[0].name='Root         '`、`asset.extras.crs='        '`）——因为 `█` UTF-8 24B ≠ 原 8B，导出器退化为空格（`[码] :1093-1100`，与 warning 语义一致）；verify True。
- **原样保留**：`asset.generator=ContextCapture 10.20`、`asset.copyright=XX测绘院 项目：XX新区`、`scenes[0].name=Tile_+000_+000_L20`、`images[0].uri=photo_sign.jpg`、`accessors[0].min/max=[500123.456,3450123.789,10.5]…`（**原始大地坐标仍以 JSON 数值形式存在**，是定位泄漏点）。
- 内嵌图：BIN 内 JPEG 未抽取、未 OCR、未剥 EXIF；`mesh_parser` 不写 `doc.meta["embedded_media"]`（`[测]` 重解析 meta 无该键）→ jobs 的「未处理内嵌媒体二次确认」对 GLB/OSGB **静默放过**。

### 3.6 verify 边界（后续架构的关键约束）

`pipeline.verify` 对三维只做「重解析成品 → 重跑检测器找原文 + meta 黑名单 + geo_tags + 视觉 IoU」（`[码] pipeline.py:635-758`；mesh 无任何专属分支）。实测 6 类篡改：

| # | 篡改 | verify 结果 | 说明 |
|---|---|---|---|
| 2a | 导出后把 OBJ 顶点**改回大地坐标**（模拟几何未中性化/被还原） | ✅ 放行 `verified=True` | 几何数值不参与 verify（parse 只抽文本） |
| 2b | 把 `CGCS2000` 写回 STL 80B 头（同时改一个顶点） | ❌ 拦截：`仍有 1 处原文残留` | **只有文本层可验** |
| 2c | GLB BIN 内 9 个 float 全改成 `123456.0` | ✅ 放行 `verified=True` | 几何不可验 |
| 2d | GLB BIN 内嵌 JPEG 字节替换为 `ExifGPS:39.9,116.3`（长度不变） | ✅ 放行 `verified=True` | 内嵌图/EXIF 不可验 |
| 2e | STL 纯几何篡改（三角形 z=999） | ✅ 放行 `verified=True` | 几何不可验 |
| 2f | 使用导出器自己产出的**损坏二进制 PLY**（§3.3） | ✅ 放行 `verified=True` | 成品结构性损坏也不可验 |

结论：**verify 对「文本」有效、对「几何/贴图/内嵌图/文件结构」全部不可验证**。这与「出口自检 residual=0 才允许落盘」的产品承诺存在语义缺口；三维落地时必须新增**结构断言 + 字节不变性 + 贴图重扫 + `unverifiable` 显式声明**（详见 §5.6 与姊妹稿 §7.6），不能沿用现有 verify 的「重解析文本」思路。

## 5 架构触点：各模块现状与需要的新抽象

> 逐模块只写「现状证据 + 缺什么」；抽象形态与 CONTRACT v4 草案细节见姊妹稿 `_survey/architecture.md §4.3/§7.6`，本稿补充**本次实测到的硬约束**。

### 5.1 UDM / Block（`udm.py`）

- **现状**：`Document.fmt` 注释为 `pdf|docx|xlsx|image|tiff|mesh|text`（`udm.py:83`）；`Block.kind` 只有 `text|table|image`（`udm.py:50`）；mesh 解析把注释/JSON 文本塞进 `Page(A4 595×842)` 的 `text` Block（`[码] mesh_parser.py:48-49,590-648,707-740`；`[测]` OBJ 7 block、GLB 9 block、width/height=595/842）。
- **缺口**：无「多文件资产」（MTL/贴图/tileset 子瓦片/点云分块）表达；无几何/UV/瓦片引用；`Page` 是页面坐标，3D 无页面语义；`Block` 无 bbox/空间定位 → 无法给贴图区域做 2D 对照框选。
- **新抽象**：`Document.assets[]`（role: geometry/material/texture/metadata/tile；path/rel_path/sha/handled）、`Document.scenes[]`（根 transform/CRS/瓦片树）、`Document.fmt` 扩 `pointcloud|tileset|package`；`Span` 扩几何/UV/tile 可选字段（向后兼容）。

### 5.2 pipeline（`pipeline.py`）

- **现状**：`detect` 只遍历文本 Block（`iter_text_blocks`，`registry.py:177-188`）；`has_cleanup_targets` 只认 `geo_tags`、PDF 隐藏数据、`geo_transform/geo_params`、`META_KEYS`（`[码] pipeline.py:585-608`）；**实测纯坐标 OBJ 无实体 → False → UI 拒绝导出**（§3.7）；`verify` 无 mesh 分支（`[码] pipeline.py:635-758`）。
- **缺口**：几何/贴图/资产不是「实体」，没有对应的 Plan/清理目标/复检器；`has_cleanup_targets` 不认三维坐标偏移。
- **新抽象**：`has_cleanup_targets` 扩 `coordinate_offset/geometry_plan/package_assets`；`verify` 增加可注册结构化复检器 `register_structural_verifier(name, fn)` + 返回 `structural/unverifiable` 字段；几何变换参数与 TIF 一样走 `doc.extra`。

### 5.3 jobs（`jobs.py`）

- **现状**：1 job = 1 文件、`path` 单文件；导出名/审计/加密映射齐全；`media_confirmation_required` 只读 `doc.meta["embedded_media"]`（`[码] jobs.py:69-99, 559-573`）——**mesh 从不写该字段**（`[测]` GLB 重解析 meta 无 `embedded_media`）→ GLB 内嵌图不走二次确认；`geo_params` 已能从 `doc.extra` 取并写 vault（`jobs.py:598-605`，TIF 用）；无目录/zip 输入输出。
- **缺口**：整包（目录/zip）任务模型；资产级进度/取消；3D 参数入 vault 的字段（现在只有 `geo` 段，3D 需 `geo3d`）；内嵌图/贴图的「未处理媒体」二次确认需要 mesh 侧写 `embedded_media`。
- **新抽象**：`Job.root: Path`（目录）+ `output_kind: file|dir|zip`；上传支持 zip / `/api/jobs` 支持目录；`doc.extra["geo3d"]` 自动入 vault（与 `geo` 同 AES-GCM 通道）；`ExportResult` 支持目录 + manifest。

### 5.4 UI 预览（`app/web/`、`app/server/yinzhan/api.py`）

- **现状**：mesh `can_render=False` → `build_preview` 返回 `kind="flow"`（`[码] pipeline.py:832`；`[测]` OBJ preview kind=flow）；`render()` 返回 `None`（`[码] registry.py:44-45`）；前端 flow 渲染把 block 当文本行排版（`app/web/app.js:1157-1226`），flow 下整页矩形框选被禁用（`app.js:1583` 侧注释）；投放台文案已写「三维模型」（`[码] app/web/index.html:45`）。
- **缺口**：无 3D 场景/贴图资产视图；无「哪些贴图已处理/未处理」清单；无法在贴图上框选敏感区域回写（贴图 OCR 的失败兜底）。
- **新抽象**：`PreviewDoc.kind="scene"` + `scene:{format, url/tileset, assets[]}`；前端离线 WebGL（three.js MIT / CesiumJS Apache-2.0）或「最小可用」= 资产清单 + 贴图 2D 对照 + 可选网格查看；框选语义从「页面矩形」扩到「贴图 UV / 资产路径」。

### 5.5 vault（`vault.py` + `jobs.py`）

- **现状**：`save_mapping(job_id, session_map, meta)` 已支持 `meta` 透传 + AES-GCM（`[码] vault.py:47-61`）；`jobs` 在 ai 模式把 `doc.extra["geo_params"]` 写入 `meta["geo"]`（`[码] jobs.py:598-605`）；TIF 中性化参数走此通道（HEAD 已落地，`[码] tiff_parser.py:558-621,599-604`；`[测]` `git show HEAD` 可见）。
- **缺口**：3D 无参数通道（mesh 从不写 `doc.extra["geo_params"]`）；首版无「参数 TTL/一次性」策略（`[文]` 姊妹稿 R4）。
- **新抽象**：`doc.extra["geo3d"]={method, translate, rotate, quantize, decimate, noise, src_crs, seed}` → vault `meta["geo3d"]`；导出记录 `unverifiable`；参数即钥匙的安全话术不变（只降密不匿名）。

### 5.6 verify（`pipeline.verify`）

- **现状**：只重解析文本 + `META_KEYS` 黑名单 + `geo_tags` + 视觉 IoU（`[码] pipeline.py:635-758`）；对 3D 的 6 类篡改/损坏放行 5 类（§3.6）。
- **缺口**：无结构断言、无字节不变性、无贴图重扫、无「不可验证」显式声明；`media` 检查只覆盖 `doc.meta["embedded_media"]`（mesh 不设置）。
- **新抽象（必须写进 CONTRACT，不能静默放行）**：L1 结构断言（GLB chunk/accessor/索引/包围盒；tileset schema 与全 uri；LAS header 与点集一致）；L2 字节不变性（未处理 BIN/tile/贴图与输入哈希比对）；L3 贴图重扫（OCR/视觉残留=0，抽检 ≥20 张/批）；L4 人工抽样声明；L5 `unverifiable: []` 显式字段（导出记录 + UI 明示）。任一未声明/未通过 → 阻断导出（与现有 `VerifyError` 语义一致）。

### 5.7 规则（`rules/*.yaml`）

- **现状**：`scope: mesh` 共 13 条（common×9 + geo-cn×4，`[测]` `_load_rules("mesh")`）；`cn.geo_decimal` 不含 mesh；无项目名/软件名/版权/瓦片名/拍摄日期/MTL 名/metadata.xml SRS 规则。
- **新抽象**：`geo3d-cn.yaml` 域规则包（项目名锚点、建模软件名、版权方、瓦片命名、`SRSOrigin`/`SRS` 文本、KML 坐标串）；坐标数值规则需专门检测器（数值 + 量级门控），非 regex 文本规则。

## 6 技术难点排序（风险从高到低）

1. **OSGB 容器自研（最高）**：无公开规范（OSG 二进制序列化由源码定义，OSGPL≈LGPL-2.1+wxWindows 例外，自研只能 clean-room、禁复制代码）、LOD/PagedLOD 层级、内嵌纹理块长度回写、不同建模软件（ContextCapture/大疆智图）目录与 `metadata.xml` 差异、无真实样例/查看器 → 工期 15–23 人日且不能承诺「可打开」。
2. **GLB / 3D Tiles 字节级重打包**：`bufferView/accessor` offset、4 字节对齐、BIN 长度变化、b3dm feature/batch table、JSON 变长替换（当前只能等长/空格）；失败必须阻断，不能 fallback 原样复制（现有 `_copy_fallback` 会留下未脱敏成品并经 verify 漏检）。
3. **贴图抽取→OCR→局部涂黑→回写**：JPEG 长度变化破坏块偏移（需等长/重排）、贴图 OCR 小字召回低（旧基线 TIF 实测 0.267 缩放只识别 48px 行）、人工抽检 ≥20 张/批的流程与 UI；这是「招牌/门牌/车牌」唯一有效路径，但召回与工作量大。
4. **verify 的「不可验证」责任**：几何/点云/内嵌图无法像素级复检，必须靠结构断言+字节不变性+贴图重扫+人工声明；若沿用现有 verify 语义 = 静默放行（本次已实测 5/6 放行），会稀释主产品「出口自检」公信力 → 必须写进契约（`unverifiable`）。
5. **大文件/流式/内存**：OSGB/点云整包常几十–几百 GB；当前 GLB 整读（`[码] mesh_parser.py:1066` `read_bytes()`）、PLY binary 整读+256MB 上限（`:54,980`）、OBJ 流式（唯一）；需要 chunk/分块/取消/进度。
6. **3D 预览与交互**：现有对照台是「raster/flow 二态」，3D 需新 kind + WebGL 离线资源 + 相机/瓦片流 + 3D 拾取；「最小可用（资产清单+贴图 2D 对照）」可先做，完整场景预览 8–15 人日且易失控。
7. **许可证/依赖/契约**：`lazrs` 仓库 LICENSE=Apache-2.0（PyPI 元数据却标 MIT，**元数据不一致**）且是 LASzip（LGPL）的移植，需法务确认；OSG 为 LGPL 血缘；`CONTRACT.md:15` 现禁 trimesh/GDAL CLI；新增依赖须离线 wheel + 许可证白名单 + `app.spec`/`requirements.txt` 同步（`CONTRACT.md:316-319`）。
8. **规则/口径**：项目名/软件名/版权方/瓦片名/建模元数据无规则；坐标数值规则缺失；README/投放台「三维」表述需先收敛。
