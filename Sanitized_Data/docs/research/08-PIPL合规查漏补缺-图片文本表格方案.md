## 0 结论摘要

**一句话**：用户列出的 PIPL 条目**绝大多数可以加进去**；但有三处"实测已经在泄漏"的缺口必须优先堵——**PDF 附件/批注/表单**、**文件名与审计**、**大图人脸漏检且无告警**；另有 **10 条敏感规则在图片上不生效**、**表格纯数值与表头语义缺失**、**Office 图表/公式字符串/ OLE 不在拦截范围**。全部方案分 P0/P1/P2：

|---|---|---|---|

## 1 法律口径与本产品定位

| 依据 | 要点 | 对本产品的含义 |
|---|---|---|
| PIPL 第 4 条 | 个人信息定义；**匿名化后的信息不属于个人信息** | 只有真正匿名化才跳出适用范围；换名/涂黑多数仍是去标识化 |
| PIPL 第 6 条 | 最小必要、目的限定 | 脱敏项可配置（严格度/规则包/keep 白名单），不无差别全涂 |
| PIPL 第 17 条 | 告知义务 | 界面必须说明处理范围与残留风险（本地工具也一样） |
| PIPL 第 28 条 | **敏感个人信息**：生物识别、宗教信仰、特定身份、医疗健康、**金融账户**、**行踪轨迹**等，以及**不满十四周岁未成年人的个人信息** | 人脸/证件/金融账号/位置轨迹/未成年人默认从严（L3/涂黑/整图） |
| PIPL 第 29 条 | 处理敏感个人信息需**单独同意** | 工具不采集，但导出提示要说明"已隐去 ≠ 可自由共享" |
| PIPL 第 31 条 | 不满十四周岁：监护人同意 + 专门处理规则 | "未成年人模式/强提示"的产品依据 |
| PIPL 第 51 条 | 处理者应采取加密、**去标识化**等安全技术措施 | 本产品能力的法律定位 |
| PIPL 第 55 条 | 处理敏感个人信息应做 PIA | 企业客户仍需自评；审计链可提供证据，不能替代 |
| PIPL 第 73 条第 3/4 项 | **去标识化**：不借助额外信息无法识别；**匿名化**：无法识别**且不能复原** | 只承诺"已隐去/去标识化"；human 模式虽不可逆，场景/组合仍可能重识别 |
| GB/T 35273-2020 | 个人信息安全规范：敏感个人信息判定、去标识化 | 分类与验收参考 |
| GB/T 37964-2019 | 个人信息去标识化指南：**重识别风险评估（含组合效应）** | "组合风险提示"的设计依据 |
| GB/T 39335-2020 | 个人信息安全影响评估指南 | 企业 PIA 方法参考 |

> 官方入口：[PIPL 中国人大网全文](http://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)、[GB/T 35273-2020](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=4568F276E0F8346EB0FBA097AA0CE05E)、[GB/T 37964-2019](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=C8DF1BC2FB43C6EC0E602EB65EF0BC66)、[国家标准全文公开系统](https://openstd.samr.gov.cn/)。条文以官方最新有效版本为准，报告引用仅用于定位与说明。

### 4.2 关键实现要点

- **人脸（P0 最优先）**：长边>1600 时 2×2/3×3 分块（cap 640/960）检测并映射合并（08a 实测 12MP +0.3–1s）；检测被缩小时写 warning + UI 提示"照片较大，小脸可能漏检，请人工复核/整图涂黑"；人脸框扩至头部（发际/耳廓/下颌）或提供整图按钮（复用 `/mark` 全页 rect 链路）；P1 portrait 模式/YuNet（227KB MIT）。
- **证件**：扩 10 类锚点（身份证/护照/驾驶证/营业执照/社保卡 + 银行卡/工作证/居住证/港澳台通行证/永居证）+ `cn.passport_no`；整卡区域由锚点并集 + 邻域扩张；命中后整卡/整页黑。
- **车牌**：改为"完整牌面色块检测（蓝/绿/黄底+白字）→ 整块矩形涂黑"，OCR 仅确认；检测不到时回退 OCR 框+外扩并标注"可能只覆盖文字区域"。
- **门牌/路牌/店招（P1）**：OCR 锚点（路/街/大道/号/栋/单元/室/店/招牌/公司/单位）+ 区域扩大；无文字场景不承诺自动 → 整图/人工。

- **生物识别（P2/不建议）**：不自动检测指纹/虹膜；整图/区域黑兜底。

## 5 文本、表格与隐藏数据方案

### 5.1 文本规则（P0，零架构改动，约 3–4 人日）

新增 `rules/pipl-cn.yaml`（建议包名）约 13 类规则：社交账号/聊天 ID/昵称（near 约束）；快递/物流单号；机票/火车票/行程单票号 + CVV（near）；VIN（ISO 3779 校验）；IMEI（Luhn）/SN/MAC；IPv4/IPv6；航班/车次/座位；工牌/工号；独立门牌/单元/室；带空格分组手机号；日期只在"带时刻/严格模式"处理。所有弱特征规则必须带 `near`/校验器；候选实测在 5 个基线样例上只有日期命中（medical 2 行），**日期默认不动**即可不破坏基线。详见 08b §4.1。

### 5.2 表格（结构级，P0 约 4–6 人日）

1. **`table_column` 表头列级检测器（P0，零解析器改动）**：XLSX `ref={sheet,cell,row,col}`、DOCX `ref={t,r,c}` 已存在；取前 1–3 行识别表头 → 列语义（姓名/身份证/手机/地址/银行卡/单位/邮箱/金额/订单号）→ 对整列每行生成实体；与现有规则结果同值合并、重叠取更长值/更高密级；高风险列可 pending。原型：一张 3 行表应处理 10 个实体，现有规则只覆盖 3 个。
2. **`numeric_cell` 纯数值单元格（P0，小改解析器）**：`xlsx_parser` 给 Block.attrs 增加 `numeric/date/number_format`（**只加元数据，不改解析/导出语义**）；数值单元格按列语义生成 AMOUNT/ACCOUNT/DATE 实体；金额交给现有 `amount_consistency`（无单位按"元"、按 number_format 保小数）；导出写回**数字而非字符串**（否则 Excel 求和/公式失效）。
3. **公式/图表/隐藏表/定义名/外部链接（P1，2–3 人日）**：已清隐藏表/定义名/批注/外部链接/属性；缺：公式字符串里的 PII（`="张三"` 保留）、图表 XML 标题/系列名（保留且不触发确认）、隐藏行/列数值不处理、verify 不检查这些容器。
4. **Office 内嵌图片/图表/OLE（P1，3–5 人日）**：解析按 zip `namelist()` 全量枚举 media/embeddings/drawings/charts/activeX → 计入 `hidden_objects`/媒体确认；导出 standard 确认/strict 剥离；P1 内嵌图片自动走 mediascan→涂黑→zip 回写。
5. **CSV/TSV/合并单元格（P1，2.5–4 人日）**：CSV 无列语义、TSV 不支持；用 `csv` 模块解析成 `ref={row,col}` 复用 `table_column`；导出保持引号/编码；合并/多级表头做列语义继承。

### 5.3 隐藏数据（P0 约 2–3 人日）

- **PDF 附件/批注/表单（P0，实测泄漏）**：`pdf.embfile_names()`、`page.annots()`、`widgets()` 解析计数写 meta+warning；导出默认剥离/二次确认；`pipeline.verify` 重解析成品要求 0 附件/0 注释/表单值无原文；strict 直接剥离。
- **文件名/审计（P0）**：默认中性名（不含原 stem）；可选"保留业务名（stem 跑规则命中则替换）"；审计新增清洗名/hash 字段（历史不迁移，链完整）；上传临时名只用 uid；MCP 输出同步；README 话术同步。
- **vault TTL（P1）**：映射库默认 7 天自动清理，启动扫描 `vault/*.bin`；UI 提示剩余天数。
- **UI/话术**：README 支持表/已知限制与实现对齐（当前 README 未披露人脸/证件/车牌/二维码能力与 640 cap 限制，属透明度缺口）；补充"去标识化≠匿名化、本机副本不在保证范围"。

### 5.4 未成年人（P1，1–3 人日）

- 从已识别身份证号 → 生日 → 年龄 <14 时：job 增加 `minor_warning`；UI 醒目提示并给"未成年人严格模式"一键（更激进涂黑、导出二次确认）；审计只记"提示已展示/严格模式已启用"，不记生日/年龄原值。

## 7 验收标准（摘要）

- **图片**：用户提供的真实/合成测试集（正脸/侧脸/合影/证件/银行卡/车牌/门牌/路牌/店招/聊天截图/窗外/反光）上：标注的敏感区域**零漏涂**；导出后原目标不可检出；EXIF/GPS=0；输出名不含原 PII；大图人脸分块后 12MP 合影（脸≥150px）召回≥90%；负样本误报≤5%；性能增量 ≤1.5×。
- **文本**：新增规则在 5 个基线样例上**非预期新增误报=0**（候选扫描只有日期命中，默认排除）；虚构正例召回≥95%（有校验位 100%）；verify residual=0。
- **表格**：表头列级覆盖 100%；纯数值金额识别 100%、勾稽 100%；导出后 Excel 打开数值仍为数字、公式可重算；strict 成品无 chart/OLE/embeddings；CSV/TSV 列数/编码保持。
- **隐藏数据**：PDF 成品 `embfile_names=[]`、注释无原文、表单无原文；文件名/审计不含 PII；元数据/Geo 断言保持；verify 能拦截上述残留。
- **红线**：e2e 5/5、regression 当前 166 项硬检查全绿；不引入模糊/马赛克；不 push（按用户指示）。

## 8 风险与边界（必须写进产品说明）

1. **去标识化 ≠ 匿名化**：即使涂黑，仍可能通过文本结构、金额、关系、场景/组合线索、系统副本重识别；产品只承诺"已隐去"。
2. **组合效应**：无脸无车牌也可能被"门牌+车型+时间"锁定；提供提示/整图，但不承诺自动消除（GB/T 37964 的重识别评估由用户完成）。
3. **自动识别能力有限**：侧脸/遮挡/低清/手写/反光/大图小目标会漏；漏检必须能人工框选补（已有）；真实测试集是当前最大缺口（samples 仅 5 个，无真人脸/证件/门牌/聊天截图）。
4. **生物识别不承诺自动识别**：指纹/虹膜、窗景/室内装修/反光、聊天关系语义不做自动承诺；整图/人工更稳妥。
5. **未成年人**：只能由身份证生日/人工判断推断；不做人脸年龄估计；误判/漏判风险如实说明。
6. **排版/附件删除风险**：PDF 附件/注释、Office 图表/OLE 可能承载业务信息；默认"确认/剥离"可配置，strict 模式明确告知"版式/附件会变化"。
7. **合规不是本产品能认证的**：企业客户仍需 PIA（PIPL 55）、告知/同意、跨境评估等；本产品提供技术手段与审计证据。
8. **测试集与性能**：新能力需真实标注测试集（约 85–120 张 / 2–3 人日）；新增扫描/规则不得让红线 F12 性能超基线 1.5×。
