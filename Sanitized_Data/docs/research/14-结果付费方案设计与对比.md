> - **对比结论不变：传统年费/席位胜；结果付费只适合获客/低频补充，纯结果付费不可行。**

## 0 结论先行

### 0.1 结果付费怎么设计（一页版）

| 项 | 设计 |
|---|---|
| **产品形态** | **条件方案**：默认不改变“免费 3 份/天、导出永不 gate”；**水印已否决（含预览）**；只有先拍 D-R1（免费额度/导出 gate 例外）才做“预览免费+按结果付费”。预览保护仅靠“限页+低清+禁下载”，无可见水印。否则最多做“首单 ¥9.9 获客券”。 |
| **计价单位** | 1 次“成功导出”= 1 个结果；同一 Job 的换名版+涂黑版算 1 个结果；按页数分档（≤50 / 51–150 / >150 页）。 |
| **建议价** | 首单 **¥9.9**（限 1 次、≤20 页）；单份 **≤50 页 ¥19**、51–150 页/扫描件 **¥29**、>150 页/含审计报告 **¥49**（天花板档，不主推）；**P0 不做 10 份包**（包价会打乱年费交叉点，P1 再评估）。年费用户不受影响。 |
| **怎么收** | 预览/复核/自检免费 → 点“满意，导出” → 显示价格 → 微信/支付宝/卡密 → 获得 **result token/credits（离线签名）** → 导入 → 校验通过后导出；**导出失败不扣费/人工退，不做自动退**。 |
| **与免费版** | 保留 3 份/天免费导出；**低频用户（1–3 份/年）已被免费版覆盖，结果付费真实需求≈0**——这是本方案最大的问题（D-R1）。仅“同一天第 4 份/超大页”可能触发，而那类人本应买年费。 |
| **MCP/团队** | **MCP 不参与结果付费**：仍只认 Pro/Team/Org，返回 `license_required`；**团队/机构不开放**按文件付费（合同/席位）。 |
| **退款/发票** | **未签发/未导入 7 天内可退；已导入/已签发即数字化交付，不退**；导出失败走客服工单人工核验（不承诺自动退）；每笔可开电子普票，支持按月合并开票；**首单 ¥9.9 也可开票**。 |

**一句话**：在当前“免费 3 份/天 + 导出永不 gate + 水印已否决”的约束下，结果付费**需求不足、不建议立项**；最多做“首单 ¥9.9 获客券”。只有先改免费策略与导出 gate，才值得谈按结果付费，且仍只是第三轨。**不做水印**——预览只限页/低清/禁下载，接受截图泄漏风险。

### 0.2 结果付费 vs 传统付费：结论

| 维度 | 传统年费/席位 | 结果付费 |
|---|---|---|
| 收入可预测性 | **高**（预收、续费） | 低（按次、季节波动） |
| 首次付费门槛 | 高（¥199/499 先付） | **低（¥9.9/19，看到结果再付）** |
| ARPU / LTV | **高**（尤其 Pro/团队） | 低（低频用户 ARPU 几十元） |
| 适合人群 | 高频个人、专业版、团队/机构、MCP | **低频、偶发大文件、第一次用** |
| 团队/机构/MCP | **适配** | 不适配（按文件开票/对账、Agent 无法支付） |
| 离线可行性 | 已设计（license） | 需 credits/token，复杂但可行 |
| 运营/发票成本 | 低（按年/席位） | 高（微支付、逐单发票、客服） |
| 对年费的蚕食 | — | 有风险，需定价保护（≥11 份/年小文件、≥7 份/年大文件买年费） |

**结论（评审后修订）**：
1. **在当前约束下（免费 3 份/天、导出永不 gate、水印已否决），完整结果付费的需求≈0、收入≈0，不建议立项**；若强行上，会破坏免费版承诺与历史 P0 修复。
2. **传统年费/席位是唯一可支撑公司收入的模式**；纯结果付费不适合做唯一模式（收入不可预测、团队/机构/MCP 不适配、运营成本高）。
3. 若要做，**只做“首单 ¥9.9 获客券”**（不改免费额度/导出 gate，**也不加水印**；8–12 人日，A 模式），作为拉新/验证，不当作收入线。
4. 若愿意先改产品底线（D-R1：免费额度/导出 gate 例外；**水印已否决，不列入**），才考虑完整版 31–45 人日；即便那时，也定位“第三轨”，不替代年费。
5. 若必须二选一：**选传统付费**；结果付费只作为获客/补充。

**建议试点**：默认只上“首单 ¥9.9 获客券”（≤20 页、限 1 次、A 静态码；**不加水印**、不改免费额度、不改导出 gate），成本 8–12 人日；先验证“首单券→年费”升级率。**不要**在没有 D-R1 拍板前做导出付费墙/credits 完整版。

## 1 定义、边界与“满意的结果”怎么落地

### 1.1 什么叫“结果”

- **结果 = 一次成功导出、可外发的成品**（换名版或涂黑版；同一 Job 两种出口算 1 个结果）；
- **计费条件必须机器可判定**：导出接口返回成功（文件已生成 + 自检报告已产出）；**不把 `residual=0` 当计费/阻断条件**（自检是建议性的，`residual>0` 也可能被用户确认导出）；**不按“用户主观满意”计费**（主观满意只决定“买不买”，不决定“算不算成功”）；
- **预览、识别、复核、自检、框选补漏全部免费**；收费点只在“导出成品”。

### 1.2 “满意后付费”的现实实现

完全“先导出后付款”在离线产品上无法约束（导出即拿到文件）。可落地的流程是：

```
免费预览（低清/限页，无水印） → 用户判断满意 → 付费 → 解锁高清导出 → 失败人工核验/不扣
```

- 对外文案应写“**先预览，满意再付费导出**”，不能写“先导出后付款”；
- 若导出失败/自检残留 >0 → 不扣 credit；已扣走客服工单人工核验（零外呼无法自动退）
- 用户不满意 → 不付费即可，无损失（预览免费）。

### 1.3 不做的

- 不做“按效果/按满意度评分收费”（无法核实）；
- 不做“后付费/账期”（个人客户坏账、离线无法约束）；
- 不做团队/机构按文件（发票/对账/合同成本高）；
- 不让 Agent/模型代付；不做个人收款码。

## 2 完整付费方案

### 2.1 价格表（建议，待市场锚校准）

| SKU | 价格 | 内容 | 有效期 |
|---|---|---|---|
| 首单体验 | **¥9.9** | 1 个结果（≤20 页），限首次购买/设备；**可开票** | 30 天 |
| 单份·小 | **¥19** | 1 个结果（≤50 页） | 购买后 30 天 |
| 单份·中 | **¥29** | 1 个结果（51–150 页 / 扫描件 OCR / 含复检报告） | 30 天 |
| 单份·大 | **¥49** | 1 个结果（>150 页 / 批量 / 含审计报告 / 加急；不主推） | 30 天 |

> **P0 不做 10 份包/年费抵扣**：包价会把“≥11 份买年费”的交叉点推到 13–15 份，直接蚕食年费；年费抵扣需要券/订单关联模型，P1 再议。P0 只做单份。

**定价逻辑**

- 年费个人 ¥199 不限量；单份 ¥19 × **10.5 份 ≈ ¥199** → **≥11 份/年应买年费**；单份 ¥29（扫描件/大文件）× **6.9 份 ≈ ¥199** → **≥7 份大文件买年费**；
- **不做包**：避免 129/149 元包价把临界点推到 13–15 份；如未来做包，必须同时满足“仅 ≤50 页、限首年 1 个、6 个月有效”，并重算交叉点；
- 首单 ¥9.9 是获客价，**限 1 次/机器/手机号、≤20 页**；A 静态码链路无法验证手机号时，只限“机器码 + 订单号”一次，接受刷单风险。

### 2.2 免费预览与付费墙

- **未付费预览（仅当 D-R1 改产品底线后才做；无水印）**：低清（服务端输出像素上限，不写 dpi）、每 Job 只给前 5 页、每天最多 3 个 Job；实体清单/已隐去处数/自检结果照常可见；**预览图不可下载/复制**；**不加水印**——靠“只给部分页 + 低清”限制可用性，接受截图泄漏风险；
- **前置改造**：现有 `preview?mode=out` 会下发原文/替换表，“外发版”是前端 overlay，`/file` 无鉴权，预览还会落盘清晰成品——必须先做**服务端 out 预览 + `/file` entitlement + 清理临时成品**；**不做水印叠加**（省 1 人日，但防绕过更弱）；
- **付费后**：原清晰度、全页、两种出口、30 天内同 Job 重下不重复收费（token 可重复校验该 Job，见 §5）；
- 免费版 3 份/天仍按原规则；结果付费用于**免费额度无法覆盖的场景**：单份 >20 页、OCR >10 页、当天第 4 份及以后（D-R1）；
- 前端导出按钮触发“满意再付”面板；后端强制校验 credits/token，不能只靠前端隐藏。

### 2.3 支付与交付（离线友好）

| 模式 | 流程 | 适用 |
|---|---|---|
| **A 静态码/卡密**（ICP 前） | 弹窗显示价格/二维码 → 手机支付/平台买卡 → 官网兑换得到 **credits license** → 回软件导入 → 导出 | 现在可用；体验一般 |
| **B Native 扫码**（ICP/商户号后） | 软件内建单 → 微信/支付宝 Native → 回调签发 **result token/credits** → 宿主自动导入 → 自动继续导出 | 体验最好 |
| **MCP** | `export_sanitize_job` 仍只认 Pro/Team/Org，无授权返回 `license_required`；MCP 不参与结果付费、不发起支付 | — |

**离线原则**：引擎零外呼；支付在宿主/浏览器侧由用户点击触发；结果以 **Ed25519 签名 credits license / result token** 导入本地，离线验签；不联网校验。

### 2.4 退款、失败与发票

| 场景 | 规则 |
|---|---|
| **未签发/未导入 token** | 7 天内可退（原路）；这是唯一可自助退的状态 |
| **已导入/已签发** | 视为数字化商品交付，**不退**（购买页显著提示；与 payment-invoice §11.1 一致） |
| 导出失败/残留>0 | 不扣 credit；已扣则**客服工单人工核验**，不承诺自动退（零外呼无法回报） |
| 重复支付/支付异常 | 全额退 |
| 发票 | 每笔可开电子普票（含 ¥9.9 首单）；支持按月合并（同一购买方）；专票按资质；**不得以金额小为由拒开/延迟** |

### 2.5 团队/机构

- **不开放**自助结果付费；团队/机构按席位/年合同；
- **P0 不卖团队 credits 包**（与“不按文件计费/对账”冲突）；P2 如需，单独立项（按包开票、不按文件）；
- 机构超量按合同附件，不进入自助结果付费。

### 2.6 与年费的衔接（防蚕食）

- **P0 不做年费抵扣**（需要券/订单关联模型，且文案容易承诺过度）；P1 再议；
- 结果购买页展示“年费 ¥199 不限量；你已买 ¥X 结果，若一年 ≥11 份（或 ≥7 份大文件），年费更划算”；
- 年费用户不消耗 credits；团队/机构不显示结果付费入口；
- 价格设计保证：**≥11 份/年（小文件 ¥19）或 ≥7 份/年（扫描件/大文件 ¥29）→ 年费更划算**。

## 3 市场参照（结果付费/按份价格锚）

> 由两路调研汇总：D 线「按结果/按成功付费案例」、E 线「国内按份/按页价格」。逐条来源见 [raw-D](mcp-pricing/raw-D-outcome-pricing.md)、[raw-E](mcp-pricing/raw-E-per-doc-pricing.md)。

### 3.1 全球「按成功结果」怎么定价

| 产品/服务 | 结构 | 价格 | 结果定义/失败规则 | 对我们的含义 |
|---|---|---|---|---|
| Intercom Fin | 按 outcome | **$0.99/次 ≈¥6.65** | 客户不再求助才算；失败/转人工/技术错误不计费；同会话最多 1 次 | 国际“一次成功结果”的心理价位 |
| Salesforce Agentforce | 按 conversation / credits | **$2/会话 ≈¥13.44**；1 action≈$0.10≈¥0.67 | 按可计量会话/动作 | 结果单价低；B 端靠席位/加购 |
| TextIn | 按页 credit | **$0.01/页 ≈¥0.067** | **仅成功页扣费**；credits 不过期 | 计费口径（失败不计费）值得抄 |
| 阿里云 OCR | 按次阶梯 | **0.009–0.225 元/次** | 按调用计费 | 纯 API 成本地板极低 |
| 微信支付 | 通道费 | **0.6%**（¥19≈¥0.11） | 退款退手续费 | 单份微支付在国内可成立 |
| 律师风险代理 / no-win-no-fee / 猎头 | 按结果分成 | 风险代理 6–18%（分段）；英国成功费上限 25%；猎头 15–20% 首年薪 | 结果可货币化才成立 | 脱敏结果不可货币化 → **只能按件固定价，不抽成** |

**关键结论**：国际市场“一次成功 AI 结果”约 **¥6.7–13.4**；我们计划 **¥19–49/份**是它的 **1.4–7 倍**，必须靠“本地不联网 + 可还原换名 + 出口自检 + 可审计”撑价，不能只讲“一次脱敏”。

### 3.2 国内「按份/按页」价格锚

| 服务/产品 | 计费 | 价格 | 折算/备注 |
|---|---|---|---|
| 法院卷宗数字化 / 病案扫描 | 按页 | **0.07–0.4 元/页** | 30 页 ≈¥2–12；纯“搬纸”，不含判断 |
| 人工录入/排版/改字 | 按页 | **1–10 元/页** | 30–50 页 ≈¥30–500；人工时间价 |
| 电子合同签署（法大大） | 按份套餐 | **3.00–8.75 元/份** | 规模化标准件 |
| 通义法睿·合同审查 | 按页 / 按份 | **4 元/页**；年付折算 **33.3–50 元/份**（raw-E 写 33–59 有误）；增购 **50 元/份** | 30 页≈¥120、50 页≈¥200 |
| AI 合同审查接单（闲鱼/前法务） | 按份 | **50–1,000 元/份**（简单筛查 99–300） | 体验价 **9.9 元** 引流 |
| 律师文书/审查 | 按份 | **600–20,000 元/份** | 人工替代成本锚 |
| 国内 PDF 工具 | 年费/买断 | 年费 **78–602 元**；买断 **98–1,799 元** | 按次不在主流货架 |

**关键结论**：国内按份存在明显空位 **¥19–49/份**——¥19 低于 AI 合同审查按份（33.3–50）的下沿；¥29 落在其下沿附近；**¥49 不再宣称“低于”**，只作天花板档、不主推。整体高于电子合同（3–9）的上沿、远低于人工（50–1,000）。同一个 ¥19：摆进“5 元去水印”货架显贵，摆进“AI 合同审查 33–50 元/份、律师 600 元/份”货架显值。**价格页必须先讲人工替代，再讲工具年费。**

### 3.3 价格校准结论

- **¥19 作首发主力按次价**（≤50 页）：≈30–50 页材料扫描/复印成本（¥2–30）、≈通义法睿 **4.75 页**的钱、≈AI 合同审查的 **1/1.75–1/2.6**；
- **¥29 作扫描件/51–150 页档**：扫描件 OCR 成本与耗时显著更高，仍低于通义法睿基础版折算（33.3–50/份）；
- **¥49 只作天花板档**（>150 页/批量/含审计报告/加急），不首发主推，不宣称“低于 AI 审查”；
- **¥9.9 只作首单体验券**（≤20 页、限一次），不作正式价；
- **年费 ¥199 做锚**：¥19×10.5≈¥199、¥29×6.9≈¥199 → 高频用户自然转年费；
- **P0 不做 10 份包**：包价（无论 129/149）会把交叉点推到 13–15 份，蚕食年费；P1 再评估且必须重算。

## 4 用户分群与价格敏感度

| 分群 | 年处理敏感文件 | 推荐 | 理由 |
|---|---|---|---|
| 偶发/首次 | 1–3 份/年 | **结果付费**（首单 ¥9.9/单份 ¥19） | 年费 199 不划算；先试后买 |
| 低频大文件 | 2–5 份/年，单份 >50 页 | 结果付费 ¥29/份；≥7 份转年费 | 单份价值高 |
| 常规个人 | 4–10 份/年 | **年费 ¥199** | 11 份 ≈ 年费；不限量 |
| 高频/专业 | ≥10 份/年、用 MCP/批量 | **专业版 ¥499/年** | MCP/批量/审计/多设备 |
| 团队/机构 | 多人/多文件 | **团队/机构** | 席位/合同、发票/对账 |

**价格敏感度设计**：
- ¥19 是“不用请示”的价位（≈一份 30 页扫描复印/一次打印费）；
- 首单 ¥9.9 低于“决策成本”，适合拉新；
- 年费 199 对 ≥11 份/年（或 ≥7 份扫描件/大文件）的用户明显划算；
- 价格页需同时展示“单份 ¥19 起”与“年费 ¥199 不限量”，并主动帮用户算“10 份=¥190 vs 年费 ¥199”。

## 5 结果付费 vs 传统付费：系统对比

### 5.1 定性对比

| 维度 | 传统年费/席位 | 结果付费 | 判断 |
|---|---|---|---|
| 收入可预测性 | 高（预收/续费） | 低（按次） | 传统胜 |
| 首单门槛 | 高 | 低 | 结果胜 |
| 价值对齐（满意才付） | 中（先买后用） | **高** | 结果胜 |
| ARPU/LTV | 高 | 低 | 传统胜 |
| 高频用户成本 | 低（不限量） | 高（按次累计） | 传统胜 |
| 低频用户覆盖 | 差（不买） | **好** | 结果胜 |
| 团队/机构 | 适配 | 不适配 | 传统胜 |
| MCP/Agent | 适配 | 不适配（Agent 不能付） | 传统胜 |
| 支付/发票/对账成本 | 低 | 高（逐单） | 传统胜 |
| 客服/退款复杂度 | 低 | 高 | 传统胜 |
| 离线实现 | 成熟（license） | 需 credits/token | 传统胜 |
| 促销/拉新 | 一般 | 强（¥9.9 首单） | 结果胜 |
| 防绕过 | 中（license） | 中（限页/低清/credits；无水印→截图风险更高） | 平 |
| 财务/税务 | 简单 | 微交易、发票多 | 传统胜 |

### 5.2 定量模型（假设情景，非预测）

**口径**：1,000 个“有敏感文件、到达产品”的合格用户，观察首年 + 3 年；年费 ARPU 按个人/专业混合 ¥300；结果单价均值 **¥19**；结果付费者年均 1.8 个结果；续费/复购假设保守。所有假设需 4 周试点校准。

> **关键口径（避免高估）**：免费版已有 3 份/天完整导出，所以结果付费的真实可及人群是“**超出免费额度/单份 >20 页/OCR >10 页**”的用户，不是全部 1,000 人。模型里的 20%/15% 转化率只针对这部分人；若把结果付费当成人人都要买的付费方式，会显著高估收入。

| 情景 | 首年收入 | 3 年收入（同用 ×1.96） | 运营复杂度 | 备注 |
|---|---|---|---|---|
| **传统-only** | 6% 付费 × ¥300 = **¥18,000** | **¥35,280** | 低 | 低频用户 0 收入 |
| **结果-only** | 5% 付费 × 1.8 × ¥19 = **¥1,710** | **¥3,352** | 高 | 免费 3 份/天覆盖了绝大多数低频需求；收入≈0 |
| **混合（推荐但仅获客）** | 传统 6% ≈ ¥18,000 + 结果（非年费用户 5%×1.8×19≈¥1,625）+ 结果用户 5% 升级 ≈¥720 → **≈¥20,345** | **≈¥39,876** | 中高 | 增量约 13%，扣除客服/发票后可能持平；不是第二增长曲线 |

**敏感性**：结果转化率 3%/5%/10%（非年费用户）、单价 ¥19/¥29、结果/人 1.5/2.0；结果-only 首年约 **¥0.8k–¥6.8k/千人**，混合约 **¥18.5k–¥23k/千人**。**结论对排序稳定：传统-only 的首年收入通常高于结果-only；混合只多约 10–15%，且运营成本更高；结果付费单独不足以支撑公司收入。**

> **公平性说明（评审后）**：模型已把“免费 3 份/天”作为抑制项——结果-only 用 5% 而非 20%；混合只对“非年费用户中的 5%”计结果收入。即便如此，混合的增量也只有约 13%，扣除客服/发票/退款成本后可能低于传统-only。所有数字都是假设，不是预测。

### 5.3 单位经济与成本

- 支付通道费 0.6%：**¥19 订单约 ¥0.11**；
- 发票：电子普票按张/按服务商，¥19 订单的发票/开票人工相对收入偏高 → 建议按月合并；
- 客服/退款：结果订单的客服成本显著高于年费（每单可能需要指导导入/重试）；
- 结果付费的净利率低于年费，但**增量用户**（原本不会买年费）的边际收入是纯增量；
- 年费续费收入是长期价值核心，结果付费不应牺牲续费。

## 6 决策建议

### 6.1 推荐方案：三轨并行，结果付费做“第三轨”

```
免费版（3 份/天）── 低频小文件
      │
      ├─ 年费（个人 ¥199 / 专业 ¥499 / 团队 / 机构）── 高频、团队、MCP
      │
      └─ 结果付费（首单 ¥9.9、单份 ¥19/29/49；P0 不做包）── 仅“首单券”获客；完整版需 D-R1
                 └─ 不替代年费、不抵扣（P0）
```

- **主模式不变**：年费/席位仍是收入主体；
- **结果付费的 KPI 不是收入占比**，而是：首单券→年费升级率、退款/客服成本；
- **防蚕食**：年费更划算的交叉点（≥11 份/小文件、≥7 份/大文件）；结果包/抵扣 P0 不做；
- **默认试点**：只上“首单 ¥9.9 获客券”（≤20 页、A 静态码、不改免费额度/导出 gate、不加水印），8–12 人日；**不要**在没有 D-R1 拍板前做完整版。

### 6.2 什么情况下“纯结果付费”才成立

- 目标用户几乎都是一年 1–3 次的偶发用户；
- 没有团队/机构/MCP 需求；
- 支付/发票/客服可以承受逐单成本；
- 能接受收入不可预测、融资/现金流不依赖稳定 ARR。
→ 目前产品同时面向个人/团队/机构/MCP，**不满足**，所以不建议纯结果付费。

### 6.3 试点指标与决策规则

| 指标 | 目标（建议） | 不达标动作 |
|---|---|---|
| 预览→结果付费转化 | ≥10%（首单）/≥8%（复购） | 改限页/改文案/调价，先不扩 |
| 结果→年费升级率（30 天） | ≥15% | 优化抵扣/页面引导 |
| 年费蚕食率 | ≤10%（原本会买年费的人改买结果） | 提高单份价/收紧结果包权益 |
| 退款/拒付率 | ≤5% | 收紧预览/导出失败兜底 |
| 客服成本/结果订单 | ≤¥3 | 优化自动导入/导图 |
| 结果用户 90 天复购率 | ≥20% | 调整包/提醒 |
| 结果付费收入占比 | ≤5%（首年） | 若超过说明年费被蚕食，应立即收紧 |

**决策规则**：4 周后若转化 <5% 或客服成本 >¥8/单 → 停掉或只保留“首单体验”作为获客；若转化 >15% 且升级率 >15% → 扩页档/包/MCP credits。

### 6.4 与既有决策的关系

- 结果付费与 **D-M1（免费只读 MCP）** 独立：MCP 仍走 Pro；结果付费面向 GUI 导出；
- 若采纳结果付费，需要把“免费版 3 份/天”与“结果付费”的边界写入 plans/05 与 free-tier 矩阵（D-R1）；
- 结果付费的 credits/token 与 licensing 共用密钥/公钥；签名字段扩展 `term=credits`，需同步 licensing schema。
