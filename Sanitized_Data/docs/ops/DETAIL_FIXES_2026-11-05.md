# 桌面版细节修复（v1.5.1 · 2026-11-05）

## 1. 授权/试用弹窗按钮错位

**根因**：`style.css` 里的 `.seal` 是“38×38 红色印章图标”样式，但所有红色按钮也使用了 `class="btn seal"`，被强制成 38px 方形，文字只能竖排。

**修复**：

- `.seal` 改为 `.seal:not(.btn)`，不再影响按钮；
- 新增 `.btn.seal` 正常按钮样式（自动宽度、横排、红底、hover）；
- 弹窗按钮组强制 `white-space:nowrap`。

实测授权弹窗按钮：

```text
升级 / 查看价格    w=128px h=32px
开始试用 / 导入授权 w=155px h=32px
知道了             w=73px  h=32px
```

不再竖排，不再压住正文。

## 3. “检测到 1 个无法自动脱敏的隐藏对象”

**含义**：这份 DOCX 里含有解析器无法安全自动修改的对象，例如：

- 图表 chart；
- 文本框 / 旧版 VML 图形（`v:shape` / `w:pict`）；
- OLE / ActiveX 对象；
- 某些无法解码的 EMF/WMF/SVG 图片。

这次的文件实际包含旧版 VML 图形（`v:shape` / `w:pict`），通常在页眉/页脚或文本框里。这些对象里的文字/图片不在普通段落替换范围内；继续导出会**原样保留该对象**，可能带着未替换的敏感信息。

**本次改动**：提示文案改为明确风险：

> 检测到 N 个无法自动脱敏的隐藏对象（图表/文本框/OLE 等）。它们可能包含未替换的敏感信息；继续导出会在成品中原样保留，存在泄露风险。建议先在 Word 中删除或展开处理该对象。仍要继续吗？

建议处理：

1. 点「先不导出」；
2. 在 Word 中打开原文件，检查页眉/页脚/文本框/图表/OLE，把对象里的敏感内容删除或改成普通文字；
3. 另存后再重新投放；
4. 如果确认对象本身不含敏感信息，再点「仍要导出」。

注意：`strict` 模式会尝试剥离文本框/OLE/图表引用，但可能改变排版，不建议在不确认内容的情况下直接使用。

## 4. “给人看”下载按钮没有反应 / 固定默认路径

**根因**：结果卡片里的链接是浏览器 `<a download>`，在 pywebview 桌面窗口里不会可靠触发系统下载；文件实际写到默认导出目录，用户看不到。

**修复**：

- `desktop/main.py` 增加 pywebview JS API：

```text
DesktopApi.save_export(source_path, suggested_name)
  → 系统“另存为”对话框
  → 用户选择目录/文件名
  → 复制成品到该路径
```

- 只允许保存 `OUTPUT_DIR` 下的成品，防止页面写任意路径；
- 结果卡片按钮改为 **「保存到… ↓」**：
  - 桌面窗口：弹系统另存为对话框；
  - 浏览器模式：保留原来的下载兜底；
- 保存成功 toast 显示实际路径；取消/失败有提示。
