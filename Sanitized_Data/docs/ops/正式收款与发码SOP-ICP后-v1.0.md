> 日期：2026-11-02 · 适用：数据隐站 v1.3.4+ 桌面版（已含 licensing 门禁）· 状态：**可执行**
> 前置文档：[客户交付与授权SOP.md](客户交付与授权SOP.md)、[manual-license-issuance.md](manual-license-issuance.md)、
> [order-ledger-template.csv](order-ledger-template.csv)、[payment-invoice.md](../impl/payment-invoice.md)、
> [plans/05 付费与解锁](../plans/05-付费与解锁-软件内购与ICP过渡-规划.md)
>
> **一句话**：ICP 下来只解锁「网站能合法上线 + 能去申请商户号」，不等于今天就能自动收款。
> 今天就能跑的完整闭环是：**客户自助 14 天试用 → 到期回免费版 → 私域/页面引导付款（对公或平台）→
> 你一条命令签发授权 → 客户在「授权」页导入 → 续费/换机/开票走人工台账**。
> 商户号审批通过后，再把「付款」升级成扫码自动到账（L3 自动发码已实现，代码在 `commercial/`；真实支付宝待商户密钥联调）。

## 0. 先把三件事分开（90% 的混乱来自混为一谈）

| 事项 | 是什么 | 现状 | 不做什么 |
|---|---|---|---|
| **ICP 备案** | 网站可合法接入、页脚展示备案号；支付机构审核的**前置材料** | ✅ 已下（2026-11） | 不等于支付资质，不等于能收款 |
| **微信支付/支付宝商户号** | 真正合规收款的通道；钱进对公账户 | ⏳ 需用备案域名去申请（1–3 周） | 不要用个人收款码收经营款 |
| **授权签发（发码）** | 用离线私钥签 `license.json`，绑定机器码解锁 | ✅ 已实现（deploy/issue_order.py） | 不需要等商户号才能开卖 |
| **发票** | 电子普票/专票 | ⏳ 人工开（数电票） | 不要拖延到客户催 |

**授权码是什么（重要）**：本产品的「授权码」= **Ed25519 签名的授权文件**，有两种交付形态，效果完全一样：

1. `license.json` 文件（推荐：微信/邮件发附件，客户拖进授权页）；
2. **一整行文本**（把 `license.json` 压成单行 JSON，客户粘贴到授权页文本框）——用于附件不方便、或客户在手机上收到内容时。

> 这不是 16 位短卡密。短卡密必须联网到服务器兑换成授权文件，与「文件处理引擎零外呼」的卖点冲突，
> 现阶段不做；当前两种形态都已实测可导入（见 §5.6 自检记录与 §5.5 错误对照）。

## 2. 正式收款：三条路线 + 申请 SOP

### 2.1 路线对比（按「今天能不能收钱」排序）

| 路线 | 上线时间 | 开发量 | 费率/成本 | 适用 | 结论 |
|---|---|---|---|---|---|
| **A 对公转账** | ✅ 今天 | 0 | 银行手续费 | 团队/机构/愿意对公的个人；高价单 | **先跑，配合合同/报价单** |
| **B 平台店铺**（微店/有赞/闲鱼） | 1 天 | 0 | 平台抽佣 1–5%（闲鱼靠流量但虚拟商品风控严） | 个人早鸟、私域引流 | **只做过渡/引流，不做主渠道** |
| **C 微信支付 + 支付宝直连** | 资料齐全后审核 1–2 个工作日；整体 1–2 周（含公众号认证/页面整改） | 0（人工发码）～15–20 人日（自动发码） | 约 0.6%，T+1 到对公 | 官网自助购买主通道 | **ICP 下来立刻申请，审核期先跑 A** |
| D 个人收款码/二次清算聚合 | — | — | — | — | **明确不做**（税务与合规风险） |

> 决策：**A 今天开跑；C 立刻申请；B 只用于闲鱼/私域早鸟；等 C 通过后 A 保留给团队/机构。**

### 2.2 路线 A：对公转账（今天可用）

**你侧准备**（一次性）：

```text
户名：四川步络骞科技有限公司
开户行：〔银行名称 + 支行〕
账号：〔对公账号〕
统一社会信用代码：〔税号〕
备注要求：请务必填写订单号（例：ord_20261102_0001）
```

**客户流程**：选版本 → 转账 → 回传付款回单截图 → 你核对到账 → 发码。

**要点**：
- 购买说明页/报价单上写清「付款后把回单 + 机器码 + 开票信息发给客服」；
- 对公转账可与合同/报价单一起发（团队/机构版必备）；
- 发票在收到开票信息后 3 个工作日内开（普票），专票 7 个工作日内；
- 对公到账有延迟（同行实时、跨行可能当天/次日），**以银行流水为准**，不要凭截图就发码（大额单尤其）。

### 2.3 路线 C：微信支付 + 支付宝直连（主通道申请 SOP）

> 费率/材料/时效以官方与签约合同为准（2026-11-02 检索口径见附录 D）。
> 关键：**备案域名的主体必须与商户主体一致**（不一致需 ICP 备案授权函，个体户不接受授权）；
> 网站要有真实经营内容、商品与服务明细、价格、售后/客诉与退款说明，且与营业执照经营范围一致。

#### C-1 微信支付（普通商户，PC 网站 → Native 扫码）

1. 入口：`https://pay.weixin.qq.com` → 「接入微信支付」→ 普通商户申请（申请不收费）；
2. 材料：营业执照、法人身份证、对公账户（三证合一免组织机构代码证）、超级管理员、客服电话、
   **已备案域名**及网站页面截图（首页 + 任一服务页）；
3. 经营场景选「PC 网站」，行业类目选「**软件开发 / 其他互联网服务**」——
   **不要错选「虚拟充值」**（该类目需额外资质）；
4. 审核约 **1–2 个工作日**；通过 → 签约 → 商户平台获取 `mchid`；
5. **绑定 APPID（PC 扫码必须）**：Native 支付准入限「已认证服务号 / 已认证小程序 / 已认证移动应用」；
   没有就注册企业主体公众号并做微信认证（**认证费约 300 元/次，一年一审**，以官方为准）；
6. 安全材料：APIv3 密钥、商户 API 证书（`apiclient_key.pem`）、平台证书（自动更新）；
7. 开发联调：Native 下单 → 生成二维码 → 回调验签（`Wechatpay-Signature`）→ 金额核对（分）→ 幂等 → 发货（签发授权）。

#### C-2 支付宝（企业账号 → 电脑网站支付）

1. 入口：`https://b.alipay.com` 商家中心 → 产品签约「电脑网站支付」（必须企业/个体工商户账户；
   个人账户不能用于公司业务）；
2. 材料：营业执照、法人或经办人证件、对公账户、已备案网站；备案主体与签约主体不一致需 ICP 备案授权函；
3. 审核约 1–2 个工作日（服务商口径，未获取官方原文）；
4. 签约后获取 `APPID`；配置 RSA2 应用私钥/支付宝公钥；
5. 联调：`alipay.trade.page.pay` → 同步跳转 + 异步通知验签 → 金额核对（元字符串转分）→ 幂等 → 发货；
6. 费率常见 0.6%、T+1（**以签约页/合同为准**，未获取官方费率原文）。

#### C-3 网站必须具备的页面（审核会看，也是合规要求）

- [ ] 首页/产品介绍（软件功能、适用人群、不承诺合规的声明）
- [ ] 价格页（含税价、版本权益、早鸟活动规则，不虚构原价）
- [ ] 购买/下单页：明示「**虚拟商品/软件授权、交付方式（邮件/即时发送授权文件）、退款政策**」并勾选确认
- [ ] 客服与联系方式（微信/邮箱/电话，工作日响应时间）
- [ ] 用户协议 / 隐私政策 / 退款政策 / EULA（可访问链接，购买前勾选）
- [ ] 页脚：**ICP 备案号（链接 beian.miit.gov.cn）+ 公安备案号 + 营业执照信息**

#### C-4 审核被拒的常见原因（提前规避）

| 原因 | 处理 |
|---|---|
| 域名未备案 / 备案主体与商户主体不一致 | 用同一主体的备案域名；或向支付机构提交 ICP 备案授权函（个体户通常不接受） |
| 网站打不开 / HTTPS 证书无效 / 只有下载没有购买说明 | 上线可访问的购买说明页 + 有效证书 |
| 商品/服务描述不清、无价格、无客服、与营业执照范围不一致 | 补齐价格、权益、交付方式、客服入口；调整经营范围或商品描述 |
| 经营类目与业务不符（如错选「虚拟充值」） | 选「软件开发/其他互联网服务」；如实描述虚拟商品 |
| 个人收款/代收代付嫌疑 | 只用商户号收自有业务款；不做二次清算 |
| 无交付记录/退款争议举证不足 | 下单页留证（页面快照）+ 交付记录（授权文件、聊天/邮件）+ 台账 |

#### C-5 微信支付对虚拟商品的争议规则（要写进页面）

- 微信不禁售软件授权，但投诉处理要求：**1 天内首次回复、3 天内办结**；
- 虚拟类退款专项：充值后服务无法使用 → 全额退款；用户不再需要 → 按实际使用情况退款；
- 未达标可能被延长结算、扣待结算资金退款、关闭支付权限；
- 因此下单页必须显著写明「虚拟商品、交付即不可退」的边界，**并保留交付凭证**（授权的 license_id/导入记录）。

### 2.4 ICP 下证后 30 天内必须补的合规动作（官方口径）

1. **公安联网备案**：网站开通（联网）之日起 **30 日内**，登录 `https://beian.mps.gov.cn` 提交；
   材料：主体证件、网站负责人身份证、域名、ICP 备案号；通过后 **30 日内**把公安备案号+图标放页脚；
2. **页脚 ICP 备案号**：必须展示并链接 `https://beian.miit.gov.cn/`（信息产业部令第 33 号）；
   部分省份另要求版权信息与备案主体一致；
3. **是否需要 ICP 许可证**：四川省通管局官方问答明确——**以自营方式直接销售自身商品/服务、无第三方入驻的，
   不属于增值电信业务，无需《增值电信业务经营许可证》**；若后续加会员体系/引入第三方入驻，再咨询属地通管局；
4. **协议三件套**：用户协议 / 隐私政策 / 退款政策（+ EULA）上线并在购买前勾选；建议法务过一遍；
5. **软件著作权登记**：建议做（1–3 个月，不阻塞销售），对维权/上架/信任背书有用；
6. **隐私最小化**：只收交付/开票必需信息；不收集客户文件；隐私政策写明数据范围与保存期限。

### 2.5 收款合规红线（写进团队守则）

1. **不用个人微信/支付宝收款码收经营性款项**（税务风险 + 平台规则风险）；
2. **不做二次清算/代收代付/租借商户号**；
3. 收款主体、开票主体、合同主体统一为「四川步络骞科技有限公司」；
4. 价格页展示含税价；不虚构原价、不搞虚假倒计时；
5. 客户文件一律不收集、不上传（只收交付/开票必需信息：机器码、联系方式、发票信息）。

## 4. 完整流程：试用 → 到期 → 付费 → 发码 → 续费

### 4.1 客户旅程与你的动作（一张表跑完）

| 阶段 | 时间点 | 客户看到/做什么 | 系统行为 | 你做什么 |
|---|---|---|---|---|
| ① 交付安装 | D0 | 收到安装包/绿色版 + 说明 | 免费版可用（3 份/天） | 发安装包 + 交付说明 + SHA256 + 客服微信 |
| ② 开试用 | D0–D3 | 「授权」页点「开始 14 天全功能试用」 | `state=trial`，14 天全功能，顶栏显示「试用 · 剩 N 天」 | 在私域记一笔「试用开始日」；**试用不需要机器码** |
| ③ 试用期中 | D7 / D11 / D13 | 继续用全功能；额度不限制 | 到期自动回 free（3 份/天），数据不删 | 私域提醒（话术 T2）；匿名用户靠产品内提示 |
| ④ 决定购买 | 试用期内或到期后 | 点「购买/升级」→ 价格页 → 联系客服（当前） | 到期后额度用完会弹升级提示，按钮指向 `/pricing` | 发购买说明（话术 T3）：版本、价格、付款方式、需要提供的信息 |
| ⑤ 付款 | 当天 | 对公转账/平台下单/（商户号后）扫码 | — | 核对到账 → 台账登记 `order_id` → 回复「已确认收款」 |
| ⑥ 发码 | 到账后 ≤1 个工作日 | 收到 `license.json` + 导入说明 | — | **一条命令**签发（§5.2）→ 发文件 + delivery 话术 |
| ⑦ 导入 | 收到当天 | 授权页拖入/粘贴 → 「已授权」→ 点「备份当前授权」 | `state=paid`，功能位生效；旧 license 自动备份 `.json.bak` | 让客户回一张「已授权」截图；台账补 `license_id` |
| ⑧ 开票 | 付款后 3 个工作日 | 收到电子发票（邮箱） | — | 收开票信息 → 数电票 → 发邮箱 → 台账 `invoice_status` |
| ⑨ 续费 | 到期前 30/14/7/1 天 | 收到提醒 | 到期后进入 14 天宽限期（仍可用），之后回 free | 台账筛到期日 → 发续费提醒（话术 T5）→ 新订单 → 重签 |
| ⑩ 售后 | 随时 | 换机/重装/退款/补发 | 离线授权无法远程吊销 | 按 §7 场景处理并留痕 |

### 4.2 必须守住的关键规则

1. **先收款、后发码**；没有到账凭证不发（大额单以银行流水为准）。
2. **一单一 `license_id`**；`order_id` 唯一；发码脚本默认拒绝重复订单（防重复签发，见 §5.2）。
3. **机器码必须让客户从「授权」页复制**（形如 `ZH39-7N5C-98CD-A8GB`，Crockford Base32，无 I/L/O/U）；
   手抄容易错，错了客户导入会报「不适用于本机」。
4. **试用 ≠ 授权**：试用是本地状态，不能转付费；付费授权必须绑定机器码。
5. **年费到期后有 14 天宽限期**，之后回免费版；**买断授权无到期日**（更新服务按约定）。
6. **试用只有一次**：到期后不能重新试用（删除单个状态文件也会被历史事件拦住；整目录清空的极端情况接受风险）。
7. **不承诺「永久免费升级」**：买断 = 永久使用 + 约定更新期；大版本升级另议。
8. **退款口径**：未签发 7 天内可退；已签发/已激活不退（数字化商品；购买前用免费版/试用验证）。

### 4.3 到期提醒从哪来（要诚实）

产品**没有**遥测/账号体系，所以你**收不到**匿名试用用户的到期通知。
能做的只有：
- 产品内：顶栏「试用 · 剩 N 天」+ 免费额度用完时的升级弹窗（已实现）；
- 私域：加过微信/留过邮箱的客户，按台账手动提醒（话术 T2/T5）；
- 内容侧：价格页/公众号持续承接。

> 因此私域承接不是"可选项"，是这套离线产品的转化命脉。

## 5. 发码操作手册（一条命令）

### 5.1 前置检查（第一单前做一次）

- [ ] 私钥存在：`%USERPROFILE%\.sanitized-data-license-keys\license_signing_ed25519.pem`；

### 5.2 一条命令：签发 + 授权码 + 交付话术 + 台账

```powershell
cd D:\DSH_DESKTOP_WORKSPACE\Sanitized_Data

python -X utf8 deploy\issue_order.py `
  --private-key "$env:USERPROFILE\.sanitized-data-license-keys\license_signing_ed25519.pem" `
  --key-id prod-2026b `
  --sku pro `
  --machine-code "ZH39-7N5C-98CD-A8GB" `
  --order-id ord_20261102_0001 `
  --customer-name "张三" `
  --contact "微信 zhangsan" `
  --amount 299 `
  --payment-method "微信支付" `
  --paid-at 2026-11-02
```

运行后提示输入私钥口令（不回显）。产物：

| 文件 | 用途 |
|---|---|
| `out/licenses/ord_20261102_0001.json` | **发客户**（附件 / 拖入授权页） |
| `out/licenses/ord_20261102_0001.code.txt` | 备用：一整行纯文本授权码（粘到授权页文本框） |
| `out/licenses/ord_20261102_0001.delivery.txt` | 交付话术（整段复制进微信；含备用授权码） |
| `out/licenses/orders.csv` | 台账自动追加一行（订单/客户/金额/机器码/license_id/到期） |

常用变体：

```powershell
# 个人版（1 台）
... --sku personal --machine-code "..." --order-id ord_... 
# 专业版 2 台（重复 --machine-code）
... --sku pro --machine-code "A..." --machine-code "B..." --order-id ord_...
# 团队版（5 席，需 team-id）
... --sku team --seats 5 --team-id team_acme_001 --machine-code "..." ... 
# 买断
... --sku pro --term perpetual --order-id ord_...
# 自定义到期日 / 试用延期（14 天）
... --expires-at 2027-12-31T23:59:59+08:00 ...
... --sku pro --days 14 --notes "试用延期" ...
# 重复签发保护：默认拒绝已存在的 order_id/文件；确需重签加 --force
```

> 说明：同一年费授权重签（续费/换机）请用**新订单号**；`--force` 只用于"同一订单发错文件需要重发"。
> 旧授权在客户机导入时自动备份为 `.json.bak`，不会丢。
> **关于 `--days 14` 试用延期**：年费授权固定带 14 天宽限期，所以 14 天授权实际可用约 28 天；
> 要严格 14 天需要改代码或接受宽限（内部延期一般可接受，不要对外承诺"精确 14 天"）。
> 上面的变体是"参数差异示意"，实际执行时复制 §5.2 首条完整命令再替换参数。

### 5.5 常见错误对照表

| 报错/现象 | 原因 | 处理 |

## 6. 台账、发票、对账

### 6.1 台账字段（`orders.csv` 由脚本自动写）

`order_id, customer_name, customer_org, contact, sku, amount_cny, paid_at, payment_method, machine_codes, license_id, issued_at, expires_at, invoice_status, notes`

台账是唯一事实来源：**收款、发码、开票、续费、退款都以台账为准**。每周备份一次（加密盘/网盘私有目录）。

### 6.2 发票（数电票，人工开）

- **票种**：电子发票（普通发票）；电子发票（专用发票，购买方具备一般纳税人资质/按票种核定即可，**不按 SKU 限制**）；
- **怎么开**：2024-12-01 起数电票全国推广，**电子发票服务平台免费**，去介质、无需税控盘/UKey，
  实人认证后在电子税务局手工开票即可；几十张/月不需要买第三方开票系统；
- 信息：抬头、税号、邮箱；专票另需地址电话、开户行及账号；
- 时效：普票 3 个工作日、专票 7 个工作日内；
- **红冲**：数电票**不能作废，只能红冲**；受票方未做用途/入账确认 → 开票方直接红冲；
  已确认 → 一方发起、对方确认（确认单 72 小时未确认自动作废）；
- 开票内容建议「信息技术服务*软件服务费」（以财务/税务核定为准）；
- 每月固定一天集中开票，避免遗漏；台账 `invoice_status` 更新为「已开/待开/红冲」。

### 6.3 对账节奏

| 频率 | 动作 |
|---|---|
| 每日 | 微信/支付宝/银行流水 vs 台账；差异当天查（重复支付、未发码、未开票） |
| 每周 | 到期续费清单（未来 30 天）；退款/补发/换机工单清空；备份台账 |
| 每月 | 收入/退款/发票汇总；渠道费率核对；私钥备份介质抽检 |

### 6.4 客户信息最小化

只收集：机器码、联系方式（微信/邮箱/手机）、开票信息、付款凭证。
**不收集**：客户文件、文件内容、身份证、银行卡、密码。隐私政策里写清楚。
